# SaaS & AI 模板（工作名）

本文件是项目当前唯一的方向文档。下面的决定是 2026-10-17 和项目负责人讨论后定下的；以后变化以讨论结论为准，并同步更新这里。

## 目标

做一个**能卖的 SaaS & AI 工程产品**：以成熟商业化软件为目标，自己长期开发复用作为收益兜底。

- **卖给谁**：独立开发者、小团队、想给现有系统加 AI 的团队、用 Coding Agent 开发的人。
- **卖什么**：四类模板/积木：SaaS 通用模块、业务模板、AI 原生模板、给现有 SaaS 加 AI 的模块。
- **怎么算成功（North Star）**：从选模板到交付一个可运行的新产品，净省了多少时间（第二个同类项目接入时间至少减半），并且测试、安全、合规不打折。

## 关键判断

- **样板代码已经不值钱，认知才值钱。** coding agent 很快就能写出网页和 demo，但做不出成熟的 SaaS：它不知道这类产品有哪些现成的东西可用，也不知道一个"完整成熟"的产品到底包含什么。
- 所以**模板 = 交给 coding agent、让它把产品做到成熟的"说明书 + 契约 + 可执行验收"**。使用者不需要自己具备这些认知：把模板交给 agent，让 agent 按阶段开发即可。难点部分（租户隔离、计费账本、作业重试/取消、成本上限、权限）附验证过的参考代码。
- **工厂是手段，不是目的。** 认知类产出（调研、功能清单、验收标准）可以批量生产；底座和契约手工打磨；独立验证是核心资产。不再追求"批量把开源仓库加工成模板"。
- **硬规矩：一个模板只有在 agent 真的照它做出产品、并通过它自带的验收之后，才算合格。**

## 现阶段的约定

- **优先级**：AI 相关优先，先做 AI 原生模板和 SaaS+AI 模块；其他类型需要时按需生成。
- **只给自己用**：商业化才需要的东西（销售用的许可证审查、发布流程等）推到商业化前再做。但每段复用代码的来源、许可证和 commit 现在就要记下来。
- **一人 + AI agent**：负责构建和负责验证的 agent 相互独立，人只在关键节点批准。
- **批量执行**：本地 opencode CLI，模型 `open-design/deepseek-v4.1-flash`。
- **预算**：第一版暂不设上限。

## 模板格式 v0

```
blueprints/<模板名>/
  TEMPLATE.md        # 给 agent 的入口：怎么分阶段推进、什么时候停下来问人
  template.json      # 机器可读：阶段、决策点、默认技术栈、启动约定
  spec/
    landscape.md     # 品类认知：现成产品、开源项目、哪些复用、哪些自建（附许可证）
    product.md       # 成熟产品定义：角色、流程、功能清单（MVP → 成熟）、边界情况
    architecture.md  # 默认技术栈、数据模型
    api.yaml         # API 契约
    decisions.md     # 人工决策点及默认值
  stages/            # 每个阶段的目标说明
  acceptance/        # 每个阶段一组可执行验收测试（含难点负向用例）
  reference/         # 难点的参考实现（可选）
```

验收的独立性靠三点保证：
- **黑盒**：只通过 API 契约和少量浏览器流程测试运行中的应用；
- **每次从模板重新拷贝测试**：构建 agent 改测试没有作用；
- **测试先验**：对一个空应用跑必须全部失败。

## 第一版：把一条链完整走通

**第一个模板**：AI 研究/文档助手。默认技术栈固定为 TypeScript/Next.js + Postgres。验收时用"假模型"模式，不调用真实模型。

| 阶段 | 内容 | 关键验收（含负向） |
|---|---|---|
| S1 骨架 | 注册登录、组织/租户、权限 | 跨租户访问被拒 |
| S2 AI 作业 | 提交任务 → 后台多步执行，有进度、可取消、可重试 | 取消后不再继续执行；重试不重复执行 |
| S3 成本与产物 | 模型调用记账、用户额度、报告存储 | 超预算被拒；他人拿不到我的报告 |
| S4 成熟化 | 针对报告追问、运营后台、审计日志、数据导出 | 每个操作可追溯 |

**harness v0**：每个阶段先构建（opencode，在独立工作区里），再提交 git 快照，然后跑验收。不通过就把失败报告交回构建 agent 重做；通过后停下来等人批准，再进入下一阶段。全程记录用时、token、尝试次数、人工介入次数。

**对比实验**：A 组是 agent 拿着模板按阶段开发；B 组是同一个 agent 只拿到一句话需求，从空的 Next.js 项目开始。最后两组跑同一套验收，比较用时、花费、介入次数和通过率。

**顺序和人工节点**：
1. 写模板的 spec 和验收（并用空应用确认测试会失败）；
2. **人工审批 spec 和验收**（最重要的节点，它定义了什么叫"成熟"）；
3. 写 harness；
4. 跑 A 组，每个阶段人工看一眼；
5. 跑 B 组；
6. 复盘并修订格式；
7. 之后再考虑第二个模板和批量生产。
