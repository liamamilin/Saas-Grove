# 01 — 产品边界、权限与治理

## 目标与非目标

工厂目标：接受声明式资源需求，在合规授权和隔离环境下批量发现来源、筛选、加工、验证、分级、存档、发布与维护；让新增资源的成本和结果可度量、可复现、可审计。

非目标：自动保证任意仓库可转化为商业级模板；自动判定法律争议；无人审批地写入生产系统；承诺一键转换所有语言/架构；以资源数量代替可用质量。

## 六类角色及批准权

| 角色 | 主要权利 | 不可自行越权 |
|---|---|---|
| Product Owner | 决定需求、优先级、目标等级、停止/继续 | 不得覆盖安全/许可阻断 |
| Discovery Agent | 搜索、证据采集、只读分析 | 禁止对候选源码执行不可信脚本 |
| Builder Agent | 在授权隔离区提交 patch、测试 | 不得改上游仓库、真实生产或已发布制品 |
| Validator | 运行独立检查，签发可核查的结果记录 | 不得凭 Builder 自述签发 PASS |
| Security/License Reviewer | 审查高风险依赖、合规与发布限制 | UNKNOWN 不得推断为 APPROVED |
| Release Approver | 综合证据、签发版本并批准仓储发布 | 不得把缺证据改成 PASS |

同一 Agent 可以在不同阶段调用工具，但**不能让 Builder 的自评直接变成最终发布审批**。重大许可、上线、资金与密钥问题保留人工负责人。

## 约束优先级

1. 不损坏目标项目、真实生产及用户数据，任何写操作先授权、隔离、Checkpoint。
2. 合规、安全、数据一致性是硬门，不能用高分或低等级抵销。
3. 证据可复现；`UNKNOWN` / `NOT_RUN` 与 `PASS` 严格区分。
4. 允许有限范围交付和不同质量等级，不要求所有条目必须 L3。
5. 多来源并不等于随意拼合代码：逐个文件、模块、资产审查许可证、兼容与 provenance。
6. 建设可维护的商业产品；自用是收益下限，而非降低质量标准的理由。

## 决策点

- 选择 Candidate：人类批准或根据事先批准的规则作出有限自动选择，包含选型证据。
- 启动改造：必须指定可写路径、隔离模式、风险边界和预算。
- 释放正式制品：Release Approver 显式批准；没有审批禁止自动发布。
- 风险升高或证据过期：停止或隔离；禁止偷偷降级/绕过检查。

## 核心追踪对象

`CatalogTarget`（需求）→ `DiscoveryRun`（候选搜索）→ `Candidate`（来源）→ `SelectionDecision`（方案）→ `ProductionJob`（加工）→ `Artifact`（制品）→ `EvidenceBundle`（证据）→ `ScopedAttestation`（按范围认证）→ `RegistryRelease`（入库发行）。

一个目标可有多个候选和多个生产 Job；一个 Job 可产出多个制品，但**每个发行制品只对应一个明确的来源集合、内容 hash 与验收证据集合**。
