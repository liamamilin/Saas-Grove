# 10 — 商业交付与发行方案

## 1. 产品销售对象

首要对象：需要反复开发 SaaS/AI 应用的独立开发者、小型团队和 Agent-first 开发团队。早期真正优势必须通过跨项目可用性、许可透明度、安装可靠性来证明。

## 2. 交付结构（首版建议）

- **Core Source Distribution**：经过筛选和改造的 SaaS Core 源码、模块 manifest、参考项目。
- **AI Template Packs**：每类具备完整 UI、API、后台作业、用量计费和测试的模板包；可包含一个或多个适配的原型资源。
- **Business Template & Prototype Packs**：业务代码与能力契约是应用模板主体；可选原型按独立版本、实现层级及绑定清单交付，不把设计稿当作完整运行产品。
- **SaaS + AI Integration Packs**：通用 AI 核心、adapter contract、示例集成、权限/审计用例。
- **Docs + Changelog + Migration Guides**：完整技术与运营文档。
- **License & Notices**：本产品商业许可文件及第三方开源许可清单，额外列出设计稿、字体、图标、UI 套件等原型资产的使用和再分发授权，不混淆多种授权。

实际经营可采用一次性源代码授权、订阅更新/支持或托管服务；正式价格与授权模型要经外部验证再决定。

## 3. 发布渠道/维护策略

- 网站：产品介绍、文档、Demo、购买/授权方式、更新日志。
- 分发：打版本 tag、打包源代码、生成 checksum/SBOM、版本发布说明。
- 支持：最小重现模板、明确支持窗口、兼容矩阵、FAQ、公开已知限制。
- 安全：漏洞修复流程、受影响版本、私密报告渠道、密钥泄露处置。
- 版本：遵循 semver，不保证所有旧版永久兼容，但必须提供公告与迁移说明。

## 4. 包装与产品主张

不要用「全 SaaS 覆盖」「无需开发」「100% 自动 Agent 适配」等尚未证明的营销表述。建议描述为：

> 商业级 SaaS 与 AI 工程模板体系，提供经过验证的模块、业务模板和 AI 集成套件，面向人类开发者与 Coding Agent，可在明确许可与验收标准下组合构建产品。

## 5. GA 发布检查表

- [ ] 独立品牌及商标风险初查。
- [ ] 许可审核、第三方 NOTICE、完整 SBOM。
- [ ] 价格、退款、授权内容与更新/支持范围清晰。
- [ ] 官网、安装文档、用户手册和故障处理齐全。
- [ ] 全新环境独立安装测试 PASS。
- [ ] 发行目录明确每个原型是设计稿、交互模拟还是已集成可运行 UI；已集成原型附能力绑定与 E2E 证明。
- [ ] 首个业务模板的两种可运行原型通过切换兼容回归；设计资产的再分发许可已审核。
- [ ] 发布构建锁依赖且签发版本号。
- [ ] 关键安全/数据一致性门禁 PASS。
- [ ] 至少两个真实项目验证通用模块跨项目复用。
- [ ] 未完成特性明确列出，不计入宣传。
- [ ] 商业负责人批准发布。

## 6. 自用收益兜底

独立记录：每个实际项目的复用模块、节省的人天、解决的缺陷、重复出现的适配成本、后续维护成本。即使没有商业销售，也需证明系统本身的净收益为正。
