# 07 — 商业级质量与验收门禁

## 1. 原则

**实现了 ≠ 可用；可用 ≠ 可发布。** 质量门禁对商业版和自用版同样适用；自用环境可以降低对 SLA 的营销承诺，但不能降低核心安全与数据完整性要求。

## 2. 单模块 Definition of Done

- 功能：需求/非目标/输入输出/失败分支明确，示例可运行。
- 接口：公开 contract 和兼容范围确定。
- 测试：单元、契约、集成、必要 E2E、负向与权限测试可重复执行。
- 文档：安装、配置、示例、FAQ、排错、升级、回滚。
- 安全：鉴权、输入校验、密钥隔离、限流与审计。
- 合规：上游 SHA、许可与通知、第三方服务政策。
- 运维：日志/metrics/trace、故障排查、错误预算或 SLO 说明。
- 可维护：锁版本、迁移说明、维护负责人、变更记录。
- 原型（如有）：覆盖范围、实现层级、所需业务能力、bindings、资源许可、mock/真实行为界限清楚。

## 3. 发布硬门槛

| 类别 | 阻断条件 | 验收证据 |
|---|---|---|
| 数据与支付 | 丢单、重复发权益、未验签、错租户访问 | 幂等/对账/权限自动测试 |
| 安全 | 高危漏洞未解决、密钥泄漏、越权写操作 | 漏扫、负向测试、审查记录 |
| 合规 | 许可证 UNKNOWN/RESTRICTED 且没有批准方案 | OSS_AUDIT、NOTICE、SBOM |
| 可用性 | 新用户按文档无法独立启动核心示例 | 干净环境安装录屏/日志 |
| 升级 | 无数据库迁移及恢复策略 | 迁移排练及恢复报告 |
| 可观测 | 核心失败没有 requestId / jobId / orderId | 故障注入和链路追踪 |
| AI | 无租户权限、安全审批、成本边界 | tool-call 负向测试、配额测试 |
| 来源可靠 | 用 mock 假冒 live，声明未测功能为已通过 | 测试证据与环境标识 |
| 原型真实性 | 将静态设计/Mock 交互宣传成完成真实业务的 SaaS 应用 | 原型实现层级及绑定验证报告 |
| 原型兼容 | 更换原型意外改动领域模型、越权访问或页面动作失效 | 能力契约检查、两变体切换回归与变更 diff |

## 4. Agent 改代码的隔离门禁

- 默认只读；明确仓库及目标 branch、文件范围后才能写。
- 先建立 checkpoint，记录未提交修改，不覆盖用户工作。
- 测试须使用临时 DB、模拟支付、隔离工作目录和受限密钥；**不能访问或修改真实用户数据、支付回调配置、生产计划任务、launchd/cron**。
- 验证四层：结构路径隔离、运行时行为、故意打破隔离时触发失败、正常测试路径通过。
- 代码变更必须报告 diff、通过的测试、未通过的测试、风险与回滚点。
- 涉及生产部署、真实支付或删除需额外明确批准。

## 5. 典型验收场景

**SaaS Core / Billing**：重复事件、付款乱序、退款失败、冲突查单、租户串单、数据恢复。

**AI Native**：模型超时、重试、重复回调、预算耗尽、取消、失败恢复、作业产物、持久化执行状态。

**SaaS + AI**：被拒绝的业务动作不得执行；检索文档中的恶意指令不能改变授权；跨租户数据不可见；审批 token 过期不得重用。

**Template Installation**：干净环境成功；缺少必要配置给出精确错误；失败安装可恢复；重复运行安装不会破坏已有工作。

**Prototype Resources**：同一业务模板至少两个已集成原型在共同覆盖范围内完成真实能力绑定、页面动作 E2E、不同角色授权、切换兼容性及数据不变性测试；Design-only/Interactive-mock 只能宣称其实际验证过的层级。AI Native 可先以一个原型发布，但必须支持多个原型的契约；跨原型能力在具备第二个真实样例后才可宣称完成。

## 6. 非功能目标

- **安全和数据一致性**：硬要求，不能用“以后优化”推迟。
- **性能**：每个模板设基于真实负载的目标，不提前承诺统一 QPS、延迟和 uptime。
- **可靠性**：后台任务需有明确重试/幂等/恢复定义。
- **成本**：AI 调用、存储、队列和第三方收费均可追踪至租户/应用。
- **文档**：从空环境复现实例是 GA 发布前的正式验收环节。

## 7. 证据类型

`SPEC / CODE / UNIT / INTEGRATION / E2E / BLIND / LIVE / LICENSE / SECURITY / RELEASE`。

验收报告必须区分 `PASS / FAIL / BLOCKED / NOT_RUN`，不能因为某一层 PASS 推断整体 PASS。每项证据附命令、代码版本、环境与产物路径。
