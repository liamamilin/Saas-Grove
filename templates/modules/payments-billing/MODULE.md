# payments-billing（支付与计费）认知模板

## 必读（先看这一页）

- **职责**：把"客户付了多少"和"客户能不能用某功能"变成两个可验证的状态机。对象只有六类：`plan`、`checkout session`、`subscription`、`invoice`、`entitlement`、催收工单。
- **边界**：登录归 `auth`；工作区与角色归 `workspaces-and-permissions`；用量归 `usage-metering-and-budgets`；邮件归 `email-transactional`；限流归 `rate-limiting`；审计归 `audit-and-data-export`。本模块只负责**收钱、记账、判能不能用**。
- **订阅状态机**：`pending → trialing → active → (past_due → unpaid) → canceled`。恢复靠一次成功扣款；续期靠新的支付方事件；**迟到事件不得让状态回退**。
- **钱的三条铁律**：① 金额是整数（最小货币单位）配三位大写币种，无浮点；② 价格只来自服务端计划目录，客户端报的一律不信；③ 钱的状态变化只能由支付方事件或支付方调用驱动，本地定时器不得臆造"已支付"。
- **最容易出事故的五处**：webhook 不验签（谁都能给自己发会员）、缺幂等（同事件重复扣款）、乱序回退（已付款被判欠费）、令牌明文入库或进 URL（泄露即白嫖）、试用与宽限边界写死（权益忽然消失）。
- **验收怎么跑**：见 `HOST.md`。本模块另需两个测试钩子（铸造签名事件、轮换验签密钥），见 `contract.md`。

## 1. 这个模块是什么

收费系统有三层，缺一层都会在生产上出事：

1. **商品层**：`plan` 定义卖什么、多少钱、什么周期、附赠哪些权益（feature key）。
2. **交易层**：`checkout session` 收集付款，`subscription` 表示"这个工作区拥有什么"，`invoice` 是收款凭证。
3. **裁决层**：`entitlement` 是功能调用前的闸门，回答"这个工作区能不能用 feature X"。

支付方（provider）通过 **webhook 事件** 告诉本模块真相，本模块是这些事件的**唯一裁决者**：验签、去重、识别乱序、忽略未知事件，并映射成"订阅状态 + 发票状态 + 权益"一致的结果。成熟与否不看功能多寡，而看**在乱序、重放、并发、超时、攻击下是否仍收敛到唯一正确的账**。

## 2. 成熟版应该有什么（MVP → 可用 → 成熟）

层级标记：`[MVP]` 不做不能收钱；`[可用]` 不做会在真实运营中挨打；`[成熟]` 规模化后才需要。

### 2.1 MVP

- P01 `[MVP]` **计划目录（只读）**：`key`、整数 `amount_minor`、三位币种、`interval`（month/year）、`trial_days`、`features`（权益 key 数组）。下架计划不进目录。
- P02 `[MVP]` **结账会话**：创建/查询、TTL、一次性完成、价格取自目录、成功/取消落地页 URL。
- P03 `[MVP]` **支付方 webhook**：验签（签名 + 时间戳容差）、按事件 id 去重、乱序不回退、未知事件忽略、体积上限。
- P04 `[MVP]` **订阅**：状态机、周期起止、取消（周期末生效）、恢复、套餐变更。
- P05 `[MVP]` **发票**：状态（draft/open/paid/void）、金额守恒、编号不复用、已付不可变。
- P06 `[MVP]` **权益判定**：`feature → entitled`，覆盖试用中、宽限期内、取消后周期内、已到期四种边界。
- P07 `[MVP]` **认证与租户隔离**：401 未认证 / 403 成员非计费管理员 / 404 非本租户资源。
- P08 `[MVP]` **幂等键**：同键同载荷同结果且不新建对象；同键异载荷 409。
- P09 `[MVP]` **邮件模板**（由 `email-transactional` 发送，链接放 `data.link`、令牌放 `token`）：`payments-billing.invoice_paid`、`payments-billing.payment_failed`、`payments-billing.subscription_canceled`。
- P10 `[MVP]` **假支付方接口**：建结账会话、发起扣款、更新支付方式、按规范信封回调。

### 2.2 可用

- P11 `[可用]` **催收流程**：付款失败 → `past_due` → 按计划重试（有上限）→ 宽限期 → `unpaid` → 取消与取消邮件。
- P12 `[可用]` **支付方式更新令牌**：单次使用、有 TTL、绑定租户、失败尝试有上限、成功才消耗。
- P13 `[可用]` **验签密钥轮换窗口**：新旧密钥并存一段时间，旧报文不失效。
- P14 `[可用]` **套餐变更延迟到周期末**（不做按比例折算，先把语义定死）。
- P15 `[可用]` **试用到期处理**：到期未付款 → `unpaid`、权益撤销、后续付款可恢复。
- P16 `[可用]` **定时任务接入 `async-jobs`**：催收重试、试用到期、周期结束、开票。
- P17 `[可用]` **数据安全**：令牌/幂等键只存摘要；明文只在发信内容与 outbox；日志不落令牌。
- P18 `[可用]` **可观测性**：结构化日志、指标、审计事件（交给 `audit-and-data-export`）。
- P19 `[可用]` **支付方适配层**：把各家报文与签名翻译成规范信封，业务只认规范信封。
- P20 `[可用]` **收据与发票下载**：`file-storage` 短期签名 URL，链接 host 须为本应用。

### 2.3 成熟

- P21 `[成熟]` **按比例折算**：升级立即生效并出抵扣、降级周期末生效。
- P22 `[成熟]` **多币种与汇率**：结算币种、汇率快照、舍入规则、退款按原币种。
- P23 `[成熟]` **退款与贷记单**：部分退款、退款状态机、账务对账。
- P24 `[成熟]` **用量计费桥**：把 `usage-metering-and-budgets` 的用量汇总成行项周期结算。
- P25 `[成熟]` **席位/数量计费**：数量可变、价格档位。
- P26 `[成熟]` **税务与合规发票**：税率、税区、法定编号、凭证。
- P27 `[成熟]` **对账与异常处理**：每日对账、差异告警、拒付处理。
- P28 `[成熟]` **计费门户**：自助改卡、下载发票、查看用量与账单。
- P29 `[成熟]` **套餐运营后台**：灰度、限额、A/B 分组（与 `feature-flags`）。
- P30 `[成熟]` **收入分析与报表**：接 `analytics`，多实体/多币种报表。

## 3. 每项的正确行为

- **定价**：价格只有一份事实来源（服务端 `plan` 目录），请求体里的 `amount_minor` 必须忽略。错：以前端价格为准，改一行即白嫖。
- **结账**：会话一次性、有 TTL、过期不可完成。错：永久有效、同一会话可被完成两次。
- **Webhook 顺序**：先验签（签名 + 时间戳容差）→ 按事件 id 去重 → 判断乱序 → 才改状态。错：先改状态再验签（留后门），或按业务单号去重。
- **未知事件**：类型或对象 id 未知 → 200 且不创建东西。错：404/500 让支付方无限重试打爆流量。
- **乱序**：迟到的旧版本事件忽略（`applied:false`），状态不回退。错：`invoice.paid` 后一条更早的 `payment_failed` 让已付款客户被判欠费。
- **取消**：是"不再续费"不是"立刻断服"，权益保留到周期末。错：取消即扣权益，周期内被卡。
- **试用**：结束且未扣款成功 → 权益撤销。错：试用结束仍给权益，试用变永久免费。
- **权益**：只看（工作区、订阅、feature）。错：掺入请求者角色，同工作区答案不同。
- **发票**：`total_minor == Σ line_items.amount_minor`，已付不可变，编号唯一不复用。错：可改行项则与支付方对不上；复用旧号则审计断链。
- **催收**：重试有次数上限，宽限期结束才撤销权益。错：无上限重试把邮件服务商打到封号。
- **令牌**：单次、有 TTL、成功才消耗、失败尝试有上限。错：可重放（白嫖）或失败即作废（客户改不了卡）。
- **错误与隔离**：跨租户一律 404，错误体统一 `{error:{code,message}}`。错：403 区分"存在但无权限"（可枚举），500 泄露堆栈。

## 4. 容易做错的地方（具体到会出什么事故）

- X01 **不验签或只比对"看起来像订单号"** → 任何人 POST 一个伪造的 `invoice.paid` 就能把任意工作区变成 active，等于白送会员。
- X02 **去重维度选错**（按业务单号而非事件 id）→ 多个事件被误判重复而漏处理，订阅永不激活；或重复处理出两张发票。
- X03 **乱序事件回退状态** → 已付款客户被判欠费、权益被撤销，客服工单与退款申请同时暴增。
- X04 **金额用浮点或单位错位**（分当元）→ 单笔差 0.01、跨币种差百倍，对账永远对不平。
- X05 **信任客户端的金额/币种/计划** → 改一行请求就白嫖。
- X06 **令牌明文入库，或放进 URL 查询串** → 数据库备份或 Nginx 日志泄露即批量接管账号。
- X07 **轮换哈希密钥时重算旧摘要** → 已发出的链接瞬间全失效；应新旧并存到旧令牌过期。
- X08 **宽限期/试用/重试次数写死** → 调策略必须发版，各环境不一致（测试与生产不同）。
- X09 **幂等键只存在内存或易失缓存** → 进程重启后重放产生第二张发票、第二次扣款。
- X10 **跨租户用 403 或 500 回应** → 可枚举别人的工作区与发票，或把堆栈暴露给攻击者。
- X11 **结账会话不设 TTL、不失效** → 泄漏链接长期可用，同一会话可被重复完成。
- X12 **催收重试无上限无宽限；令牌过期后仍可无限尝试** → 邮件服务商封号、域名进黑名单，撞库空间打开。
- X13 **发票行项可编辑** → 已付款发票被改金额，收入报表与支付方长期对不上。
- X14 **权益掺入"最近一次请求的角色"；定时任务与请求路径都能改状态** → 同工作区结果随机、客户被拒；重复发信与扣款。
- X15 **以邮箱/账号为输入的入口暴露账号状态** → disabled / 未验证 / 已存在 返回不同，攻击者可批量枚举有效客户（要么无此入口，要么三种状态返回完全相同）。

## 5. 与其他模块的接口

| 模块 | 接口含义 |
|---|---|
| `auth` | 提供登录者身份与账号邮箱；不做注册、登录、会话、密码。 |
| `workspaces-and-permissions` | 提供工作区归属与"能否管理计费"的判定；据此返回 403/404。 |
| `usage-metering-and-budgets` | 提供用量与预算结论；本模块只把结论转成行项。 |
| `async-jobs` | 执行催收重试、试用到期、周期结束、开票；本模块提供幂等的状态变更入口。 |
| `email-transactional` | 发送 `payments-billing.*` 邮件；本模块只产出模板名、令牌与 `data.link`。 |
| `notifications` | 站内通知（催收、订阅变更）；本模块只提供事件。 |
| `rate-limiting` | 端点级限流（IP/账号）；本模块自带的是令牌尝试上限。 |
| `web-security` | 通用 CSRF/CORS/安全头；本模块额外要求结账端点拒绝外来 `Origin`。 |
| `file-storage` | 存放发票 PDF、签发短期下载 URL；本模块只引用链接。 |
| `webhooks-outbound` | 本模块向支付方或内部系统发出的通知型回调。 |
| `observability` | 结构化日志与指标（扣款成功率、催收回收率、webhook 拒绝率）。 |
| `feature-flags` | 套餐权益之外的运营开关与灰度；权益判定不查开关。 |
| `analytics` | 收入、转化、续费事件分析。 |
| `internationalization` | 邮件与页面的多语言文案。 |
| `audit-and-data-export` | 审计事件与个人数据导出/删除。 |

不涉及：`ai-model-gateway`、`ai-retrieval`、`llm-observability-and-evals`、`prompt-injection-and-guardrails`。

## 6. 不做什么

- 不做税费计算、税务合规、汇率换算、多币种定价（成熟层另议）。
- 不做收银台 UI、支付方式表单、银行卡/钱包 SDK 接入。
- 不做 3DS/风控编排、KYC/AML、拒付申诉流程。
- 不做用量计量与配额（属 `usage-metering-and-budgets`），不做端点限流（属 `rate-limiting`）。
- 不做登录、注册、邮箱验证（属 `auth`），不做角色定义（属 `workspaces-and-permissions`）。
- 不做收入确认、财务总账对接、合同签署。
- 不做退款审批工作流（早期由运营在支付方后台人工执行）。
- 不做多集团合并计费、不做历史数据迁移。
