# ai-retrieval 模块认知模板

> 读者：在自己技术栈里实现本模块的编码 agent。宿主约定（启动、路径映射、测试钩子、依赖顺序）见 `../HOST.md`，本文件不重复。

## 必读（一页速览）

**一句话**：把租户上传的资料变成「可被 AI 功能安全引用的事实来源」——解析 → 分块 → 嵌入 → 检索 → 带原文出处的引用。本模块交付**证据**，不交付**文采**：答案好不好看在验收范围之外，但「有没有证据、证据是否属实、是否来自本租户」在验收范围之内。

**不变式链**（断一环即出事故）
`上传字节 → 提取文本 → 按 Unicode 字符边界切分（逐字、覆盖完整）→ 同一模型同一维度嵌入 → 仅 ready 后可见 → 只在本工作区检索 → 每个命中能逐字回到原文 → 没有上下文就不生成`

**成熟版的六条底线**
1. 上传立刻返回，解析异步；状态机 `pending → processing → ready | failed` 单向可见，失败带错误码且可重试。
2. 引用不可篡改：命中带 `documentId / chunkId / 字符偏移 / 逐字原文`，任何人都能独立取回原文逐字比对。
3. 没有证据就不生成：空库或零命中返回空结果 + 明确 status，且不发起生成模型调用。
4. 隔离贯穿到底：文档、chunk、向量、引用、列表、统计、去重、幂等键一律按工作区切分；不可见资源一律 404，不用 403 区分。
5. 幂等 + 去重 + 并发安全：重试不产生第二份文档；同工作区同内容只留一份；跨工作区同内容互不影响。
6. 中文一等公民：多语言嵌入、Unicode 字符边界切分、查询归一化、UTF-8 无损往返。

**三个致命事故**（评审必查）
- 空库仍调生成模型 → 模型编造「你们 SLA 是 99.95%」并伪造引用编号。本模块最贵的 bug。
- 向量检索漏掉工作区过滤 → A 公司的内部文档出现在 B 公司的回答里。
- 引用用模型改写的摘要 → 用户点开来源对不上，责任落到你身上。

**去哪找什么**：可验收行为看 `contract.md`；验收用例看 `acceptance-plan.md`；需要拍板的取舍看 `decisions.md`；宿主怎么启动、怎么映射路径、假模型怎么用看 `../HOST.md`。

## 1. 这个模块是什么

知识库底座。输入是租户上传或同步进来的文档（文本、Markdown、PDF 等），输出是「可被检索、可被逐字引用」的事实片段。它被 AI 功能（问答、客服、Copilot、搜索）当作唯一事实来源使用，因此它的核心承诺不是「搜得准」，而是**「搜到的每一条都能被证明来自本租户的某段原文，没证据就闭嘴」**。

它同时是一个数据管道（有异步阶段、可失败的文档、可重建的索引）和一个多租户数据边界（租户之间互不可见，这比检索质量更难补救）。

## 2. 成熟版应该有什么（MVP → 成熟）

**L0 MVP：能上线的最小闭环**
- 上传单文档 → 异步解析 → 状态机 → 文本分块 → 嵌入 → 向量检索 → 返回命中与逐字引用。
- 工作区级隔离 + 读/写权限校验；不可见即 404。
- 幂等键 + 同工作区内容去重（跨工作区互不影响）。
- 空库/零命中降级为「无上下文」，不生成。
- 解析失败可诊断（错误码）可重试。

**L1 可用：能吃真实内部数据**
- 多格式解析（txt / Markdown / PDF），扫描件走失败分支而不是乱码入库。
- 混合检索（向量 + 关键词）融合排序，排序稳定可复现。
- 多语言嵌入（中文/中英混排合格）。
- 文档级元数据过滤（标签、来源系统、时间范围）。
- 删除即真删（正文与 chunk 清除）、索引重建入口、批量导入/导出。
- 计量信号（文档数、chunk 数、嵌入 token、检索次数）。

**L2 成熟：对外售**
- 连接器同步（外部知识源 → 知识库），增量同步、删除传播、源 ACL 映射到 chunk 级。
- 增量更新（文档改版只重建受影响 chunk）、版本与快照。
- 检索质量面板：命中率、空结果率、拒答率、引用点击率。
- 限流与配额、审计事件、租户级开关与灰度索引（双索引切换）。
- 上下文预算管理：去重、截断、保留多样性。

**L3 完备：平台化**
- 多知识库路由（按意图选库）、多路召回 + 查询改写 + 学习排序。
- 多模态（扫描件/表格 OCR → 文本 chunk 后入同一索引）。
- 检索缓存与失效策略、评测集回归门禁。

## 3. 每项的正确行为

| 项目 | 正确行为（黑盒可观察） |
| --- | --- |
| 上传 | 立即 201 返回文档对象；解析异步；响应含 `id/state/contentDigest` |
| 状态机 | `pending → processing → ready \| failed` 单向；只有 `ready` 可被检索 |
| 失败 | `error.code ∈ {parse_failed, empty_content, embedding_failed}`；`chunkCount=0`；不可检索 |
| 解析 | 支持 text/plain、text/markdown、application/pdf；其余 415；空文件 400 |
| 分块 | 字符边界切分；chunk 文本非空、UTF-8 无损；相邻块无空洞；重叠部分逐字一致 |
| 嵌入 | 同一模型同一维度；响应回显模型与维度；换模型后旧文档不得混检 |
| 可见性 | 未 ready 的 chunk 绝不出现在任何命中里（发布是原子的） |
| 检索 | 只在当前工作区内；命中数 ≤ topK；同查询两次结果序列一致；分数同值按 chunkId 升序 |
| 引用 | 命中带 `documentId/chunkId/start/end/text`；`text` 逐字来自 chunk；可独立取回原文比对 |
| 无上下文 | 空库 → `contextStatus=empty_kb`；有文档零命中 → `no_context`；两者都 200 空结果，不调用生成模型 |
| 答案 | `text` 非空 ⟹ 引用非空且与 `citationIds` 双向一致；引用必须来自本次命中集合 |
| 幂等 | 同键同体 → 同一 `documentId` 且不新增文档；同键异体 → 409 |
| 去重 | 同工作区同内容 → 409 且不新增；跨工作区同内容各自成功 |
| 删除 | 200 后 GET → 404、检索不再命中、数据库中正文与 chunk 文本消失 |
| 限额 | 单文档字节上限声明后生效，超限 413 且不落库；topK ≤ 20；上下文总长有上限 |
| 稳定性 | 依赖故障 → 503 且 fail closed（不返回半截命中）；上游 429 原样透传 |

## 4. 容易做错的地方（具体到事故）

| 错误做法 | 事故 |
| --- | --- |
| 去重用全局内容哈希 | B 租户导入与 A 相同的公开文档被 409 拒绝或被合并，B 的知识库被污染 |
| 先取 topK 再按工作区过滤 | topK 全被别家占满 → 检索恒返回 0 条，用户以为「没数据」 |
| 按 UTF-8 字节切分 | 中文变 `�`，命中了却展示成乱码 |
| 用纯英文模型嵌入中文 | 相似度落在噪声上，中文检索等于随机 |
| 解析未完就写进索引并参与召回 | 用户引用到半截文档、空白页、目录页 |
| 引用 = 模型改写的摘要 | 无法逐字回溯，构成事实上的捏造 |
| 无上下文时兜底生成「通用回答」 | 数据管道坏了被掩盖，几天后才发现 |
| 不可见资源返回 403 | 403/404 的差异泄露「该文档存在」，可被枚举 |
| 只删向量不删原文 | 删除请求未真正完成；导出与审计仍能带出正文 |
| 换嵌入模型后沿用旧向量 | 新旧向量混检，排序静默错误且无任何报错 |
| 只信客户端 Content-Length | 超限文件入库，网关与存储双重击穿 |
| 文件名直接拼存储路径 | 路径穿越、覆盖他人文件 |
| 幂等键用全局作用域 | 跨租户键互相冲突，还把对方的 `documentId` 泄露出去 |
| topK / 上下文长度无上限 | 单次请求塞进百万字，成本失控、模型超时 |
| 同步解析大文件 | 请求拖到网关超时，用户重传产生重复文档 |
| 检索不设超时、不隔离连接池 | 一个慢查询拖垮整个实例 |
| 只做向量检索不做关键词 | 查「错误码 E-1042」「合同编号」零召回 |
| 查询与文档归一化不一致 | 同义不同形 → 召回漂移、结果不可复现 |
| 失败文档直接删掉不留错误 | 排查线索丢失，用户重传变成重复文档 |

## 5. 与其他模块的接口（只列含义）

| 模块 | 接口含义 |
| --- | --- |
| auth | 当前调用者身份（session/cookie/Bearer）；未认证由本模块回 401 |
| workspaces-and-permissions | 工作区上下文与成员角色 → 读写判定、跨租户不可见性 |
| file-storage | 大文件直传与原件下载；本模块只存引用与元数据 |
| async-jobs | 解析/分块/嵌入任务：幂等 job key、重试与死信、取消 |
| ai-model-gateway | 嵌入调用（模型 id、维度、批量、超时、重试）与生成调用；验收期走假模型 |
| prompt-injection-and-guardrails | 文档正文进入模型上下文前的处理；本模块原样交付并标注来源 |
| usage-metering-and-budgets | 计量事件（文档数、chunk 数、嵌入 token、检索次数）与额度拦截 |
| rate-limiting | 摄入/检索频率限制；上游 429 原样透传，不改写为 500 |
| audit-and-data-export | 文档创建/更新/删除审计事件；导出用户可检索内容 |
| llm-observability-and-evals | 检索质量埋点、命中与引用日志、评测集回归 |
| feature-flags | 新解析器、新嵌入模型、灰度索引开关 |
| notifications | 摄入失败等通知（模板 `ai-retrieval.ingest_failed`，链接放 `data.link`） |
| observability | 结构化日志、traceId 回显、延迟与失败率 |
| internationalization | 文档语言识别与分词/归一化策略（中文与中英混排） |
| analytics | 检索与引用的使用埋点 |

## 6. 不做什么

- 不判断答案文本的好看与专业度；只保证结构一致与引用可追溯。
- 不做 OCR 与图片理解（交给上游文档处理）；本模块只接收解析后的文本。
- 不规定索引/向量库实现，不接通真实第三方服务。
- 不做跨组织联邦检索、跨库路由与权限合并。
- 不做嵌入/重排模型训练、不做评测集标注。
- 不做知识库 UI 与文档编辑器。
- 不做计费与配额策略，只提供计量信号。
- 不承诺语义检索质量（近义召回属「建议不测」项）。
