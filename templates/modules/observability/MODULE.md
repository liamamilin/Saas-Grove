# observability（可观测性）模块模板

## 0. 必读（一页速览）

**一句话**：observability 回答"应用自己发生了什么"——把请求、错误、业务关键计数变成**可写入、可查询、可告警的结构化事件**，并在**写入之前**把所有秘密抹掉。它不是 APM 平台、不是日志全文搜索引擎、不是告警通道、不是对外状态页。

**八条最容易出事的结论**

1. 脱敏必须在**写入前**做。写完再脱 = 库里躺着明文口令，一次备份泄漏或"日志平台被误配置成公开可查"就是安全事故。
2. 脱敏要**按字段名 + 按取值形态**两套规则同时做：只按形态漏掉 `pwd=1`、`token: hunter2`；只按字段名漏掉 `Authorization` 与 URL 查询串。
3. 客户端 IP 取 **X-Forwarded-For 右起第一个非受信条目**，不是最左边。最左边由客户端自己写，是日志投毒入口。
4. 秘密最常藏在 **stack、request body、headers、cookie、URL 查询串**。只脱 message 等于没脱。
5. 指标标签的**基数（cardinality）**是内存和账单爆炸点：`user_id` 进 label，几小时就能打爆存储。
6. 观测写入**绝不能影响主链路**：写入失败必须降级为丢弃或异步重试，不能让业务接口变成 500。
7. 错误分组指纹用 **type + 归一化 stack + route**；用 message 分组会把一个问题拆成几百组，也会把不同问题并成一组。
8. **error 采样率默认 1.0**，要降的是 trace 不是 error。丢掉的错误等于没埋点。

**术语速查**：group = 同类错误分组；series = 一组标签下的时间序列；cardinality = series 数量；mask = 掩码常量 `[REDACTED]`。

**MVP 判定**（缺一不可上线）：结构化日志写入 + 写入前脱敏 + 错误捕获与分组 + 分页查询 + 限额与保留期。

**读法**：契约与验收见 `contract.md`、`acceptance-plan.md`；本文只讲成熟版长什么样。契约里的路径是**概念名**，由宿主在 `module-map.json` 中映射（HOST.md §2）。

## 1. 这个模块是什么

只做三件事：**写入**（日志、错误、指标点进工作区隔离的存储）、**查询**（按级别/时间/关键字/指标+标签查回，分页限长）、**告警**（对指标写规则，越线产生告警并投递邮件）。

**为什么是模块而不是日志文件**：日志文件没有隔离、查询接口、脱敏契约与限额，等于把"我们出事了"交给工程师在服务器上 grep。

**参考实现的取舍**：原脚手架用外部错误跟踪 + 日志聚合 + 状态页；本模板保留其职责、去掉厂商绑定，出口全部换成本模块自己的写入/查询/告警概念。

## 2. 成熟版应该有什么（按层）

### 2.1 MVP（缺一个就不能上线）

1. **结构化日志写入**：一次可提交多条事件，每条含 `level`、`message`、`fields`；级别枚举固定 `debug|info|warn|error|fatal`。
2. **写入前脱敏**：固定的"按值形态"集 + "按字段名"集，掩码恒为 `[REDACTED]`，嵌套同样生效。
3. **错误捕获与分组**：上报返回事件 id + 分组 id；同一错误重复上报进同一组，计数累加。
4. **查询与分页**：日志与错误都能查；`limit` 有上限、`cursor` 翻页、结果倒序且不重复。
5. **限额与保留期**：请求体字节、批量条数、单字段长度都有上限；保留期后不可见；写入端点拒绝跨源请求。

### 2.2 可用（有它才敢规模化）

6. **指标写入与聚合**：counter/gauge/histogram，按标签分组聚合（count/sum/avg/min/max/p50/p95/p99）。
7. **基数保护**：每指标的 series 数有上限，越限的新序列被拒绝，而非无限增长或静默丢弃。
8. **幂等写入**：客户端带 `eventId` 时，去重窗口内重复提交不新增记录（防重试/重放重复计数）。
9. **时钟与保留期**：时间戳由服务端生成，客户端时间戳只在偏差窗口内接受；过期事件既查不到也被删除。
10. **配置自省**：只读接口暴露生效上限、脱敏规则名、采样率、保留期、受信代理、管理角色、服务器时间。

### 2.3 成熟（可以对客户承诺 SLO）

11. **告警规则**：指标 + 比较符 + 阈值 + 冷却期 + 收件目标；越线产生告警并通过邮件队列送达。
12. **告警去重与静默**：冷却期内不重复轰炸；同一规则重复越线只留一条。
13. **收件人约束**：告警只能发给本工作区成员，杜绝把本模块当邮件中继。
14. **隐私最小化**：客户端 IP、收件人邮箱在库里只存**带密钥的哈希**，可关联、不可还原。
15. **可信来源识别**：显式声明受信代理网段，按右起第一个非受信条目取客户端 IP。
16. **自监控与分级路由**：观测写入失败、丢弃量、写入延迟本身也是指标；告警优先级可配置，分级投递。

## 3. 每项的正确行为

判定口径全在 `contract.md`，此处一句话摘要（括号内为规则号）。

| 能力 | 正确行为（外部可观察） | 规则 |
|---|---|---|
| 认证与跨源 | 未认证 401 且无副作用；禁用/未验证账号与未认证表现一致；跨源写入 403 | A-1, A-5, A-7 |
| 隔离与权限 | 非成员访问 = 404（与"工作区不存在"响应逐字节相同）；写接口要成员，缺权限 403 | A-2, A-3, A-4 |
| 客户端 IP | 右起第一个非受信条目；无受信代理则忽略 XFF；只存 32 位 hex 哈希 | A-6 |
| 脱敏（值/名/范围） | 固定形态集与固定字段名名单全部掩码，覆盖嵌套对象、数组、headers、cookie、URL 查询串、stack | R-1, R-2, R-3 |
| 脱敏（时机/保真/不回显） | 落库前脱敏；掩码恒为 `[REDACTED]`；响应与错误 `details` 不含提交原文 | R-4, R-5, R-6 |
| 防伪造 | 自由文本 CR/LF 被转义，不产生第二条事件 | R-7 |
| 日志字段与查询 | 级别非法 → 条目级拒绝（202 + `rejected[].code`）；时间戳由服务端生成；时间倒序 + 游标，`limit` 超上限 → 400 `limit_exceeded`；级别/时间/关键字可组合过滤 | L-1, L-2, L-3 |
| 幂等与请求 id | 同 `eventId` 在去重窗口内只存一条；不信任客户端 `X-Request-Id` | L-4, L-5 |
| 错误捕获/分组 | 202 返回 `{id, groupId}`；同 type+stack+route → 同 groupId 且计数累加 | E-1 |
| 错误上限/脱敏/保留期 | stack 帧数或 message 超限 → 条目级拒绝；错误 message/stack 写入前脱敏；过期事件查不到、库中也无 | F-1, R-1, E-4 |
| 采样 | error 采样率默认 1.0（配置接口暴露） | E-2 |
| 指标字段与基数 | 名称/类型/标签/值逐项校验；越限新序列被拒（`metric_cardinality_limit`） | M-1, M-2 |
| 聚合与规模 | 聚合值与写入一致；区间超限 → 400 `range_too_large`；命中序列超上限 → 400 `result_limit_exceeded` | M-3, M-4, M-5 |
| 告警规则 | 创建 201；目标非成员 → 400 `invalid_alert_target` | T-1, T-2 |
| 告警投递 | 一条告警 + 一封 outbox 邮件，`template=observability.alert.fired`，链接在 `data.link` 且无凭据 | T-3 |
| 告警去重/存储 | 冷却期内不再产生告警或邮件；只存成员 id/哈希 | T-4 |
| 限额与健壮 | 体超限 → 413 `payload_too_large`；批量超限 → 400 `batch_too_large`；恶意输入不产生 5xx，之后 `/api/health` 仍 200 | X-1, X-2 |
| 配置自省 | 只暴露生效参数与规则名，无密钥值 | C-1, C-2 |

## 4. 容易做错的地方（具体到会出什么事故）

1. **读取时才脱敏**：库里是明文口令，一次备份泄漏或日志平台被误配置成公开可查即全量泄漏。
2. **只做一套脱敏规则**：只按字段名漏掉 `note`、`data` 里的秘密；只按形态漏掉 `pwd=1` 这类短口令。
3. **只脱 message**：异常 stack 带 SQL 参数与 token，网关记录的 body 里是完整口令。
4. **客户端 IP 取 XFF 最左**：伪造 `X-Forwarded-For: 10.0.0.1` 即可把攻击流量记到内网地址头上，审计与限流一起被骗。
5. **同步写日志且失败即抛**：日志平台抖动 → 用户请求 500，故障从"观测不可用"升级成"业务全挂"。
6. **日志注入**：昵称塞 `\n2026-01-01 ERROR admin logged in` 伪造日志行，污染值班判断与合规证据。
7. **用 message 做分组指纹**：message 带 id/时间戳 → 每次错误都是新分组，告警风暴且计数永远是 1。
8. **label 放高基数字段**：`user_id` 进 label → 序列数百万，费用暴涨甚至拖垮主库。
9. **counter 当 gauge 累加**：进程重启后 counter 归零，监控图出现"流量掉到 0"的假故障。
10. **信任客户端请求 id/时间戳**：伪造 request id 可串起别人的请求，未来时间戳能把事件挤出查询窗口。
11. **没有幂等键**：超时重试 → 同一错误计数两次；重放攻击 → 计数刷爆，告警阈值被绕过。
12. **把 5xx 堆栈返回给客户端**：攻击者拿到内部路径、框架版本、SQL 片段，照着打。
13. **告警目标允许任意邮箱**：本模块被当邮件中继对外群发（垃圾邮件/钓鱼）。
14. **不限制 `limit` 与查询区间**：一次请求拉走全部日志，数据库被打满，连带拖垮业务。
15. **错误采样率设成 0.1**：真实错误只剩十分之一，事故当天才发现"什么都没记录"。
16. **明文 IP/邮箱留在观测库**：合规问询答不出"这些数据是谁的"，还要连夜清洗历史数据。
17. **告警邮件链接带 token**：邮件一转发即越权，链接进聊天记录后长期有效。

## 5. 与其他模块的接口

只列模块名与接口含义；本模块不替其他模块实现任何东西。

| 模块 | 接口含义 | 方向 |
|---|---|---|
| auth | 提供当前会话身份；未认证 401，身份不可伪造 | ← auth |
| workspaces-and-permissions | 工作区归属、成员身份、管理角色（决定 404 与 403） | ← workspaces-and-permissions |
| rate-limiting | 观测写入的**速率**配额（本模块只管体积与批量条数） | rate-limiting → 本模块 |
| notifications | 告警事件的送达通道 | 本模块 → notifications |
| email-transactional | 告警邮件的 outbox 投递（模板名与 `data.link` 约定） | 本模块 → email-transactional |
| audit-and-data-export | 观测数据的导出与留存合规（本模块不开导出接口） | 双向 |
| async-jobs | 保留期清理、指标预聚合等后台任务 | async-jobs → 本模块 |
| web-security | 跨站防护策略来源；本模块按 A-7 拒绝跨源写入 | web-security → 本模块 |
| llm-observability-and-evals | AI 调用事件与评测结果写入本模块（语义由该模块定义） | llm-observability-and-evals → 本模块 |
| usage-metering-and-budgets | 用量与预算计数作为 metric 写入 | usage-metering-and-budgets → 本模块 |
| analytics | 业务埋点进 analytics，技术异常进本模块 | 双向 |

其余模块（ai-model-gateway、ai-retrieval、payments-billing、prompt-injection-and-guardrails、file-storage、webhooks-outbound、feature-flags、internationalization）无接口。

## 6. 不做什么

- 不做全链路追踪/APM 的实现选型：本模块只给事件与指标契约。
- 不做日志全文检索后端（倒排索引、搜索引擎选型）。
- 不做告警通道接入（邮件供应商、群机器人、第三方 SDK）。
- 不做对外状态页组件与可用性探测调度。
- 不做 PII 合规策略与数据主体请求（属 audit-and-data-export）。
- 不采集或存储请求体原文、session 原文、文件内容。
- 不存明文客户端 IP 与收件人邮箱（只存带密钥哈希）。
- 不做错误修复建议、自动重放、会话回放与界面录制。
- 不把日志当审计流水：需要防篡改留痕的走 audit-and-data-export。
