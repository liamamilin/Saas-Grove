# observability 决策点

每条给"推荐默认"与"选别的的代价"。标"已入契约"的项对应 `contract.md` 的 MUST 规则与用例，要改须同步改契约与用例。

| # | 决策点 | 推荐默认 | 选别的的代价 |
|---|---|---|---|
| D1 | 脱敏在写入前还是读取时 | **写入前**（R-4） | 库里是明文：备份外泄、只读 SQL、日志平台被误公开即全泄漏 |
| D2 | 脱敏按字段名、按形态还是都做 | **都做 + 固定最小集**（R-1/R-2） | 只按字段名 → 秘密藏在 `note`/`data` 里进库；只按形态 → `pwd=1` 这类短口令进库 |
| D3 | 客户端 IP 存明文还是哈希 | **HMAC-SHA256 截断 32 位 hex**（契约 §4） | 存明文：合规答不出数据归属，还要清洗历史数据；裸哈希对低熵 IP 可枚举还原 |
| D4 | 客户端 IP 取 XFF 哪一跳 | **右起第一个非受信条目**，受信网段显式声明，无声明就完全忽略 XFF（A-6） | 取最左：伪造 `X-Forwarded-For` 就能把攻击记到别人头上，审计与限流一起被骗 |
| D5 | 错误采样率 | **1.0**（只降 trace）（E-2） | 设 0.1：真实错误只剩十分之一，事故当天才发现没记录，且丢掉的补不回来 |
| D6 | 错误分组指纹用什么 | **type + 归一化 stack + route**，不用 message（E-1） | 用 message：每次都是新分组 → 告警风暴、计数永远是 1 |
| D7 | 写入要不要幂等键 | **客户端 `eventId` + 去重窗口（默认 24h）**（L-4） | 无幂等键：超时重试重复计数；重放刷爆计数、绕过告警阈值 |
| D8 | 保留期多长 | **错误 30 天、日志 7 天**，宿主可调（E-4） | 太长：成本高、删数据难；太短：出事时证据已过期 |
| D9 | 指标基数超限怎么办 | **拒绝新序列**（`metric_cardinality_limit`），不静默丢弃也不无限增长（M-2） | 静默丢弃 → 数据有洞没人知道；无限增长 → `user_id` 进 label 打爆存储 |
| D10 | 告警收件人允许哪些地址、链接怎么放 | **只允许工作区成员邮箱**（T-2）；链接放 `data.link` 且不带任何凭据（T-3） | 允许任意地址 → 本模块被当邮件中继对外群发；链接带 token → 转发即越权 |
| D11 | 写入端点是否校验 Origin | **校验**，不在 `allowedOrigins`（默认 APP_BASE_URL 的 origin）就 403（A-7） | 不校验：恶意页面借会话写伪造日志与假告警，污染值班判断与合规证据 |
| D12 | 观测写入失败时主链路怎么办 | **fail-open**：降级为丢弃/异步重试并计数 | fail-closed：日志后端抖动 → 用户请求 500，故障升级成业务全挂 |
| D13 | 500 是否自动上报错误 | **自动接线**，未处理异常都可按分组定位（X-2） | 不接线：线上错误只能靠用户截图，事后答不出"那次 500 是什么" |
| D14 | 查询存储放哪 | **起步复用主库 + 强限额**，规模上来再迁 | 一上来上独立后端多一套运维；无限制查主库则一条大查询拖垮业务 |
| D15 | 错误响应体长什么样 | **统一信封 `{error:{code,message,requestId,details}}`，code 稳定**（§2） | 直接回原始异常：前端无法按稳定码分支，且泄漏堆栈、路径、其它租户标识 |
| D16 | 是否做 PII（邮箱/手机号）脱敏 | **默认不做**，只脱凭证类秘密 | 一上来就脱：日志可读性骤降、排障变难，还易被误当成"已经合规" |
| D17 | 告警规则由谁建 | **工作区管理员建，收件人默认创建者**（T-1） | 普通成员也能建并任意指定收件人：告警系统对所有成员开放，噪音与泄漏同升 |
| D18 | 是否需要 trace/span 与会话回放 | **不做**，交给专门方案；本模块只给事件与指标契约 | 一并做：范围失控、成本上升，还与本模块的验收口径互相干扰 |
