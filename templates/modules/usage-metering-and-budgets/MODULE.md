# usage-metering-and-budgets — 模块认知模板

> 本文件教"成熟版本的这个模块长什么样"，不是代码。判定标准见 `contract.md`，用例见 `acceptance-plan.md`。

---

## 0. 必读一页（速览）

**做什么**：把"谁、在哪个租户、用掉多少、值多少钱"记成不可篡改的账本，并在租户花超预算前挡住。

**四条原则**

1. **钱是整数微元**。1 货币单位 = 1,000,000 微元，字段一律 `*_micro` 且为整数；传 `10.5` → 400；float 参与计算 = 事故。
2. **账本只追加**。用量事件不可 UPDATE/DELETE，更正用反向调整条目追加。
3. **事件时间定归属**。用量归属由 `occurred_at` 而非入库时间决定；延迟 3 小时仍属发生那天。
4. **两个动作不能混**。
   - `usage.record` = **事实登记**（已花掉，如实记，恒 201）。
   - `budget.reserve` = **消费闸门**（没花，先占额度，超预算 402）。
   混用事故：超支没被挡住；已发生的用量被丢弃导致少收钱。

**典型调用链**

```
消费方 → budget.reserve {resource_type, quantity}   # 原子预留，超限 402
      → 干活
      → budget.commit {reservation_id, quantity}  # 按实际结算，多占的释放
      → (跨阈值时) outbox: usage-metering-and-budgets.budget_warning
```

**闸门语义**：`committed + reserved + 本次请求 > limit` 时拒绝；硬停只在闸门生效，账本仍如实记账。

**月窗口**：按租户计费时区的自然月，`[start, end)` 左闭右开；跨月开新窗口，上一窗口明细永久可查。

**金额与价格分离**：价格带版本；事件入库时把单价版本与金额**冻结**在事件上，改价不回溯历史。

**最容易忽略的三件事**

- 并发下的预算检查必须原子，否则 20 个并发请求能花掉 20 倍预算。
- 预留必须带 TTL 自动释放，否则一次崩溃永久占死额度。
- 阈值通知必须"每窗口每阈值只发一次"，否则通知轰炸，硬停告警也收不到。

## 1. 这个模块是什么

**边界**：租户维度的用量记账与预算控制。
**输入**：谁产生了用量（租户、成员、资源类型、数量、发生时间）。
**输出**：可对账的用量账本、窗口预算状态（已用/已占/剩余/超支）、阈值与硬停通知、给账单的计费金额。

**为什么金额要自己算**：本模块是"计价的事实来源"——它知道单价和数量。`payments-billing` 只汇总成账单/发票/税费/折扣；`llm-observability-and-evals` 只做观测与 token 口径。三方各算一次必然对不上账。

**核心对象**

| 对象 | 关键约束 |
|---|---|
| 用量事件（不可变的使用事实） | 只追加；金额冻结；带幂等键 |
| 价格（每单位微元单价，带版本） | 改价不回溯；未知类型必须报错，不能算 0 |
| 预算（一月窗口的上限 + 阈值 + 硬停开关） | 上限改立即生效；窗口自动滚动 |
| 预留（对额度的原子占用） | 带 TTL；只能结算一次 |
| 放行令牌（一次性超支放行） | 一次性、有 TTL、明文只现一次、只存哈希 |
| 计量密钥（机器调用凭据） | 明文只现一次；只存哈希；轮换双密钥并行 |

## 2. 成熟版应该有什么（MVP → 成熟分层）

**MVP（能收钱、不出事故）**：M1 登记用量并按价格表算出 `cost_micro`；M2 金额整数微元，小数 400；M3 幂等键，重复提交只记一次；M4 预算上限 + 月窗口 + 剩余额度查询；M5 闸门接口，超预算 402 且不产生预留；M6 阈值通知（50%/80%/90% 各一次）；M7 价格表可读，未知类型 400。

**成熟（能规模化运营）**：M8 两阶段预留 `reserve → commit`，预留自动过期释放；M9 并发原子性，总占用不超上限、恰好 `floor(剩余/单笔)` 笔成功；M10 放行令牌，一次性、有 TTL、跨租户不可用；M11 计量密钥签发/列举/吊销/轮换双密钥并行；M12 硬停耗尽单独通知一次；M13 迟到事件按 `occurred_at` 归入历史窗口；M14 价格版本冻结；M15 批量登记（≤1000 条），部分失败整批不写入；M16 用量明细分页查询。

**完整（多产品线共用）**：M17 资源类型注册表——新类型必须先有单价才能上报，杜绝"0 元静默漏收"；M18 反向调整条目，导出对接 `payments-billing`；M19 多币种，币种租户级固定、窗口内不可切；M20 按资源类型分别设限，闸门判据始终是金额上限。

## 3. 每项的正确行为

### 3.1 用量登记
必填 `resource_type`（在价格表内）、`quantity`（正整数）、`occurred_at`；可选 `unit`、`metadata`（≤8 键，不放 PII/密钥）、`reservation_id`。返回事件 id、`cost_micro`、`window_key`、窗口 `committed/remaining/over_budget`。校验数量/单笔金额上限与 `occurred_at` 容忍窗口（过去 ≤7 天、未来 ≤5 分钟）。幂等头 `Idempotency-Key`：同键同义 → 200 返回原事件；同键异义 → 409。

### 3.2 金额与价格
一律 `*_micro` 整数，1 货币单位 = 1e6 微元。单价是"每 1 个单位的微元数"，"每 N 个单位"时用整数除数 + 四舍五入（half-up）。单笔金额 ≤1e12 微元（界限见 contract §2），超限 400。事件记录 `price_version`，改价只影响之后的事件。**权威值是累计后的整数金额**，不要用"单价 × 显示数量"反推。

### 3.3 预算与闸门
`budget.upsert`：`limit_micro`（`null`=不限额；`0`=任何正数用量都拒绝）、`currency`、`warning_thresholds`（百分比 ∈[1,99]，去重排序）、`hard_stop_enabled`、`alert_email`、`timezone`（计费时区，默认 UTC）。写权限限租户管理员；改预算立即生效。
`budget.reserve`：原子占用，成功 201（`reservation_id/reserved_micro/expires_at/remaining_micro`）；会超上限则 402 `budget_exceeded`，**不产生预留**、剩余额度不变。`budget.commit`：按实际用量结算并写入用量事件、释放多余占用；重复结算或已过期预留 → 409 `reservation_not_active`；预留不存在 → 404。实际用量大于预留时按实际结算并置 `over_budget`。`budget.release`：释放未结算预留；非活跃预留 → 409。

### 3.4 月窗口
窗口键 = 计费时区下的 `YYYY-MM`，`[period_start, period_end)` 左闭右开。跨月自动开新窗口：`committed/remaining` 归零，**历史窗口用量永久可查**。迟到事件按 `occurred_at` 归入历史窗口并使其已用量增加；阈值按窗口分别计算。

### 3.5 阈值与通知
阈值从"未达到"变为"已达到"的那一次提交触发一次，随后本窗口内**锁存**；用量回落后再冲高不再发。模板 `usage-metering-and-budgets.budget_warning`，硬停耗尽用 `usage-metering-and-budgets.budget_exhausted`，链接放 `data.link`，收件人为 `alert_email`（缺省为设置预算的成员邮箱），耗尽通知每窗口一次。

### 3.6 放行令牌（一次性超支放行）
管理员 `allowance_issue {amount_micro, ttl_seconds?}` → 201，**响应体不含明文**；明文只出现在 outbox 记录 `usage-metering-and-budgets.allowance_grant` 的 `token` 字段，链接在 `data.link`。兑换 → 200，当前窗口 `remaining` 增加该额度；同一令牌第二次兑换 → 404 `allowance_invalid` 且额度**不再增加**。过期、未知、属他人 → 同样 404 同样响应体。存储只存哈希。

### 3.7 计量密钥
签发 → 201，明文**只在这次响应**出现，之后任何接口都读不回。列举只显示前缀、末 4 位与时间戳。吊销后立即失效（401）。轮换：签发新密钥后**新旧双密钥并行**，旧密钥在过渡期内仍有效，过渡期结束才失效；不得"用新密钥重算旧密钥摘要"。

## 4. 容易做错的地方（会出什么事故）

| 做错 | 事故 |
|---|---|
| 用 float 存钱算钱，或阈值用浮点百分比比较 | 0.1+0.2≠0.3，明细加总与账单对不上；恰好 50% 算出 49.999%，漏发或重复发 |
| 预算检查"先读后写"或只判断"是否超限" | 20 个并发请求各自看到还有额度 → 花费 20 倍上限，平台直接亏钱 |
| 预留没有 TTL | 超时或崩溃永久占死额度，客户"没用却被限流" |
| 把 `usage.record` 也做成会 402，或硬停只在前端禁用 | 已发生的用量被丢弃 → 少收钱无凭据；用户直接调 API 绕过 → 上限形同虚设 |
| 幂等键三种错法：只比对请求体字节、没绑租户、保留期太短 | 微差被当成新事件 → 重复计费；A 用 B 的键 → 串号写入；隔天重试 → 重复扣费 |
| 窗口用本地时区或固定 UTC 偏移 | 边界漂移，夏令时那天少/多一小时 |
| 事件时间处理错：用入库时间归窗口，或完全信任客户端 `occurred_at` | 延迟事件记错月份，账单对不上；伪造时间塞进上月或未来，操纵窗口、逃过告警 |
| 阈值通知每笔用量都发，或不锁存 | 通知轰炸（用户关掉全部邮件）；或用量抖动时同一问题反复告警 |
| 账本可 UPDATE/DELETE | 数字可被改写，无法对账 |
| 金额单位混用（分/微元/元），或币种中途切换 | 1000 倍误差；历史账单含义改变，客户看到"同价不同数" |
| 单笔用量无上限，或同时开放登记/提交/预留三条路径 | 大批量请求吃掉整月额度；同一笔用量被记两次（须先设计成单一路径） |
| 错误信息回显内部细节或其他租户数据 | 泄露结构与数据，也泄露"令牌存在" |
| 用不同错误码区分令牌不存在/已用/过期/属他人 | 令牌可被枚举探测 |

## 5. 与其他模块的接口（只列模块名和接口含义）

| 模块 | 接口含义 |
|---|---|
| `auth` | 提供调用者身份；计量密钥在本模块校验 |
| `workspaces-and-permissions` | 提供租户范围与角色；隔离与写权限取自它 |
| `ai-model-gateway` | 消费前申请预算、消费后回报 token/调用量 |
| `ai-retrieval` | 检索/embedding 用量回报 |
| `file-storage` | 存储字节等用量回报 |
| `async-jobs` | 后台任务消费预算并回报用量，自带幂等键 |
| `llm-observability-and-evals` | token 统计口径与计费口径对齐（它观测，本模块计价） |
| `payments-billing` | 取"本期计费金额（微元）"生成账单；税率折扣汇率归它 |
| `notifications` | 送达预算事件；本模块只产出事件与模板名 |
| `email-transactional` | 承载 outbox 邮件：链接在 `data.link`，令牌在 `token` |
| `audit-and-data-export` | 记录预算变更、令牌签发/吊销、放行；导出用量明细 |
| `rate-limiting` | 请求频率限制，防重放刷接口；本模块不实现 |
| `web-security` | 通用 CSRF/CORS；本模块保证涉钱写接口拒绝外域 `Origin` |
| `observability` | 指标与日志（超支、预留泄漏、通知失败） |
| `feature-flags` | 新预算引擎/闸门策略的灰度开关 |
| `internationalization` | 金额与时间展示、租户时区解析；内部整数微元 |

## 6. 不做什么

- 不做付款、账单、发票、税费、折扣、汇率 → `payments-billing`。
- 不做请求频率限制与封禁 → `rate-limiting`。
- 不做权限模型、角色、组织架构 → `workspaces-and-permissions`。
- 不做登录、注册、密码、会话 → `auth`。
- 不做通知渠道、模板渲染、重试 → `notifications` / `email-transactional`。
- 不做模型调用、token 采集口径、质量评估 → `ai-model-gateway` / `llm-observability-and-evals`。
- 不做分析埋点与看板 → `analytics`；不做 webhook → `webhooks-outbound`。
- 不做用户级配额、逐 token 实时计量；本模块只做租户级金额预算与事件记账。
- 不做 schema、迁移与索引优化；不写 UI（本模块只产出链接）。
