# file-storage —— 对象存储模块认知模板

> 读者：要在自己技术栈里实现这个模块的 coding agent；以及不熟悉该领域的产品负责人。
> 本文件讲"成熟版应该是什么样"，不讲具体实现。规则编号 R1–R23 在 `contract.md` 里是可验收的 MUST；用例编号 C01–C30 在 `acceptance-plan.md`；需要人拍板的选择在 `decisions.md`。

## 必读一页（Must read）

**一句话**：本模块是"应用与对象存储之间的受控门面"——应用只保存文件的元数据，字节放在对象存储里，用户凭有时限、一次性、租户绑定的签名票据取回文件。

**成熟版的 8 条骨架**

1. **上传是三段式**：领上传票据 → 客户端把字节直传存储 → 回应用做"完成校验"（存在性 / 实际大小 / 实际类型）。少一段，就会留下"声称上传成功、落地却是错文件"的洞。
2. **每一步过三道闸**：认证（auth）→ 租户与能力（workspaces-and-permissions）→ 限额（本模块）。顺序固定：先认证，再判"对你不可见"（404），最后判"你缺能力"（403）。
3. **票据一次性 + 有时限 + 只存哈希**：上传令牌、下载令牌都满足这三条。下载链接进了聊天记录，也必须很快失效。
4. **跨租户一律 404**："不存在"与"存在但你没权限"必须返回同一个码；否则任何人都能靠 403/404 的差异探测别人文件是否存在。
5. **限额是数据不是常量**：单文件大小、允许类型、单 workspace 占用字节、票据 TTL，全部由宿主在 `params` 声明，验收按声明值测。
6. **用户上传的内容绝不能被浏览器当代码执行**：类型嗅探 + `nosniff` + 非内联白名单类型强制 `attachment` + 危险类型降级为 `application/octet-stream`。
7. **对象 key 由服务端生成**：客户端不能指定 key、猜不到别人的 key、不能用 `../` 穿越目录。
8. **失败要留痕**：被拒的上传要清理字节、通知上传者（R23）、进入审计（audit-and-data-export）。

**最常见的 4 种事故**

| 做错 | 事故 |
|---|---|
| 上传地址是长期有效的公开地址 | 任何人都能覆盖或读取任意文件，等价于删库 |
| 下载签名永久有效 | 链接泄露 = 文件永久公开 |
| 直接回显用户声明的 `Content-Type`（text/html、image/svg+xml） | 存储型 XSS：偷会话、钓鱼 |
| 拿客户端传来的路径当对象 key | 目录穿越、覆盖同租户其他文件 |

**读法**：先读 `contract.md`（规则、状态码、数据字段），再读 `acceptance-plan.md`（用例），最后读 `decisions.md`（12 个岔路口）。路径映射、测试支撑、数值声明见 HOST.md，本文件不重复。

## 这个模块是什么

- **职责**：让应用里的"文件"有身份、有归属、有时限、有配额、有清理策略，而应用自己不搬字节。
- **三个角色**：应用（元数据与裁决）、对象存储（字节）、客户端（直传直下）。
- **数据形态**：元数据落业务库（一条文件记录 + 若干票据记录）；字节落对象存储（不可变对象）；两者用 `objectKey` 关联。
- **核心张力**：字节要能直接给浏览器（快、省带宽），但"直接给"意味着凭据泄露就等于文件泄露。一切设计都围绕"**凭据短命、一次性、可撤销、与租户绑定**"。

## 成熟版应该有什么（按 MVP→成熟分层，逐条）

### MVP（能上线，不出事故）

1. 上传前校验：大小、类型、租户三项必查，超限立即拒绝，不产生对象。
2. 下载走应用：先鉴权再取字节，链接短 TTL。
3. 租户隔离：所有读写按 workspace 过滤，跨租户 404。
4. 文件名清洗（去路径分隔符、控制字符、CRLF），对象 key 服务端生成。
5. 删除：软删除 + 记录状态，异步物理清字节。

### v1（能运营）

6. 两步上传 + 完成校验（对象存在性、实际字节数、实际内容类型）。
7. 一次性票据：上传令牌、下载令牌；服务端只存哈希；各自 TTL。
8. 工作区容量配额：票据即占位，删除/拒绝即释放。
9. 列表与分页：每条记录带状态（pending / ready / rejected / deleted），排序稳定。
10. pending 超时回收：没人回来说"传完了"的票据必须过期作废。
11. 统一错误形状与稳定错误码（见 contract R19）。
12. 存储后端假实现：第三方一律用假实现，假实现的行为在 contract 里写死（B1–B4）。

### 成熟（能被安全评审过）

13. 内容嗅探 + 内联安全策略：`nosniff`、`attachment`、危险类型降级。
14. 审计事件：谁、何时、哪个 workspace、哪个文件、来源 IP。
15. 用量上报：把字节数/文件数交给 usage-metering-and-budgets。
16. 失败通知：产出 `file-storage.*` 模板的 outbox 消息，链接放 `data.link`。
17. 客户端 IP 正确解析：可信代理跳数 + 从右取，绝不取最左。
18. 大文件直传存储（不经应用内存）+ 短 TTL 上传地址。
19. 上传地址不可篡改：改 key、改签名一律 403，不允许覆盖他人对象。
20. 病毒扫描与隔离区（交 async-jobs，不在请求链里做）。

### 领先（可选，看业务）

21. 分片上传 / 断点续传。
22. 内容去重（内容寻址）。
23. 跨 workspace 分享（显式模型 + 独立 TTL，不复用租户票据）。
24. 对象版本化与覆盖保护。

## 每项的正确行为

| # | 能力 | 正确行为（判据） |
|---|---|---|
| 1 | 上传前校验 | 大小超限 413、类型不允许 415，都必须在生成对象之前判定 |
| 2 | 下载鉴权 | 未认证 401 → 不可见 404 → 缺 `files.read` 403，按此顺序 |
| 3 | 租户隔离 | 按 workspace 过滤；跨租户统一 404，不区分不存在与无权限 |
| 4 | 文件名清洗 | 去 `/`、`\`、`..`、控制字符、CRLF，截断 255；响应头用清洗值 |
| 5 | 删除 | 软删 + list 不再出现 + 旧下载票据立即失效；物理删交 async-jobs |
| 6 | 两步上传 | `upload.create` 给地址/令牌/`expiresAt`；`upload.complete` 才置 ready |
| 7 | 完成校验 | 字节没到 409；实际超限 413；嗅探类型不允许 415；成功时 `sizeBytes` = 实际字节数 |
| 8 | 一次性票据 | ≥128 bit 随机；只存 SHA-256；用过/过期/不存在同一码 401；并发恰好一次成功 |
| 9 | 配额 | pending 按声明、ready 按实际占用；超限 409；删除或拒绝后释放 |
| 10 | 列表分页 | `limit` 超限 400；返回 `items` + `nextCursor`；`createdAt` 倒序 + `id` 升序 |
| 11 | pending 回收 | 超 `pendingTtlSeconds` 未完成 → 按 404 处理，字节不保留 |
| 12 | 假存储后端 | PUT 有效地址 2xx；篡改 key/签名 403；过期 403；时钟随测试时钟 |
| 13 | 内联安全 | 必带 `nosniff`；非白名单类型 `attachment`；危险类型降级 `application/octet-stream` |
| 14 | 审计 | 上传/下载/删除留主体、workspace、文件、IP、时间 |
| 15 | 用量上报 | 只报数，口径由 usage-metering-and-budgets 定 |
| 16 | 失败通知 | 字节已落地但校验失败 → outbox `file-storage.upload_failed`，链接放 `data.link` |
| 17 | 客户端 IP | 剥最右 `trustedProxyHops` 项后取最右一项；绝不取最左；无则用连接对端地址 |
| 18 | 大文件直传 | 地址 TTL ≤ `maxUploadUrlTtlSeconds`；应用内存不装文件体 |
| 19 | 地址不可篡改 | 改 key、改签名、换方法 → 403；不能覆盖他人对象 |
| 20 | 扫描隔离 | 扫描前字节不可下载；扫描结论决定 ready / rejected |

## 容易做错的地方（具体到会出什么事故）

1. **上传地址是公开且长期有效的**。事故：地址进了浏览器历史/日志，任何人可 PUT 覆盖任意对象或 GET 读走文件——存储变成公共网盘。判据：地址必须带签名、有 TTL、绑死一个 key（R7）。
2. **上传时不校验、只信任声明**。事故：用户声明 `image/png`、实际是 HTML，落地后你按声明类型回源 → 存储型 XSS，能偷会话 cookie。判据：完成时按嗅探类型判定（R9），回源再降级（R12）。
3. **下载签名不过期，或票据可重放**。事故：链接被转发或进了日志，文件长期公开。判据：TTL 上限 + 一次性 + 用后即废（R11）。
4. **跨租户返回 403 而不是 404（或返回 200 + 空列表）**。事故：`403`/`404`/`空结果` 的差异成为文件存在性探测器，可批量枚举你租户的文件名与数量。判据：不可见一律 404（R13）。
5. **对象 key 用文件名或用户输入拼**。事故：`../../other-tenant/secret` 穿越目录，或同名覆盖他人文件。判据：key 服务端生成、随机、带 workspace 前缀（R6）。
6. **文件名原样塞进 `Content-Disposition`**。事故：文件名里带 `"` 或 CRLF → 响应头注入，可伪造 Set-Cookie/拆分响应。判据：清洗 + 安全引用（R5、R12）。
7. **把用户声明的类型原样回显**。事故：同第 2 条，一个 `text/html` 直接变成钓鱼页。判据：内联白名单 + `nosniff`（R12）。
8. **完成接口不看真实字节**。事故：用户先领一张 1 KB 票据，再用同一地址传 5 GB——账单爆掉、租户互相拖累。判据：完成后按实际字节数复核，超限即拒（R9）。
9. **上传令牌可重复使用**。事故：令牌泄漏后，别人能在你的租户里反复完成上传、塞满配额。判据：一次性 + 只存哈希（R8、R10）。
10. **只看最左一个 `X-Forwarded-For`**。事故：客户端随手伪造头部就能污染审计里的 IP，追溯全错。判据：从右取（R21）。
11. **令牌明文入库**。事故：一次库泄露（或只读备份外泄）= 全部下载链接立即有效。判据：只存 SHA-256（R22）。
12. **删文件只删元数据**。事故：字节一直留着，合规上叫"未真正删除"，导出/审计对不上。判据：软删 + 明确的物理清理任务（R15）。
13. **忽略 pending 泄漏**。事故：用户领 1000 张票据就走，存储与配额被"预约"死。判据：pending 超时回收（R17）。
14. **把凭据回显在列表/日志里**。事故：日志系统成了新的凭据泄露源。判据：明文只出现在签发它的那一次响应里（R22）。

## 与其他模块的接口

| 模块 | 接口含义 | 本模块用它做什么 |
|---|---|---|
| auth | 提供调用者身份（会话或 token） | 每个接口第一步鉴权；未认证 401 |
| workspaces-and-permissions | 给出"某人在某 workspace 的成员身份与能力集合"（`files.upload`/`files.read`/`files.delete`） | 决定 404（不可见）还是 403（缺能力） |
| usage-metering-and-budgets | 接收"某 workspace 已用存储字节/文件数"的上报 | 只报数；计费口径与预算封顶不在本模块 |
| async-jobs | 执行耗时任务 | 物理删除对象、pending 回收、扫描、缩略图 |
| audit-and-data-export | 接收文件事件与文件清单 | 审计与数据导出；导出链接的 TTL 也归它管 |
| notifications | 投递站内/邮件通知 | 上传失败等事件 |
| email-transactional | 发送 outbox 邮件 | 本模块只产出 outbox 消息（template `file-storage.<name>`，链接放 `data.link`） |
| rate-limiting | 对票据签发接口限流 | 本模块不自带限流 |
| web-security | 全局 CSRF/Origin 与安全响应头策略 | 本模块只在状态变更接口上要求 Origin（R20），其余交给它 |
| observability | 上传失败率、下载延迟、配额水位 | 指标与告警 |
| feature-flags | 灰度新上传策略（直连大文件、扫描开关） | 开关 |
| ai-retrieval | 解析后的文件文本进入索引 | 本模块只存字节与元数据，不做解析 |
| internationalization | 错误消息本地化 | 本模块只给稳定错误码，message 由它处理 |

不涉及：payments-billing、webhooks-outbound、prompt-injection-and-guardrails（文件内容不是 prompt）、llm-observability-and-evals、ai-model-gateway、analytics。

## 不做什么

- 不做病毒扫描、缩略图、转码、内容解析：属 async-jobs / ai-retrieval，请求链里不做。
- 不做计费口径与预算封顶：那是 usage-metering-and-budgets / payments-billing 的事。
- 不做全局 CSRF、防爬、限流、审计流水线（属 web-security / rate-limiting / audit-and-data-export）。
- 不做跨 workspace 分享与公开链接：除非显式建模并给独立 TTL。
- 不把字节存进业务数据库（极小文件需显式配置并接受备份膨胀）。
- 不做内容去重、对象版本、分片续传（见 decisions）。
- 不向前端暴露存储服务商的 SDK、密钥、签名细节；不实现签名算法细节，只消费后端给的地址。
- 不负责邮件/通知的送达。
