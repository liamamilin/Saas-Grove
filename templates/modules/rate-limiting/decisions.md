# rate-limiting 决策点

每条给出：**选项**、**推荐默认**、**选别的后果**。默认值是"最小依赖下把成熟版做对"。

## D-01 限流算法
- 选项：A 固定窗口（按时间片取整）；B 滑动窗口（保留窗口内计数）；C 令牌桶。**推荐默认：B**。
- 后果：A 在窗口边界可打出 2 倍突发（60s 窗口在 59 秒与 60 秒处各打满一次）；C 要额外维护"补充令牌"的时间基准，"窗口过期后恢复"语义不如 B 直观。

## D-02 计数存哪
- 选项：A 复用已有数据库表；B 独立缓存服务；C 进程内存。**推荐默认：A**；没有数据库或并发量极高时选 B。
- 后果：C 是最常见的致命选择：多实例的实际限额 = 声明值 × 实例数；B 多一个依赖与一致性延迟；A 需要唯一索引与清理策略，高并发要处理行锁竞争。

## D-03 计数器不可用时怎么办
- 选项：A fail-open（放行并告警）；B fail-closed（返回 503）。**推荐默认：A**；只允许登录、注册、找回密码这类端点切成 B。
- 后果：A 在存储故障期间等于没有限流（撞库窗口），但业务不中断；B 一次存储抖动就让全站不可用，也可能被当成放大器反复触发。产品明确接受"限流优先于可用性"时才选 B。

## D-04 维度组合与计数口径
- 选项：维度上 A 仅 IP / B 仅账号 / C IP + 账号双维度；口径上 ① 到达限流点全计 / ② 只计失败 / ③ 只计成功。
- **推荐默认：C + ①**。
- 后果：仅 IP 挡不住分布式撞库与单账号批量消耗；仅账号挡不住单 IP 批量注册与邮件炸弹；双维度意味着每请求查两个桶。只计失败会让上传、大导出等昂贵请求不受限；只计成功等于给爆破与注册 spam 免单。

## D-05 账号枚举
- 选项：A 登录与找回密码对"存在 / 不存在 / 禁用 / 未验证"返回完全一致的响应；B 区分提示。
- **推荐默认：A**。
- 后果：B 直接制造账号枚举接口，配合邮箱列表可筛出有效账号；A 让"账号被禁用"的用户只看到含糊错误，需要产品接受并另设自助找回路径。

## D-06 可信代理
- 选项：A 显式声明可信代理 CIDR，其余一律忽略 `X-Forwarded-For`；B 默认全信；C 默认全不信。
- **推荐默认：A**。
- 后果：B 让任何客户端伪造 IP，限流形同不存在；C 在有 CDN / 网关的部署里把所有人算成同一来源，误杀所有人；A 要求部署文档写清可信网段。环境没有固定代理层时 C 已够。

## D-07 身份标识怎么存
- 选项：A HMAC-SHA256（带密钥与轮换盐）；B 裸 SHA-256；C 明文。**推荐默认：A**。
- 后果：C 一旦泄露即可直接定位用户；B 对 IP 这种小空间取值可被字典反查；A 需要一把密钥与轮换策略（轮换期间旧键与新键都要能查到对应桶）。

## D-08 配额粒度与数值默认
- 选项：粒度上 A 按端点条目配置 / B 全局一个桶；数值上账号 5、IP 20、窗口 60 秒，或更严（3 / 10 / 60）、更松（10 / 100 / 60）。
- **推荐默认：A + 5 / 20 / 60**，并在 `module-map.json` 的 `params` 里显式声明；契约界限是账号 ≤ 10、IP ≤ 100、窗口 ≤ 60。
- 后果：B 会让一个热点端点吃光配额、全站 429。数值过严会误杀共享出口 IP 上的正常用户，过松挡不住慢速爆破。上线后按 observability 指标调参，不要临时改代码。

## D-09 惩罚力度与豁免范围
- 选项：只返回 429，还是重复违规升级窗口并在 TTL 后自动解封；豁免只含健康检查，还是含测试接口与内部服务身份。
- **推荐默认**：先只返回 429，豁免健康检查与测试支撑接口；内部服务豁免默认关闭、留审计、设到期时间。
- 后果：升级惩罚的风险是误封无法自动解除（必须保证 TTL 到期自动解封）；豁免每加一项都是绕过限流的后门。出现"429 之后立刻换 IP 继续打"的攻击模式时再上惩罚。
