# analytics · 决策点（需要人拍板，含推荐默认）

每条给出**推荐默认**与**选别样的后果**；未拍板即按默认实现。

## D-01 事件落在哪
**默认**：自建库为**唯一事实源**；第三方分析服务只是可选副本，未配置时**静默降级 no-op**。
**第三方为唯一源**：撤回时无法证明"数据已删除"（只能删自己的索引），R-C5/INV6 不成立。
**自建源 + 第三方副本**：撤回时也须向第三方发删除请求。

## D-02 同意模式
**默认**：默认拒绝（未表态 = 不落库）；`marketing` 等非必要用途走 `double_opt_in`（邮件令牌确认），`analytics` 等必要用途走 `direct`。
**未表态 = 允许**：属"默认同意"，监管处罚高频原因。
**全部 double_opt_in**：证据链最强，但每次授权都要等邮件。
**登录即视为同意**：把登录页当同意条款。

## D-03 purpose 粒度
**默认**：`analytics` + `marketing` 两档。**加更多档**每档都要单独文案、状态机与撤回路径。

## D-04 主体模型
**默认**：登录走 user id，匿名走客户端生成的 `anonymousId`，都用 HMAC 摘要存储。
**只留登录用户**：漏斗前段全丢，转型率分母失真。**只留匿名 id**：登录后行为无法归到账号，漏斗断在登录处。**共用 id 空间**：会撞车，也无法分别"撤回匿名历史"。

## D-05 哈希与密钥轮换
**默认**：带服务端密钥的 HMAC-SHA256 + 域分隔（user / anonymous / token / idem 各自独立域），密钥取自环境变量或密钥管理服务；**轮换时不重算存量摘要**，旧令牌过期前用**新旧双密钥并行校验**。
**裸 SHA-256(userId)**：可被字典反查，等于没哈希。**轮换时重算存量摘要**：当场作废未过期的一次性令牌，用户点邮件链接得 410。**密钥进代码库**：泄露即全部摘要可反查。

## D-06 客户端 IP
**默认**：**不存完整 IP**，只存 IPv4 `/24`、IPv6 `/48` 截断网段；必须从 `X-Forwarded-For` 的**最右侧非受信跳**取，绝不取最左侧（可被伪造）。
**完全不记 IP**：隐私最好，但失去"同一人换设备"的粗判据。**存完整 IP**：一次泄露即成精确位置数据。

## D-07 撤回后清除
**默认**：`purgeMode=sync`，撤回响应前数据已不可读；延迟高的实现可声明 `deferred`，但须给出 `purgeDeadlineSeconds` 上限。
**永久异步且无时限**：用户要求删除后系统随时可能还留着。**软删除**：软删行仍含个人数据；真删。

## D-08 聚合方式
**默认**：查询时从事件表算（缓存须随删除失效）。**只读预聚合表**：撤回后聚合数字不回落，用户仍看得到自己的计数。

## D-09 采样与限流
**默认**：**MVP 不采样**（全量落库，便于对账排查）；限流按**主体**计（默认 60 次/分钟），换账号不共享计数——按 IP 计会在 NAT 后的办公网误伤所有人。
**默认开采样**：数据量降一个量级，但漏斗与唯一主体数有偏且无法补齐。

## D-10 原始事件读回接口（`analytics.events`）
**默认**：提供，但**只返回调用者自己的事件**，且写入前已剥离敏感属性键；这是"撤回后确认删干净"与"去敏验证"的黑盒抓手。
**管理员可见全量明细**：同工作区成员等于互相可读。**完全不提供**：模块变黑盒，撤回与脱敏只能靠数据库查询。

## D-11 匿名历史是否缝合到账号
**默认**：**不自动缝合**，登录前后用两条线（`anonymousId` 摘要与 user id 摘要）分别计数；确需跨登录漏斗时，由产品提供受控的"合并匿名事件到账号"动作并记入审计。
**自动缝合**：等于在用户未同意时把登录前行为归属到自然人。

## D-12 保留期
**默认**：原始事件保留 90 天（上限 730），到期真删并从聚合消失；只含汇总数字的聚合可留更久。
**永久保留**：成本与合规双输。**短于 30 天**：跨月分析断档。
