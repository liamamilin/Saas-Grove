# ai-model-gateway（模型网关）认知模板

> 写给实现者：这是"成熟版应该长成什么样"，不是实现教程。硬规则见 `contract.md`（R 编号），验收用例见 `acceptance-plan.md`（A 编号），宿主约定见 `HOST.md`。
> 术语：**上游** = 真实模型服务；**网关** = 本模块；**逻辑模型名** = 业务侧用的模型别名（如 `chat-default`），不直接暴露上游 model id。

## 必读（一页）

**是什么**：SaaS 内调用大模型的**唯一出入口**。业务代码只跟网关说话，网关负责选模型、限上限、算账、兜底故障。
**不是什么**：不是聊天界面，不是内容安全模块，不是限流模块，不是向量检索，不是扣款。

**十个不可妥协**
1. 业务代码不得直接引用厂商 SDK；只能调网关的 `complete` / `stream`。
2. 配置缺失或非法 → **进程拒绝启动**（退出码非 0、端口不监听），不能等第一个用户请求才 500。
3. 生产不得启用假模型：`MODEL_PROVIDER=fake` 仅在 `TEST_MODE=1` 下有效，否则同样拒绝启动。
4. `max tokens` 由服务端裁剪到模型上限，请求值不得直通上游。
5. usage 以**模型上报值**为准；缺失才估算，且必须标 `source`（`reported`/`estimated`）。
6. 一次逻辑调用 = **一条** usage 记账（取消/被拒不记）；中间尝试不单独计费。
7. 只对明确的瞬时错误重试，且有次数上限、指数退避+抖动、整体超时预算。
8. 回退必须显式标记（`fallback: true` + 实际模型名），不得静默换模型。
9. 幂等：同工作区 + 同幂等键 + 同请求体 → 同一结果，不重复调用上游、不重复记账。
10. 错误体形状统一，永不含凭据、上游响应原文、堆栈。

**三个最容易出事故的坑**
- 直接 `import` 厂商 SDK → 换不了供应商、测不了、密钥散落在业务代码里。
- 4xx 也重试 / 重试无上限 → 上游抖动被放大成雪崩，账单翻倍。
- 上游错误原文直接回传 → 密钥与内部结构泄露给终端用户。

**怎么读**：先读第 4 节，再按 `contract.md` 的 R 编号实现；每条 R 都有对应 A 用例。

## 1. 这个模块是什么

把"业务想生成一段文本"翻译成"安全、可计费、可兜底地调用某个模型"的中间层。

- **输入**：逻辑模型名 + 消息列表 + 可选参数（max tokens、温度、停止词、幂等键）。
- **输出**：内容 + 结束原因 + usage（token 数及来源）+ 实际使用的模型 + 尝试次数。
- **附带职责**：配置与启动门禁、上游选择与回退、超时与重试、熔断、并发护栏、usage 记账、调用留痕。
- **边界**：网关**不做内容判断**（→ `prompt-injection-and-guardrails`）；**不做频率限流**（→ `rate-limiting`）；**不做检索**（→ `ai-retrieval`）；**不决定扣不扣钱**（→ `usage-metering-and-budgets`、`payments-billing`）。

成熟版只有一条判据：**任何一次模型调用，都必须能回答"谁、用哪个模型、花了多少 token、失败时退到了哪里"**，答不上来就还没成熟。

## 2. 成熟版应该有什么（按层）

### MVP（能上线，但会被打脸）
| 编号 | 能力 | 判据 |
|---|---|---|
| M1 | provider 配置 + 启动门禁 | 缺/非法配置 → 进程非 0 退出，不监听端口 |
| M2 | 统一生成入口 + 统一错误体 | 只有 `complete` 一个入口；错误体形状固定 |
| M3 | 请求校验 + max tokens 裁剪 | 超模型上限时自动裁剪并回显生效值 |
| M4 | usage 记账（上报值优先） | 记录带 token 数与 `source` |
| M5 | 假模型 + 测试可跑 | `TEST_MODE=1` 下全链路不触网可验收 |

### 可用（v1，扛得住日常流量）
| 编号 | 能力 | 判据 |
|---|---|---|
| V1 | 逻辑模型目录与别名 | 换上游 model id 不改业务代码 |
| V2 | 流式生成 | 事件顺序固定、唯一终止事件，也报 usage |
| V3 | 有界重试 | 类别明确、次数有上限、退避带抖动、总耗时有预算 |
| V4 | 幂等键 | 客户端重试不产生第二次调用/记账 |
| V5 | 凭据脱敏 + 配置变更审计 | 没有明文密钥；改配置要 admin 且留痕 |
| V6 | 调用记录 | 可查模型、尝试数、usage、错误码、耗时 |

### 成熟（能对账、能兜底、能自证）
| 编号 | 能力 | 判据 |
|---|---|---|
| S1 | 回退链 | 主模型耗尽后按配置回退；响应标明实际模型 |
| S2 | 熔断 + 半开探测 | 连续失败后快速失败，不拖在上游超时上 |
| S3 | 并发护栏 | 单工作区在途上游调用有上限，超出立刻拒 |
| S4 | 预算联动 | 预算耗尽直接拒，不产生调用与记账 |
| S5 | 上下文预算与显式截断 | 过长输入默认拒绝；截断需显式开启且可见 |
| S6 | 可观测 | 一次逻辑调用一条 trace，字段固定、默认不含原文 |
| S7 | 多 provider 与成本路由 | 按价格/延迟/可用性选上游，故障能换供应商 |

### 领先（可选，锦上添花）
| 编号 | 能力 | 判据 |
|---|---|---|
| L1 | 评测回放 + 成本/延迟 SLO | 固定 prompt 集能重跑；错误率、p95、成本可告警 |

## 3. 每项的正确行为

| 编号 | 正确行为 | 规则 |
|---|---|---|
| M1 | 启动校验 provider/凭据/端点/超时/限值；非法 → 退出码非 0（建议 78）、stderr 一行 `gateway_config_invalid: <原因>`、端口不监听；仅 `TEST_MODE=1` + 假 provider 免凭据 | R1 R3 |
| M2 | 入口只有 `complete`/`stream`；错误体字段固定；响应带 `X-Request-Id` 且与调用记录一致 | R28 R29 |
| M3 | 非法 JSON → 400；字段越界 → 422；体超上限 → 413；`maxTokens` = `min(请求值, 模型上限, 全局上限)`，回显 requested/effective | R9 R10 R11 |
| M4 | 上游报了 usage 就用上报值（`reported`），没报才估算（`estimated`）；`totalTokens = input+output`，缓存/推理 token 单列不重复计入 | R19 R20 |
| M5 | 假 provider 与真实 provider 走**同一条代码路径**；只在 `TEST_MODE=1` 可用 | R2 |
| V1 | 业务用逻辑名，别名表由配置决定；改别名只影响之后的新调用 | R6 R7 R8 |
| V2 | 顺序 `start → delta* → usage → done`，错误时 `error` 终结；并发流字节不交错 | R14 R15 R16 R17 |
| V3 | 只重试超时/连接错/上游 429/上游 5xx；不重试我方 4xx 与上游 400/401/403；退避指数+抖动，总耗时不超预算 | R23 R24 |
| V4 | 同工作区同键同体 → 同一 `id`、同一 usage、不再打上游；同键不同体 → 409；跨租户同键不得返回他租户内容 | R30 |
| V5 | 配置读接口只返回脱敏值；持久化凭据加密存储；改配置需 admin 并写审计 | R4 R5 |
| V6 | 通过校验的调用（含失败、取消、被拒）留一条不可改记录 | R22 |
| S1 | 回退深度 ≤ 3；目标模型重新裁 max tokens；标 `fallback: true` 与实际模型名 | R25 R26 |
| S2 | 连续失败达阈值 → 打开；打开期间 503 且不打上游；半开探测成功即关闭 | R27 |
| S3 | 单工作区在途上限（1–64，默认 8）；超出 → 429 + `Retry-After`，不排队死等、不记账 | R31 |
| S4 | 预算耗尽 → 402 `budget_exceeded`，不调用上游、不记账 | R33 |
| S5 | 输入 + 输出上限 > 上下文窗口 → 422 `context_length_exceeded`；仅显式 `truncate:true` 才截断并回 `truncated:true` | R12 |
| S6 | 每调用一条 trace：`requestId/requestedModel/usedModel/attempts/status/errorCode/latencyMs/usage`，默认不含原文 | R22 R28 |
| S7 | 多 provider 切换不改调用方代码；路由结果（实际 provider/model）必须落进记录 | R8 R25 |
| L1 | 评测回放走同一入口与同一错误语义；指标口径为逻辑调用数、尝试数、失败率、p95、单次 token 成本 | R22 R23 R29 |

## 4. 容易做错的地方（会出什么事故）

1. **业务里直接 import 厂商 SDK** → 换供应商要改几十处；单测必须联网；密钥散落各处。
2. **`max_tokens` 原样传给 SDK** → 上游 400 或静默截断，用户拿到半截答案而你不知情。
3. **usage 用自己的分词估算当真值** → 对不上供应商账单，投诉时无法自证。
4. **所有错误都重试** → 上游 400（请求写错）被重试 3 次，故障时间 ×3、账单 ×3。
5. **重试无上限 / 无整体超时** → 上游挂起时线程与连接被拖死。
6. **回退静默发生** → 用户以为用 A 模型实为 B 模型，评测数据被污染。
7. **每次尝试都计费** → 用户被扣 3 倍钱，usage 与账单永远对不上。
8. **没有幂等** → 前端超时重试 = 两次调用两次扣费。
9. **没有熔断** → 上游已挂，所有请求仍排队等超时；表现为"整体变慢"而非"明确失败"。
10. **密钥出现在日志、错误体或前端** → 一次日志采集就把凭据送进集中日志系统。
11. **上游错误原文直接回传** → 上游结构与回显的密钥暴露给终端用户。
12. **生产可启用假模型** → 线上返回假数据、验收全绿，"线上是坏的"。
13. **流式中途失败静默断开** → 前端一直转圈；没有终止事件客户端永远等不到结束。
14. **流式不报 usage** → 流式调用不计费，统计漂移，账单对不上。
15. **幂等键作用域是全局** → 猜到别人的键就能拿到别人的回答，跨租户泄露。
16. **没有并发护栏** → 单租户打满上游配额，其他租户全被上游限流。
17. **启动不校验配置** → 部署成功、监控绿灯，第一个用户请求才 500。
18. **把内容安全判断写进网关** → 与 `prompt-injection-and-guardrails` 重复且易绕过；网关只管**数量与费用**，不管**内容**。
19. **默认全量落库 prompt/response** → 合规风险 + 存储成本爆炸；应默认不落，按需 opt-in 且可清理。

## 5. 与其他模块的接口

| 模块 | 接口含义 |
|---|---|
| auth | 提供调用者身份（会话凭据）；网关不签发、不续期会话 |
| workspaces-and-permissions | 提供成员关系与角色；据此判断谁能改配置、看记录、用哪个模型 |
| usage-metering-and-budgets | 网关→它：每次逻辑调用投递一条 usage；它→网关：预算余额 |
| rate-limiting | 它→网关：拒绝后网关透传 429（网关不自建第二套 rpm 限流） |
| async-jobs | 它→网关：长任务调用网关（幂等键与重试语义由网关提供） |
| ai-retrieval | 它→网关：向量化/重排走网关入口（凭据、限值、记账由网关负责） |
| llm-observability-and-evals | 网关→它：一次逻辑调用一条 trace（含重试/回退）；它→网关：评测回放复用同一入口 |
| prompt-injection-and-guardrails | 它→网关：调用前后检查内容；网关**原样转发**，不改写 |
| audit-and-data-export | 网关→它：配置变更、凭据轮换写审计；导出时清理持久化对话内容 |
| observability | 网关→它：结构化日志与指标（`requestId` 贯穿） |
| feature-flags | 它→网关：默认模型、灰度模型、开关 |
| analytics | 网关→它：调用量/失败率计数（不送 prompt 原文） |
| 其余模块（file-storage、payments-billing、email-transactional、notifications、webhooks-outbound、internationalization） | 无直接接口；将来需要时走各自模块接口 |

## 6. 不做什么

- 不做内容安全、注入检测、越狱判定（→ `prompt-injection-and-guardrails`）。
- 不做 rpm 限流与封禁（→ `rate-limiting`）；只保留**在途并发护栏**与**熔断**。
- 不做向量化、召回、重排（→ `ai-retrieval`）。
- 不做聊天会话历史与 UI（属业务模块）。
- 不做扣款与套餐（→ `payments-billing`）。
- 不做评测打分（→ `llm-observability-and-evals`）。
- 不默认落库 prompt/response（需显式开启，并配合 `audit-and-data-export` 清理）。
- 不自建密钥保险箱（凭据来自环境变量或宿主配置中心；运行时密钥必须加密存储）。
- 不承诺回答质量、不做内容审核、不保证上游 SLA；不负责验收真实第三方服务（按 `HOST.md`）。
