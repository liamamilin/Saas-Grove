# ai-model-gateway 决策点

每条给出**推荐默认**与**选别的后果**。默认与 `contract.md` 的规则一致；改动默认就要同步改契约与验收。

| # | 决策点 | 推荐默认 | 选别的后果 |
|---|---|---|---|
| D1 | 网关是不是唯一入口 | 业务只调网关，厂商 SDK 只出现在网关内一处 | 多入口 = 换供应商要改 N 处、密钥散落、计费与兜底无法统一 |
| D2 | 配置分层 | 凭据与端点走环境变量（启动必需），运行时配置只放非敏感开关（别名、限值） | 凭据进运行时配置就多一份加密与轮换负担；开关写死环境变量则改配置要重启 |
| D3 | 配置缺失时的行为 | 两级：启动门禁（退出）+ 运行期降级（503 `gateway_not_ready`） | 只做门禁则运行期被人改坏配置会 500；只做降级则故障拖到第一个用户请求才爆 |
| D4 | 生产能否启用假模型 | 不能：`MODEL_PROVIDER=fake` 且 `TEST_MODE≠1` 即拒绝启动 | 允许则线上可能返回假数据而验收全绿——最贵的线上事故 |
| D5 | 未知/不可见模型返回什么 | 404 `model_not_found`，两者不区分 | 403 会暴露模型存在性，方便枚举内部模型 |
| D6 | `maxTokens` 超上限 | 裁剪并回显 `requestedMaxTokens`/`effectiveMaxTokens` | 拒绝会让客户端大面积报错；透传会让上游 400 或直接超支 |
| D7 | 上游没报 usage 时 | 估算并标 `source: estimated` | 记 0 会低估账单；不标来源则对账时无法解释差异；直接报错则接不了不报 usage 的供应商 |
| D8 | 计费口径 | 一次逻辑调用记一次，中间尝试不单独记 | 按尝试记费会重复扣用户钱；不记又对不上供应商账单 |
| D9 | 重试默认值 | 3 次尝试、指数退避带抖动、单次 30s、整体 60s | 次数太高会放大故障并翻倍计费；太低则瞬时抖动直接失败 |
| D10 | 回退策略 | 深度 1、只在瞬时错误时回退、响应显式标 `fallback` | 静默回退会让用户以为用了 A 模型、污染评测；深度过大则成本与延迟失控 |
| D11 | 熔断阈值 | 连续 3 次失败打开，打开 30s，之后一次半开探测 | 阈值太低会误伤健康上游；太高则故障期所有请求都在等超时 |
| D12 | 幂等键的作用域与存储 | 作用域 `(工作区, 键)`；只存 SHA-256 摘要；窗口 24h | 全局作用域会造成跨租户拿到别人的回答；存明文键则库泄露即可重放请求 |
| D13 | prompt/response 是否落库 | 不落（默认关） | 落库必须配保留期、脱敏与删除接口，否则合规与存储成本双输 |
| D14 | 限流归谁 | rpm 交给 `rate-limiting`，网关只保留并发护栏与熔断 | 两边都做会双重计数、两个参数打架、封禁行为不一致 |
| D15 | 预算不足返回什么 | 402 `budget_exceeded`（与 429 限流区分） | 用 429 会让客户端当成限流去退避重试，钱包被反复拒 |
| D16 | 凭据是否落运行时库 | 尽量不落；必须落则加密 + 只留指纹 | 明文入库 = 一次库泄露即供应商账号被盗 |
| D17 | 网关要不要改写内容 | 不改写、不静默过滤（原样转发） | 网关改写会让用户所见与计费/审计口径不一致，也让 `prompt-injection-and-guardrails` 形同虚设 |
| D18 | 假模型与真实模型是否同一条代码路径 | 同一条（只换 provider 适配层） | 走旁路则测试验证的是假逻辑，上线换真模型立刻出问题 |
