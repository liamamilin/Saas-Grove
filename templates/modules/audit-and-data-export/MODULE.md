# audit-and-data-export · 认知模板

> 本文讲"成熟版长什么样"，不讲代码。规则见 `contract.md`，用例见 `acceptance-plan.md`，决策项见 `decisions.md`；宿主约定见 `HOST.md`。

## 一、必须先读（一页速览）

这个模块是三件套：**留证据**（审计）、**交数据**（导出）、**履承诺**（删除请求 + 保留期）。底座四件事：租户边界、令牌、时效、留痕。

**十条最容易出事故的判断**

1. 令牌只存摘要；明文只允许出现在 outbox 邮件（`token`、链接在 `data.link`）里，数据库其他位置搜不到明文。
2. 下载链接单次使用 + 有 TTL：过期/已用/被撤销一律 `410`，未知令牌 `404`；下载成功即作废。
3. 导出在**查询层**就带 workspace 过滤，不要"查全库再在内存过滤"。
4. 审计只追加：无修改/删除条目的接口；对审计路径用 `PUT`/`PATCH`/`DELETE` 必须 `405`。
5. 审计与导出里绝不出现密码、令牌、Cookie、`Authorization`、原始请求体、卡号。
6. 客户端 IP 取 `X-Forwarded-For` **最右侧非受信跳**，绝不取最左侧（可伪造）。
7. 删除执行**不删审计日志**，只把个人标识换成不可逆假名；账务/合同数据按各自模块的保留义务处理。
8. 删除必须有二次确认（邮件单次令牌）+ 宽限期；执行后被删账号的原会话立即失效。
9. 对"存在正常 / 未验证 / 已禁用 / 完全不存在"的账号，删除请求的**状态码与响应体结构必须一致**（防枚举）。
10. 所有阈值都是**上下界**，宿主在 `module-map.json` 的 `params` 声明实际值；`Idempotency-Key`、`X-Forwarded-For` 由脚本显式提供。

**七个不变量**：审计只增不改；导出只含本工作区；令牌只存摘要；删除只在执行前可取消；链接一次性；宽限期后才执行；时效走同一时钟。

## 二、这个模块是什么

- **留证据**：把敏感动作记成不可篡改、可核对条目。谁（成员/服务/系统）、何时（UTC + IP + UA）、对什么（目标类型与 id）、做了什么（`action` 枚举）、结果如何（`success|failure|denied`）。失败与拒绝同样要记——复盘靠的就是这一半。
- **交数据**：租户要"把属于我的数据给我"时，产出**只属于本工作区**的打包文件，经邮件里的一次性链接下载，带 manifest（类别、条数、校验和）与过期时间。
- **履承诺**：删除请求跑完 **确认 → 宽限 → 执行 → 留痕** 闭环，跨模块清理结果逐项回报；负责法律保留与保留期。

共同形状：都是**一次性、有时限、可撤销**的动作，都必须留痕，都能被审计员独立核对。

成熟版的判定标准不是"功能都有"，而是：**无内部特权访问时，安全评审者能否只靠接口与只读查询，独立验证"谁做了什么、数据给了谁、删没删干净、留没留证"**。

## 三、成熟版应该有什么

### MVP（能自证清白的最小集）

1. 审计事件存储：条目含 actor、action、outcome、target、UTC 时间、IP、UA、metadata。
2. 敏感动作清单：登录成功与失败、登出、改密、成员增删与改角色、工作区增删改、导出请求与下载、删除请求与执行、清理。
3. 审计只读接口：按 action/actor/目标/时间过滤，分页有上限，越界被拒。
4. 导出流水线：请求 → 生成 → 邮件交付 → 一次性下载 → 过期；链接可撤销。
5. 导出产物：JSON + manifest（工作区、生成时间、类别、条数、payload 校验和）。
6. 删除请求：创建 → 邮件确认（单次令牌）→ 宽限期 → 执行；执行前可取消。
7. 令牌只存摘要；明文只进 outbox。
8. 统一错误体与五个权限位（审计读/导出/删请求/删执行/法律保留）。

### 成长（多租户可运营）

9. 审计链式摘要 + 完整性自检端点（能回答"这几条链没被改过"）。
10. 幂等键、导出与删除请求的单飞闸门（防重复任务与邮件轰炸）。
11. 导出与删除异步化，失败可重试，原因用固定枚举而非自由文本。
12. 删除的**范围结果**：每个范围（账号、成员关系、业务内容…）给 `completed|skipped|failed`；未实现的记 `skipped`，不拖累整体成功。
13. 法律保留：可对工作区或对象挂 hold；挂 hold 后删除执行被阻止（"被阻止"而非"失败"），清理也跳过。
14. 保留策略可见（保留期、上次清理时间、清理计数）+ 手动触发清理 + 清理本身留痕。
15. 跨租户隔离的**自动化断言**：产物里每条记录的归属逐条校验，不靠"看起来对"。
16. CSV 导出与公式注入转义（以 `=`、`+`、`-`、`@` 开头的值）。

### 成熟（可审计、可合规、可运营）

17. 事件 schema 版本化 + 事件类型注册表；旧消费者遇未知字段不崩。
18. 链头摘要周期性锚定外部只追加位置（防改库后无法发现）。
19. 导出支持按类别、时间范围、增量；产物分片、压缩、清单、断点续传。
20. 删除编排：逐模块擦除清单、失败重试、人工介入队列。
21. 假名化历史审计：个人标识换成不可逆假名，映射只保留到策略期（删干净不丢证据）。
22. 保留策略按类别与法规配置（审计 ≥180 天；账务类按 payments-billing 的义务）。
23. 导出与删除的用量计量（usage-metering-and-budgets 计费）。
24. 事件外发给合规系统（webhooks-outbound）。

## 四、每项的正确行为

1. **审计条目**（R-AUD-03）：字段齐全、缺一不可；`metadata` 只放结构化小字段，不放自由文本与请求体。
2. **只追加**（R-AUD-02）：条目写入后不可改；无接口能改写或删除它（保留清理例外，且留痕）。
3. **完整性**（R-AUD-06）：每条带摘要与前一条摘要；提供"链是否完好"的端点；不同内容摘要必不同。
4. **脱敏**（R-AUD-07）：审计与产物都不含密码、令牌、Cookie、卡号；失败登录最危险——有人顺手把尝试的密码写进日志。
5. **客户端 IP**（R-AUD-08）：从 `X-Forwarded-For` 右往左跳过受信代理，取第一个非受信地址；不信任自报头。
6. **导出租户隔离**（R-EXP-07）：同一人属于多个工作区时，导出只含当前工作区的成员与数据；`manifest` 写明工作区。
7. **导出链接**（R-EXP-04/05/06）：随机高熵、只存摘要、一次性、有 TTL、过期/已用/被撤销可辨；下载响应禁止缓存（`no-store`）与外泄（`no-referrer`）。
8. **导出产物**（R-EXP-08/09/10）：`manifest` 条数与实际一致；`payload` 有校验和可自验；不含秘密；超限整体失败不留半成品。
9. **删除请求状态机**（R-DEL-01/02/03）：`pending_confirmation → scheduled → (cancelled | blocked | completed | failed)`；仅 `scheduled` 且未到执行时刻可取消；执行时刻 = 确认时刻 + 宽限期。
10. **删除执行**（R-DEL-04/05/06）：幂等（重复执行不重复记审计）；逐范围回报结果；执行后账号会话失效、成员关系消失，**审计条目不消失**（假名化）。
11. **枚举安全**（R-DEL-09）：账号任何状态下状态码与结构都一样；错误文案不出现"用户不存在"。
12. **保留与法律保留**（R-RET-01..04）：策略可读、清理可触发、清理留痕；hold 覆盖的对象既不清理也不被执行删除；审计保留期 ≥180 天。

## 五、容易做错的地方（会出什么事故）

1. **存了令牌明文** → 数据库泄露 = 所有租户的导出文件可被直接下载，备份里也全是令牌。事故：一次注入即批量泄露。
2. **下载链接可重复使用或放在公开路径** → 转发/猜路径即拿到整租户数据，而链接常被浏览器历史与代理日志留存。事故：静默泄露。
3. **导出"查全库再过滤"** → 忘了加 workspace 条件 = 跨租户数据混入产物。事故：A 公司拿到 B 公司客户名单。
4. **IP 取 `X-Forwarded-For` 最左侧，或全信客户端自报** → 审计里的 IP 一律伪造。事故：溯源失效，审计成摆设。
5. **审计可被应用内接口修改/删除** → 有普通接口权限的人就能抹痕迹。事故：内部违规无法追责，审计不被采信。
6. **审计记录原始请求体** → 密码、令牌、卡号全部进日志。事故：日志成为新的泄露面，且常无删除入口。
7. **删除时把审计一起删掉** → 丢证据，又被认定"未留存记录"。事故：合规处罚 + 无法证明谁删的。
8. **删除时把账务/合同数据一起删掉** → 违反留存义务。事故：税务与审计问题。
9. **软删除不清个人数据** → "删除"名存实亡，导出与备份里仍能检索到。事故：做不到"删除后不可恢复"。
10. **删除请求不验证身份，或确认链接不单次使用** → 任意成员可删公司数据，转发即删；已执行的删除若仍显示"可取消"，用户会以为数据还在。事故：不可逆数据损失 + 合规承诺与界面不符。
11. **枚举（"用户不存在"）** → 可批量探测企业员工邮箱。事故：钓鱼名单外泄。
12. **没有幂等键与单飞闸门** → 用户狂点"导出"生成几十个任务、几十封邮件。事故：邮件通道被打爆、成本失控、真邮件被淹没。
13. **各模块各用各的时钟** → 过期判断错乱，链接刚生成就失效或永不过期。事故：安全策略形同虚设。
14. **CSV 不转义** → 用户填 `=cmd|...` 打开表格即执行公式。事故：管理员机器遭公式注入。

## 六、与其他模块的接口

只列接口含义，路径与契约由各模块自己定义。

- **auth**：身份与账号状态来源；登录/登出/改密/账号启停是审计事件主要写入源；删除执行后账号失效由它执行；会话失效为 `401`。
- **workspaces-and-permissions**：工作区边界与成员角色；权限位由它判定；删除执行时移除成员关系由它执行；非成员访问按"不可见"处理。
- **usage-metering-and-budgets**：导出生成与保留清理的用量计量与计费口径。
- **async-jobs**：导出生成与删除执行的异步载体；要求可重试且幂等。
- **email-transactional**：导出就绪与删除确认邮件的投递；模板名 `<模块>.<名>`，令牌在 `token`、链接在 `data.link`。
- **payments-billing**：账务与合同数据的留存义务（不在本模块清理）；订阅状态是否允许导出由它解释。
- **file-storage**：导出产物的存放与访问控制（若宿主实现）；令牌与有效期仍归本模块。
- **rate-limiting**：导出与删除请求的频率限制；本模块只做"单飞 + 幂等"闸门。
- **web-security**：请求体大小限制、跨站请求防护、输出编码与安全头。
- **observability**：本模块自身运行指标（队列深度、导出耗时、清理耗时、失败率）；日志与指标不能替代审计。
- **feature-flags**：可选能力开关（CSV 导出、法律保留、多格式）。
- **ai-retrieval**：删除执行时，该用户的向量索引与检索内容需一并清除。
- **webhooks-outbound**：审计事件外发给合规/审计系统。

## 七、不做什么

- 不做通用日志平台、日志采集与检索（observability）。
- 不做业务分析、指标看板、留存漏斗（analytics）。
- 不做备份、快照、时间点恢复；导出是"给我一份"不是"恢复"。
- 不做数据分类、打标、DLP 扫描与敏感内容识别。
- 不做跨区域数据驻留与跨境合规评估；internationalization 只做本地化。
- 不做账号注册、登录、会话与密码策略（auth）。
- 不做成员邀请、角色编辑、团队结构（workspaces-and-permissions）。
- 不做营销同意与偏好中心，也不做工单、客服与申诉。
- 不做密钥托管与加密设施（用宿主既有密钥管理）。
- 不替代法务判断：本模块只实现"删除请求 + 执行编排"，法定例外由 legal hold 表达。
