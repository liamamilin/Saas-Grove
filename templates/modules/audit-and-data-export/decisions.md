# 决策点：audit-and-data-export

需人拍板的选择。每条给出**推荐默认**与**选别的直接后果**；默认值已写进 `contract.md` 与 `acceptance-plan.md`。

## D-01 令牌交付与产物存放

**默认**：令牌只经 outbox 邮件交付，接口不返回明文令牌；产物自持。
**后果**：接口也返回链接 → 进浏览器历史、代理日志与 Referer 头；重发只能发新令牌作废旧令牌；产物连令牌下沉 → 撤销与过期不可靠。

## D-02 下载是否要求登录会话

**默认**：令牌自证，带令牌即可下载，不要求会话与成员身份。
**后果**：要求会话 → 换设备打开邮件链接失败；不要求 → 链接泄露即等于整租户数据泄露，一次性、TTL、邮件投递、禁止缓存须同时成立。

## D-03 导出的默认内容集合

**默认**：`exportCategories` 默认 `["identity","workspace"]`；审计条目默认不导出。
**后果**：导出审计 → 产物带出内部结构与假名化前的标识，与"删除后不可检索"冲突；要导出就得按假名化状态输出。

## D-04 删除请求的粒度与主体

**默认**：只有"整个工作区"与"本人"两种主体，不提供"按成员邮箱删除他人数据"的接口；二次验证用邮件单次令牌，不额外要求重新认证。
**后果**：提供按成员删除 → 接口成邮箱探测器，须强制统一响应（R-DEL-09）；若要求"最近 N 分钟认证过" → 耦合 auth 会话新鲜度接口。

## D-05 宽限期与执行触发

**默认**：宽限期 7 天（60 秒..90 天）；到期后台执行，另提供需 `audit.delete.execute` 的 `deletion.run_due`、`retention.run_due`。
**后果**：只留后台执行 → 只能轮询，"到点没执行"无人察觉；run_due 开放给普通成员 → 任何人可手动触发删除。

## D-06 失败与拒绝是否入审计

**默认**：入；`outcome` 覆盖 `success|failure|denied`，失败原因用固定枚举。
**后果**：只记成功 → 撞库、越权、枚举不可见；原因写自由文本 → 无法聚合且易夹带敏感值。

## D-07 审计完整性的强度

**默认**：链式摘要 + 完整性自检端点；摘要用带密钥 HMAC（密钥在密钥管理而非数据库），链头定期锚定外部只追加位置。
**后果**：只存顺序号 → 改库后无法发现；带密钥 HMAC → 轮换要考虑旧链头能否验证。

## D-08 删除后审计删还是留

**默认**：留条目，个人标识换成不可逆假名，条目数不减。
**后果**：删条目 → 销毁证据、违反留存义务；`metadata` 里仍留邮箱或 IP → 仍可检索到，删不彻底。

## D-09 导出格式

**默认**：只支持 JSON；CSV 由 `exportFormats` 显式开启。
**后果**：CSV 要额外承担公式注入转义与编码；两格式并存时 `manifest` 与校验和分别定义。

## D-10 保留策略粒度与上下限

**默认**：按类别配置；审计 ≥180 天、导出产物 1 小时~30 天、删除请求记录 ≥30 天。
**后果**：单一全局保留期 → 审计太短不合规、产物太久扩大泄露面；产物保留期 ≠ 链接有效期，别只设链接 TTL。

## D-11 法律保留的表达与解除

**默认**：`legal_hold` 作用于工作区或具体对象；挂 hold 后删除执行被阻止（"被阻止"而非"失败"）、清理跳过；必须可解除。
**后果**：不可解除 → 删除永远停住；语义不分 → 运维误判成故障重试。

## D-12 枚举安全的统一程度

**默认**：账号任何状态下状态码与响应体结构完全一致；确需区分时改用成员列表。
**后果**：给"用户不存在"提示 → 接口变邮箱探测器；完全一致 → 流程上要用别的信号安抚。

## D-13 导出频率闸门强度

**默认**：最小间隔 60 秒 + 最多 1 个未完成任务；幂等键**先于**闸门判定。
**后果**：只做并发闸门 → 连点排队生成大量产物；只做频率闸门 → 长任务期间堆积请求；幂等后判 → 重试报错。
