# email-transactional 决策点

每条给出**推荐默认**。若不采用，必须同步修改 `contract.md` 的对应规则与 `acceptance-plan.md` 的用例期望——两者不能各说各话。

| # | 决策点 | 推荐默认 | 选别的后果 |
|---|---|---|---|
| D1 | 发送是否在请求内同步等 provider | 异步入队，返回 `202 + id` | 同步：provider 一抖动就拖垮业务接口，上游重试再叠一层变重试风暴；异步：调用方必须接受"已受理≠已投递" |
| D2 | 模板命名 | `<模块>.<名>`，各业务模块自命名空间 | 不带前缀：跨模块撞名，后注册覆盖先注册，收件人收到别的模块的文案 |
| D3 | 模板变量校验 | 严格相等：缺变量与多变量都报错 | 宽松（缺失填空串）：变量名拼错时静默渲染成空模板，最难排查 |
| D4 | 强制类别能否退订 | 不能；强制类邮件不带任何退订能力 | 能：用户退订后收不到安全通知，找回密码失效，等于把账号交出去 |
| D5 | GET 退订链接是否消费令牌 | 不消费：GET 只展示确认页，确认 POST 才消费 | 消费：邮件安全扫描器预取链接，用户被静默退订 |
| D6 | 退订粒度 | 按类别（令牌带类别），一次只退一类 | 全局一刀切：退订一类顺带退掉所有类，用户长期收不到必要邮件 |
| D7 | 令牌存储与轮换 | 只存 SHA-256 小写十六进制；轮换时新旧双键并存，直到旧令牌自然过期 | 明文入库：库泄露即令牌全泄露；单键立即切换：旧邮件里的链接集体失效（不要去"重算旧摘要"） |
| D8 | 退信/投诉/软退信的抑制范围 | 硬退信只抑制非强制类别；投诉抑制全部；软退信不抑制 | 一刀切：硬退信连带抑制安全邮件，用户永久失联；软退信也抑制：偶发退信的用户被永久拉黑 |
| D9 | 每收件人发送上限 | 5 封/小时（契约上限 10），超限 `429` + `Retry-After` | 无上限：单邮箱被轰炸、域名被拉黑；上限过低：正常批量通知被误杀 |
| D10 | 客户端 IP 来源 | 只采信可信代理的 `X-Forwarded-For`，取最右非可信跳 | 取最左：攻击者伪造 IP 绕过限流；完全不采信：代理后所有人共用一个桶，一人撞限全站被限 |
| D11 | 幂等键语义 | 同键同载荷 → 同一 `id`；同键异载荷 → `409`；窗口 24h | 无幂等：上游重试造成重复通知与重复扣费；同键静默覆盖：请求被吞，用户收不到邮件 |
| D12 | 记录里存不存正文与令牌 | 只存元数据（收件人、模板、类别、状态、时间）；保留 90 天后清除 | 存正文：个人数据与令牌扩散到备份、日志与分析表，删除请求清不掉；不设保留期：地址越积越多，删号删不干净 |
| D13 | provider 反馈鉴权 | HMAC 签名 + 防重放；密钥由部署配置 | 无鉴权：任何人可伪造退信把任意地址拉黑（定向拒发攻击） |
| D14 | 一键退订与浏览器 `Origin` 校验 | 机器调用（provider 的 POST）不走 `Origin` 校验，只凭令牌 | 一刀切加 `Origin`：provider 一键退订全线失效 |
| D15 | 退订/偏好接口是否要求登录 | 退订凭邮件内令牌即可；偏好读写要登录 | 全要求登录：换邮箱的老用户无法自助退订，投诉堆积；全不要求：知道地址就能改他人偏好 |
