# feature-flags 决策点

每条是**人要拍板的选择**，附推荐默认与"选别的会怎样"。默认值的机器可读形式写在 `contract.md` §6 的 `params` 里，宿主必须声明；本文说清为什么推荐它。

| # | 决策点 | 推荐默认 | 选别的后果 |
| --- | --- | --- | --- |
| D-01 | 求值一个不存在的 flag key | 404 `unknown_flag`；已归档的 key 反而返回默认值 + `reason=archived` | 宽容回落默认值时，客户端收不到"这个开关已下线"的信号；打错的 key 静默走默认路径，灰度被误读成"没生效" |
| D-02 | 谁有 flag 管理权 | 生产用平台角色（`params.feature-flags.manageRole` 声明）；缺省回退到工作区 owner/admin 只为让模块可被验收 | 用工作区 owner 时，任一租户 owner 能改全局开关——把止血开关交到客户手里，一次误操作影响所有租户 |
| D-03 | 灰度按什么分桶 | 按 `scope` 分：`workspace` 用 workspaceId，`user` 用用户 id | 一律用用户 id 时，500 人的租户里"50%"变成一半员工看得见，租户内体验割裂、工单暴涨 |
| D-04 | 灰度盐放在哪 | 持久化的固定盐（存库或配置），轮换时新旧双盐并行 | 每次部署随机生成盐时，每次发版全体人群重排，已命中的用户被踢出灰度，灰度实验失去连续性 |
| D-05 | kill 之后返回什么值 | 独立的 `killValue`，缺省等于 `defaultValue` | 直接复用 `defaultValue` 时，`defaultValue=true` 的老功能被 kill 后仍返回 true，kill 形同失效 |
| D-06 | 过期令牌与非法令牌是否区分 | 一样 404 `invalid_or_expired_token` | 区分（410 / 404）时，攻击者能判断"这个令牌曾经有效"，被截获的链接可被离线验证 |
| D-07 | 令牌摘要算法 | `sha256` 或 `hmac-sha256`（令牌是高熵随机串，不需要慢哈希） | 用 bcrypt / argon2 时每次兑换多几十到几百毫秒，登录高峰会被拖垮，且只能靠前缀索引查询 |
| D-08 | 哈希密钥轮换方式 | 新旧双密钥并行校验，等旧令牌自然过期后撤旧密钥 | 重算并改写已存摘要时，在途令牌集体失效，用户被反复登出、正在兑换的邀请失败 |
| D-09 | 求值要不要缓存 | 默认不缓存（`cacheTtlSeconds=0`）；要缓存必须满足 F-07 | 默认开缓存时，kill 生效会慢一个 TTL，事故期流量继续冲向下游，止血无效 |
| D-10 | 客户端算不算 flag | 服务端权威，客户端只做装饰性降级 | 把规则与盐下发到浏览器本地算时，灰度人群与名单可被反推，灰度等于没有 |
| D-11 | 属性规则的数据来源 | 只吃服务端权威属性；会话主体传 `attributes` 直接 400 | 接受客户端传入时，用户改一个请求参数（如 `plan=enterprise`）就是提权 |
| D-12 | flag 下线怎么做 | 归档（保留只读定义，求值回落默认值） | 硬删除时，客户端缓存里的旧 key 变成 404，全量用户白屏或报错 |
| D-13 | 租户 beta 谁来开 | 工作区管理员发起邀请 | 允许任何人自助申请时，任何人都能给任意工作区开通 beta 功能，只能靠限流与邮箱验证兜底 |
| D-14 | 邀请令牌有效期 | 短时效（契约界限 60 秒 ~ 7 天，推荐分钟级） | 设成 7 天时，邮件在邮箱里躺一周，链接被转发或抓包后长期有效 |
| D-15 | 改动是否需要双人审批 | MVP 不做；但 kill 必须单人可执行 | 一律双人审批时，止血也要等第二个人到达，事故窗口被拉长 |
| D-16 | flag 定义放全局还是放工作区 | 全局定义 + 租户覆盖 | 放工作区时，平台无法统一灰度，每接入一个租户都要单独建一遍同名 flag |
| D-17 | 灰度粒度 | 整数百分比 0..100 | 允许小数时，阈值判定出现浮点边界误差，同一用户可能在边界上反复横跳 |
| D-18 | 灰度比例下调 | 允许，但按危险操作记录（谁、何时、从多少降到多少） | 禁止下调时，线上出问题只能等所有人跑完灰度，止血手段只剩 kill |
