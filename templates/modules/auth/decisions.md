# auth 模块 · 决策点

人来做决策（产品 / 安全 / 架构），coding agent 遇到分歧时按"推荐默认"实现，并在交付说明里记录任何偏离。每条都写清代价，买方可以权衡。

**决策顺序**：D-01/D-02（身份模型）→ D-03/D-04（注册口径）→ D-05–D-07（会话）→ D-08/D-09（MFA）→ D-10–D-13（防护与运维）→ D-14–D-16（生命周期与集成）→ D-17/D-18（交互与可观察性）。

| ID | 决策点 | 推荐默认 | 选别的后果 |
|---|---|---|---|
| D-01 | 账号体系自建还是交给托管身份服务 | 自建为主（本地 userId 为权威），托管身份服务只作可选上游 | 托管为主时本地没有权威主体标识，权限、计量、审计要跨系统拼接 |
| D-02 | 主体标识用邮箱还是内部不透明 id | 内部不透明 id 为主键；邮箱是可改、唯一（大小写不敏感）的属性 | 用邮箱当主键：改一次邮箱，所有外键与审计都要迁移；泄漏邮箱等于泄漏主键 |
| D-03 | 注册后何时算"可用账号" | 邮箱验证是硬门槛：未验证账号登录一律 403 `email_not_verified`、不签发会话；**验证确认必须证明密码**（`token` + 当前密码，或有效会话） | 不验证：垃圾账号与抢注无从区分，额度被批量薅走；验证不证明密码：受害者一点验证邮件就把攻击者的密码激活 |
| D-04 | 注册/登录/找回是否区分"账号不存在" | 不区分：统一 `accepted` / `invalid_credentials`，验证邮件照发，不发任何"已注册"提示；**停用账号的注册尝试同样统一 200** | 区分了就是用户枚举：撞库、钓鱼、批量探测都变廉价；停用账号回 403 会泄漏账号状态 |
| D-05 | 会话载体：服务端会话还是无状态令牌 | 服务端会话（Cookie 只放不透明令牌，库里存摘要，可即时吊销） | 无状态令牌无法即时吊销：泄漏后只能等过期，"踢下线"做不到 |
| D-06 | 会话有效期与"记住我" | 空闲 ≤7 天 + 绝对 ≤24 小时；"记住我"才放宽到 ≤30 天，标注可信设备、可单独吊销 | 无限期或超长 Cookie：一次 XSS 或设备失窃即长期沦陷；全都很短：用户天天重登，催生"记住我"的绕路需求 |
| D-07 | 改密/重置后是否吊销其他会话 | 吊销全部其他会话并轮换当前令牌（重置则全部失效、不自动登录） | 不吊销：密码泄漏后用户无法止损，攻击者会话继续有效 |
| D-08 | MFA 默认策略 | 用户可自愿开启；对管理/高权限角色强制（开关由 `feature-flags` 控制，属 L2，验收暂不测） | 全员强制：注册转化率与支持工单压力上升；全员可选：账号接管成本极低 |
| D-09 | MFA 因子与备份码 | L1 用 TOTP（SHA1、6 位、30 秒、±1 步）+ ≥10 个一次性备份码（每个长 ≥10 字符、熵 ≥50 bit、只存摘要）；L2 加 passkey | 只做短信/邮件码：可被 SIM 劫持；只做 TOTP：挡不住代理钓鱼；备份码明文或不限次：等于没第二因子 |
| D-10 | 登录失败：永久硬锁定还是退避 | 指数退避 + 短暂锁定，不做永久锁定；成功即清零 | 永久硬锁定：攻击者能批量锁死他人账号（低成本 DoS）；无限重试：撞库成本近零 |
| D-11 | 一次性令牌的 TTL 与消费方式 | 重置 ≤15 分钟、验证 ≤24 小时、challenge ≤5 分钟、魔法链接 10 分钟；GET 只渲染页面，POST 才消费 | GET 即消费：邮件扫描器与链接预取先用掉令牌，用户永远失败；不过期：旧邮件长期是后门 |
| D-12 | 密码策略与 KDF | 长度 ≥12 且 ≤128、允许长口令、拒绝常见密码；argon2id m=19MiB/t=2/p=1 起步、随硬件上调，bcrypt 须 cost ≥12 且先 SHA-256 预哈希；登录时自动升级；哈希用**标准 PHC 串**（自带盐与参数） | 复杂度规则：用户被逼写 `Password1!` 这类可预测值；不自动升级哈希：早期弱哈希长期留库；自研 `key_id:salt:hash` 容器：各库解不开 |
| D-13 | 密钥存放与轮换 | 主密钥放密钥服务或环境变量，不进代码库与镜像；令牌摘要 = `HMAC-SHA-256(key, 令牌)`（不加盐）+ `key_id`；**新旧 key 并存，旧 key 只校验存量摘要、不重算**，保留到存量令牌自然过期 | 密钥进代码库即永久泄漏；无 key id：轮换会让所有会话与令牌同时失效；轮换后重算存量摘要：批量重写，漏算的令牌凭空失效 |
| D-14 | 账号停用与删除语义 | 停用=立即失效全部会话且不可登录（已有会话 401、登录 403）；删除=软删除 + 立即失效 + 个人数据按保留期清除（由 `audit-and-data-export` 执行） | 立即硬删：账单、审计、法定留存悬空；只软删不清个人数据：合规上仍算"持有"；不停用会话：已注销用户仍可访问 |
| D-15 | 客服/后台如何重置 MFA 或恢复账号 | 需用户身份证明 + 通知旧邮箱 + 全程审计；后台不提供"直接改密码"按钮 | 后台一键重置：客服账号被拿下即等于批量接管用户；不通知旧邮箱：用户不知情 |
| D-16 | 是否提供外部身份登录与自动合并 | L1 之后再提供；只有外部邮箱**已验证**且与已有账号同邮箱时才合并，否则要求显式登录已有账号再合并 | 按邮箱自动合并：外部注册同名邮箱即可夺走老账号；完全不提供：企业客户留存受损 |
| D-17 | re-auth 用什么凭据 | 未开 MFA 用当前密码；已开 MFA 用当前密码 + 验证码；缺任一项一律 401 `reauth_required` 且无副作用；**re-auth 的密码尝试同样限流** | 只用密码：开了 MFA 也挡不住被偷会话的人改密码；只用验证码：键盘记录器即可改密码；不限速：可离线爆破密码 |
| D-18 | 认证事件要不要被外部断言 | 宿主声明只读概念 `auth.events.list`（仅 TEST_MODE）才断言事件；未声明则列为"建议，验收不测" | 事件不可见：出事故时无法自动回归；宿主多一处脱敏负担 |
