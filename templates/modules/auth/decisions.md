# auth 模块 · 决策点

人来做决策（产品 / 安全 / 架构），coding agent 遇到分歧时按"推荐默认"实现，并在交付说明里记录任何偏离。每条都写清代价，买方可以权衡。

**决策顺序**：D-01/D-02（身份模型）→ D-03/D-04（注册口径）→ D-05–D-07（会话）→ D-08/D-09（MFA）→ D-10–D-13（防护与运维）→ D-14–D-16（生命周期与集成）。

| ID | 决策点 | 推荐默认 | 选别的后果 |
|---|---|---|---|
| D-01 | 账号体系自建还是交给托管身份服务 | 自建为主（本地 userId 为权威），托管身份服务只作可选上游 | 托管为主时，本地没有权威主体标识，权限判定、计量归属、审计都要跨系统拼接；外部身份一旦不可用，全站登录同时不可用 |
| D-02 | 主体标识用邮箱还是内部不透明 id | 内部不透明 id 为主键；邮箱是可改、唯一（大小写不敏感）的属性 | 用邮箱当主键：改一次邮箱，所有外键、审计记录、量化口径都要跟着迁移；对外泄漏邮箱等于泄漏主键 |
| D-03 | 注册后是否必须验证邮箱才能登录 | 必须验证才能拿到完整会话（未验证只能拿受限态） | 不验证：垃圾账号与抢注无从区分，额度被批量薅走，账号可被他人抢先注册；产品上要改用"邮箱+立即可用"须同时补上人机验证与配额 |
| D-04 | 注册/登录/找回是否区分"账号不存在" | 不区分：统一 `accepted` / `invalid_credentials`，验证邮件照发 | 区分了就是用户枚举：撞库、精准钓鱼、批量探测有效邮箱都变得廉价；想要"友好提示"就得先让人机验证，顺序不能反 |
| D-05 | 会话载体：服务端会话还是无状态令牌 | 服务端会话（Cookie 只放不透明令牌，库里存摘要，可即时吊销） | 无状态令牌（自带声明、库里不存状态）无法即时吊销：泄漏后只能等过期，用户"踢下线"做不到；除非额外引入黑名单，但那样就等于又维护了会话表 |
| D-06 | 会话有效期与"记住我" | 空闲 7 天 + 绝对 30 天；"记住我"只放宽绝对上限到 30 天并标注可信设备，可单独吊销 | 无限期或超长 Cookie：一次 XSS 或设备失窃即长期沦陷；全都很短：用户天天重新登录，留存率掉，且催生"记住我"的绕路需求 |
| D-07 | 改密/重置后是否吊销其他会话 | 吊销全部其他会话并轮换当前令牌（重置则全部失效、不自动登录） | 不吊销：密码已泄漏时用户无法止损，攻击者的会话继续有效；改密只会让用户"看起来更安全" |
| D-08 | MFA 默认策略 | 用户可自愿开启；对管理/高权限角色强制（开关由 `feature-flags` 控制） | 全员强制：注册转化率与支持工单压力上升；全员可选：账号接管成本极低，出事时"用户没开 MFA"挡不住责任 |
| D-09 | MFA 因子与备份码 | L1 用 TOTP + ≥10 个一次性备份码；L2 加 passkey 作为抗钓鱼因子 | 只做短信/邮件验证码：可被 SIM 劫持、邮件账号被接管即失效；只做 TOTP：可被代理钓鱼转发的中间人攻击；备份码明文或不限次：等于没有第二因子 |
| D-10 | 登录失败：永久硬锁定还是退避 | 指数退避 + 短暂锁定，不做永久锁定；成功即清零 | 永久硬锁定：攻击者能批量锁死他人账号（低成本 DoS），且客服需人工解锁；只无限重试：撞库成本几乎为零 |
| D-11 | 一次性令牌的 TTL 与消费方式 | 重置 15 分钟、验证 24 小时、魔法链接 10 分钟；GET 只渲染页面，POST 才消费 | GET 即消费：邮件安全扫描器与链接预取会先把令牌用掉，用户永远失败，且令牌已进访问日志；不过期：旧邮件长期是后门 |
| D-12 | 密码策略与 KDF | 长度 ≥12、允许长口令、拒绝常见密码；argon2id 起步并随硬件上调参数，登录时自动升级旧哈希 | 复杂度规则（大小写+符号组合）：用户写成 `Password1!` 这类可预测值且被规则逼得抄写；不自动升级哈希：早期弱哈希会长期留库 |
| D-13 | 密钥存放与轮换 | 主密钥放密钥服务或环境变量，不进代码库与镜像；摘要带 key id，新旧密钥并存窗口后重算 | 密钥进代码库即永久泄漏（历史提交还在）；无 key id：轮换密钥会让所有会话与令牌同时失效，用户被集体登出 |
| D-14 | 账号停用与删除语义 | 停用=立即失效全部会话且不可登录；删除=软删除 + 立即失效 + 个人数据按保留期清除（由 `audit-and-data-export` 执行） | 立即硬删：账单、审计、法定留存数据悬空；只软删不清个人数据：合规上仍算"持有"；不停用会话：已注销用户仍能访问 |
| D-15 | 客服/后台如何重置 MFA 或恢复账号 | 需用户身份证明 + 通知旧邮箱 + 全程审计；后台不提供"直接改密码"按钮 | 后台一键重置：客服账号被拿下就等于批量接管用户账号；不通知旧邮箱：用户察觉不到已被接管 |
| D-16 | 是否提供外部身份登录与自动合并 | L1 之后再提供；只有外部邮箱**已验证**且与已有账号同邮箱时才合并，否则要求显式登录已有账号再合并 | 按邮箱自动合并：外部注册一个同名邮箱就能夺走老账号（最常见的 SaaS 账号接管手法）；完全不提供：企业客户与移动端留存受损 |
