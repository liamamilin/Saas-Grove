# auth 模块 · 认知模板

> 读者：要在买方自己技术栈里实现本模块的 coding agent。买方不是专家。
> 本文讲"成熟的 auth 长什么样"，不给实现代码。文中路径是**概念名**，由宿主在 `module-map.json` 映射（见 HOST.md）。

## 必读摘要（一页）

**一句话**：auth 只做三件事——证明你是谁、记住你是谁、让你能安全地改回你是谁。角色/权限/业务判定都不属于它。

**边界**：进来的是凭据（密码、一次性码、外部身份）；出去的是**稳定主体标识 userId** + **可即时吊销的会话**。出去之后密码、令牌明文、验证码不再出现。

**六条最容易出事故的事**（展开见 §4）：① 会话令牌明文入库 → 库被读即全员被接管；② 找回/验证令牌可重放或 GET 即消费 → 邮件扫描器替你用掉；③ 按"邮箱是否存在"给不同响应 → 用户枚举、可撞库；④ 登录不换会话 id → session fixation；⑤ 改密码/关 MFA/改邮箱不 re-auth → 拿到会话即永久接管；⑥ 外部身份的未验证邮箱自动并入已有账号 → 一次外部注册即可夺号。

**成熟版能力速览**：L0 = 注册/登录/会话/登出/改密/找回/邮箱验证/限流/错误形状/认证事件；L1 = +会话轮换与过期、踢下线、账号停用、MFA+备份码、CSRF 与重定向防护、重认证、密钥轮换；L2 = +外部身份合并、passkey/无密码、风险自适应、密钥托管、数据导出删除与审计。

**不做什么**：角色权限 → `workspaces-and-permissions`；邮件投递 → `email-transactional`；订阅计费 → `payments-billing`；限流实现 → `rate-limiting`；UI 美观与真实第三方接通 → HOST.md §6。

**术语**：session=一次登录的服务端记录；session token=客户端持有的高熵串，服务端只存摘要；challenge=第二步的一次性凭据；enrollment=把因子绑定到账号（验证成功才生效）；re-auth=敏感操作前重出示凭据；枚举防护=让"账号不存在"与"密码错"外部不可区分。

## 1. 这个模块是什么

身份认证是 SaaS 的入口与止损阀，回答三个问题：**你是谁**（注册/登录/外部身份）、**你还被信任吗**（会话、过期、吊销、MFA、重认证）、**你能改回你是谁吗**（邮箱验证、找回密码、改密）。

它同时是**边界守卫**：会话一旦签发，后续模块都在"已认证主体"的假设上运行；auth 一旦出错（放错人、不认自己人、认错人），整条链都错，后面模块查不出来。它**不是**授权：产出的 userId 是主体，主体能干什么由 `workspaces-and-permissions` 判定。

**实现形态不限**（自建账号与会话、或托管身份服务皆可），但对外可观察行为必须满足契约；托管形态下本地仍需维护权威 userId 与身份事件同步（`auth.identity.events`）。

## 2. 成熟版应该有什么

**L0 MVP**（缺一项即可被利用）：**A1** 注册（邮箱+密码，邮箱唯一）｜**A2** 密码慢哈希（参数可升级）｜**A3** 登录（失败响应统一）｜**A4** 服务端会话（令牌存摘要）+ Cookie 加固｜**A5** 登出（吊销 + 清 Cookie）｜**A6** 当前身份 + 服务端守卫｜**A7** 找回密码（请求+确认）｜**A8** 邮箱验证｜**A9** 限流｜**A10** 错误形状 + 认证事件｜**A11** 密钥只进服务端。

**L1 生产基线**（用户丢设备、多人共用、账号被盗时用得到）：**B1** 会话轮换｜**B2** 会话过期、列表与吊销、"记住我"｜**B3** 改密、改邮箱（须验证新址）｜**B4** 账号停用（立即失效）｜**B5** MFA(TOTP) 绑定｜**B6** 备份码与强制策略｜**B7** CSRF 与重定向防护｜**B8** 敏感操作 re-auth｜**B9** 失败退避｜**B10** 密钥轮换。

**L2 成熟**（企业客户、合规、增长）：**C1** 外部身份与账号合并｜**C2** 无密码/魔法链接、passkey｜**C3** 风险自适应｜**C4** 密钥托管｜**C5** 数据导出删除、审计闭环｜**C6** 条款/隐私同意记录。

## 3. 每项的正确行为

**3.1 注册与账号（A1 A2 A8 A11）**
- A1：邮箱归一（trim + 小小写）后判唯一，唯一性靠**数据库约束**（应用层查重在并发下会漏）。新邮箱与已存在邮箱响应**完全一致**，都不下发 Cookie。请求体的 role/workspaceId 一律忽略。
- A2：慢 KDF（argon2id/bcrypt/scrypt）+ 每用户盐，参数入库；参数提升后下次成功登录自动重算。原文不进日志、错误体、审计、邮件。
- A8：验证令牌单次、TTL 24h、只存摘要；GET 链接不改状态，POST 才确认。未验证账号拿不到完整会话（403 email_not_verified）。
- A11：会话密钥、加密主密钥、pepper 只从环境变量/密钥服务读取，绝不下发浏览器。

**3.2 登录与会话（A3 A4 A5 A6）**
- A3：凭据正确才 200 并下发 Cookie；错密码与不存在账号响应完全一致（invalid_credentials），耗时也要相近。
- A4：服务端存会话记录（userId、最后活动/过期、IP/UA、吊销标记、凭据版本），令牌只存摘要并建索引。Cookie 必含 HttpOnly、Secure、SameSite=Lax、Path=/，无 Domain；建议 `__Host-` 前缀。
- A5：登出既清 Cookie 又吊销记录；旧 Cookie 再请求受保护接口 → 401。
- A6：未认证 API 返回 401 + JSON，不能是 HTML/302；页面才 302 到登录页并带受校验 next。守卫必须在服务端每个受保护请求执行，前端隐藏入口不算。

**3.3 密码生命周期（A7 B3 B8）**
- A7：请求重置对任何邮箱返回同一 200；令牌单次、TTL 15min、只存摘要；GET 只开页面、POST 才改密；成功后作废未用重置令牌并吊销全部会话。限流见 A9。
- B3：改密需当前密码，成功后轮换当前令牌、吊销其余会话，旧密码立即失效；改邮箱须验证新地址且不得属于他人，旧地址收到通知。
- B8：改密、关 MFA、改邮箱、导出/删除前必须 re-auth（当前密码或有效 MFA），失败无副作用。

**3.4 MFA（B5 B6）**
- B5：enroll = 生成密钥 → **仅此一次**返回 provisioning 信息与恢复码 → 输码确认后才写库生效（生效前不能用于第二步）。密钥用 AEAD 加密（校验需可解密，不能哈希）。
- B6：备份码 ≥10 个、单次使用、只存哈希、用后作废；密码正确但 MFA 未完成 → 401 mfa_required + challenge_id（不下发会话），challenge 单次、短 TTL、失败 5 次作废；TOTP 拒绝已用时间步（记 last used counter），否则同码 30 秒内可重放。

**3.5 防滥用（A9 B7 B9）**
- A9：按 IP + 按账号双维度计数，超限 429 + Retry-After；维度可区分，计数可清空。
- B7：Cookie 认证的写操作校验 Origin/Referer 或 CSRF 令牌，跨站 403 且无副作用；跳转只允许站内相对路径（以 `/` 开头且不是 `//`），拒绝协议相对 URL。
- B9：连续失败按账号指数退避 + 短暂锁定，**不做永久硬锁定**（会被用来批量锁死他人账号）；成功即清零。

**3.6 事件与运维（A10 B1 B2 B4 B10）**
- A10：所有错误同一 JSON 形状，code 封闭集合，message 不含敏感值；登录成功/失败、登出、找回、改密、改邮箱、MFA 变更、账号停用都产生事件（主体 id、结果、IP/UA、时间），不含密码/令牌明文。
- B1：登录成功、提权（加 MFA）、改密后轮换令牌，旧令牌立即作废（防会话固定）。
- B2：空闲（7 天）+ 绝对（30 天）超时按服务端时间判定，超期 401 session_expired；会话列表只暴露自己的会话，可吊销单个/全部且立即生效；"记住我"只放宽绝对上限（≤30 天）、标注可信设备、仍可吊销；禁止无限期 Cookie。
- B4：账号停用 → 所有会话下一次请求即 401 account_disabled，拒绝新登录与重置邮件。
- B10：摘要带 key id（`key_id:salt:hash`），新旧密钥并存窗口，轮换时重算存量摘要。

**3.7 成熟层补充（C1 C2 C3 C4 C5 C6）**
- C1：外部身份登录校验 state/nonce；只有外部邮箱**已验证**且与已有账号同邮箱才合并，否则要求显式登录再合并——绝不按邮箱自动并号。
- C2：魔法链接令牌单次、TTL 10min、只存摘要、GET 只渲染 POST 才消费；passkey 注册校验签名，登录校验 origin 与一次性 challenge。
- C3：新设备/异地登录触发二次验证或通知；风险高时重新 MFA 并吊销旧会话。
- C4：主密钥放密钥服务/环境变量，版本化可轮换，不进代码库与镜像。
- C5：属主可导出/删除个人数据，停用后按保留策略清除并写审计；事件可按主体/时间检索。
- C6：注册时记录同意的条款版本与时间戳。

## 4. 容易做错的地方

| 做错 | 会出的事故 |
|---|---|
| 会话令牌明文入库 | 库或备份被读 = 全员会话接管，无法只改应用止血 |
| 登录不轮换会话 id | 会话固定：攻击者预置 Cookie，受害者一登录即被接管 |
| Cookie 缺 HttpOnly / Secure / SameSite | XSS 即可偷走会话；或被 CSRF 跨站写操作 |
| 会话令牌放进 URL | 泄漏到 Referer、访问日志、截图、浏览器历史 |
| 找回链接 GET 直接改密码 | 邮件扫描器/预取先消费令牌，用户永远失败，日志还留令牌 |
| 重置令牌不过期或可重放 | 旧邮件长期可改密码；并发双用两次都成功 |
| 错误提示区分"邮箱不存在" | 用户枚举 → 撞库、钓鱼精准投放 |
| 并发注册同邮箱没靠唯一约束 | 出现两个账号，配额、权限、数据分裂 |
| 改密码不吊销其他会话 | 密码已泄漏时用户无法止损 |
| 关 MFA / 改邮箱不 re-auth | 拿到会话 = 永久接管账号，不需要密码 |
| 外部身份未验证邮箱直接合并 | 外部注册同名邮箱即可夺走老账号 |
| MFA 允许同一 TOTP 码重复用 | 30 秒窗口内被重放 |
| TOTP 密钥/备份码明文存储 | 库泄漏 = MFA 形同虚设 |
| 5xx 回显堆栈 / SQL / 路径 | 泄漏内部结构、密钥名、部署拓扑 |

## 5. 与其他模块的接口

| 模块 | auth 给它 | 它给 auth |
|---|---|---|
| workspaces-and-permissions | 稳定 userId、邮箱唯一性、停用事件 | 组织与角色（MFA 策略） |
| rate-limiting | 需要计数的动作（登录/找回/MFA） | 计数与封禁状态 |
| email-transactional | 收件人、模板、令牌 | 投递结果与 outbox 可见令牌 |
| notifications | 登录/新设备/MFA 变更事件 | 站内通知投递 |
| web-security | 会话 Cookie 策略、CSRF 令牌签发 | CSRF 校验、CORS 与安全头 |
| audit-and-data-export | 认证事件 | 审计写入、数据导出/删除执行 |
| observability | 登录成功率、MFA 失败率、枚举尝试指标 | 指标管道与告警 |
| feature-flags | 强制 MFA、密码策略、会话时长开关 | 开关取值 |
| usage-metering-and-budgets | 主体/会话标识（计量归属） | 配额/预算判定 |
| async-jobs | 过期会话与令牌清理、账号删除任务 | 任务执行与重试 |
| internationalization | 稳定 error.code + 可本地化 message | 邮件与文案语言 |

依赖顺序：auth → workspaces-and-permissions → 其余（HOST.md §5）。

## 6. 不做什么

- 不实现角色、权限、组织结构 → `workspaces-and-permissions`。
- 不实现邮件发送基础设施 → `email-transactional`；auth 只负责"发给谁、发什么、令牌是什么"。
- 不实现限流器与风控引擎 → `rate-limiting`。
- 不实现订阅、账单、额度 → `payments-billing`、`usage-metering-and-budgets`。
- 不做 UI 视觉、主题、登录页设计（HOST.md §6）；只要求页面可达、含条款/隐私链接。
- 不直接接真实第三方（邮件服务商、身份服务、支付）；按 HOST.md §6 用假实现。
- 不自研密码学：KDF、加密、随机数用成熟算法与库。
- 不做头像与附件存储 → `file-storage`。
- 不实现审计留存与导出 → `audit-and-data-export`。
