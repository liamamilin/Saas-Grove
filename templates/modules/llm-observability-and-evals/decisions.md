# decisions.md — llm-observability-and-evals 人的决策点

> 这些是**需要产品/工程负责人拍板**的分歧点；契约给出必须满足的行为，但"默认取哪个"由人决定。每条给出推荐默认与选别样的后果。实现时按推荐默认落地，除非有人明确改动。

| # | 决策点 | 推荐默认 | 选别样的后果 |
|---|---|---|---|
| D-01 | 默认正文策略 | `bodyMode=hash`（只留摘要） | `full` → 一次数据库泄露就是全租户 PII 泄露；`none` → 线上排障全靠猜，客服工单无解 |
| D-02 | 策略降级时是否连带清除历史正文 | 自动清除且不可逆 | 不清除 → 管理员以为已删实际还在，删除请求无法闭环、审计不通过 |
| D-03 | 是否允许 `full` 模式 | 允许，但只对指定 feature 由管理员开启并留审计 | 全局可开 → 排障便利变成常态，明文长期留存；完全禁止 → 排障只能看摘要 |
| D-04 | 内置脱敏清单能否关闭 | 不能关闭（只能加） | 可关 → 一次"临时排障"忘开就是长期泄露 |
| D-05 | 采样粒度 | 按 trace 决定 | 按 span → trace 只剩一半，排障被"缺失的 span"误导，成本估算偏差 |
| D-06 | 默认采样率 | 1.0（全留） | 0.5 → 事故最需要的那条链路恰好没被采到 |
| D-07 | 默认保留期 | 30 天 | 7 天 → 季度级问题无法复盘；90 天以上 → 删除请求做不干净 |
| D-08 | 评测判据类型 | 确定性判据（equals/contains/not_contains/regex） | LLM 自评（温度 > 0）→ 同一版本两次结论不同，回归门禁误报漏报，团队开始忽略它 |
| D-09 | 基线语义 | 锁定"运行开始时"的基线 | 用最新一次 → 回归被自我覆盖，永远发现不了退化 |
| D-10 | 基线能否跨数据集引用 | 不能 | 可跨 → 对比数字无意义，团队误判质量 |
| D-11 | 评测用哪个模型与参数 | 与生产同配置 | 用便宜模型 → 评测结论对生产无效，回归门禁挡不住真实退化 |
| D-12 | 评测调用是否计入产品成本 | 计入，单列 feature 便于对比 | 不计入 → 账单与看板对不上，评测被当成"免费"，成本失控无感知 |
| D-13 | 评测数据集能否编辑 | 能编辑，但历史运行保留当时快照 | 可改并改写历史 → 历史结论不可复现；完全不可改 → 调判据就得重建数据集 |
| D-14 | 评测资产是否随保留期清理 | 随保留期清理 | 永久保留 → 删除请求永远做不干净 |
| D-15 | 是否提供重放 | 提供，但一次性令牌 + 权限 + 限流 | 开放任意重放 → 令牌重放即账单放大攻击；不提供 → 偶发问题无法复现 |
| D-16 | 无正文时能否重放 | 不能（409 `replay_unavailable`） | 放行 → 等于绕过日志策略把原文拿回来 |
| D-17 | 成本表示 | 整数 `costMicros` | 浮点美元 → 累加误差导致月底对账差钱且无法复现来源 |
| D-18 | 限流维度 | 账号 + 工作区 | 全局共享 → 一个租户拖垮全部租户，验收用例也互相干扰 |
| D-19 | 采集幂等键 | `spanId`（调用方生成） | 无幂等 → 网关重试让成本翻倍，与模型供应商账单对不上 |
| D-20 | 失败调用是否记录 | 记录（`status=error` + `errorCode`） | 只记成功 → 事故时看不到失败率与真实成本，形成盲区 |
| D-21 | 是否记录来源 IP | 记录，且按最右侧非受信跳解析 | 取最左侧 → 攻击者伪造 IP 绕过风控限流、污染审计记录 |

## 取舍补充（不必拍板，但要知道）

- 评测判据用 `regex` 时模式长度上限 512：够用且挡住 ReDoS 式的长表达式；确需复杂语法时按 feature 单独放开。
- `clientIp` 只用于滥用排查，不做精确地理位置，避免额外合规面。
- 本模块不发邮件：评测失败与预算超限的通知交给 notifications 模块，本模块只产出事件。
