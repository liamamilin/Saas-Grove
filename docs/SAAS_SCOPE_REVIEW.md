## 复核过程

先审阅全部 203 个拟排除项，再处理另外 345 个低把握、混合形态及范围变化项。345 项使用轻量执行代理逐项判断，拟新增排除的 32 项又经过独立复核：12 项纳入、16 项待确认、4 项确认排除。每条最终记录都有理由和交付边界；争议项不会被迫二选一。

主要纠正两类偏差：有离线实现不代表整个类型不能服务化；面向个人或公众、提供网页前台，也不自动等于消费场所。网页邮箱、论文阅读、市场建设、道路救援运营等按真实工作对象和完整应用边界判断。反过来，公共社交内容池、实际交易和金融服务、裸组件与现场控制不会仅因有登录、订阅或管理控制台就纳入。

例如：团队消息、客户自建社区、代码编辑与完整开发应用可寻找服务化案例；浏览器、软电话及裸引擎和完整控制台混合的类型需要具体产品证据；大众社交网络、约会撮合、实际市场、模型 API 服务和 SCADA 仍按定义排除。所有边界均见逐项决策，不能用此处例子代替具体定义。

## 案例验证仍是独立阶段

`definition_reviewed` 表示按定义完成边界复核，不能声称 1,511 类均已有真实应用。真实案例按官方资料、开源许可证、部署形态和叶子匹配逐项验证；商业仅基本记录。资料核对与实际部署测试分别标记。首批进展见 [案例采集](CASE_COLLECTION_REPORT.md)。

本次未因“搜索失败”或“未找到开源”归档任何叶子。案例不足的冷归档仍要求多轮有效搜索和复核，并保留恢复依据。
