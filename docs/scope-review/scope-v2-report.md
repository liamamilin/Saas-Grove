# SaaS 目录边界修订

本报告记录当前已发布的规则范围；后续全量逐叶模型初判已完成，见 [模型初判结果](../LEAF_REVIEW_REPORT.md)。模型建议尚未自动发布。

日期：2026-10-23。策略：`saas-scope-v2`。修订源于用户指出“有些类型没有 SaaS 形态，例如通讯社交”，对整个目录的收录依据重新收紧。

## 判断方法和完成程度

已按 241 个子分类审阅用途和交付边界，结合类型名称及跨界定义，记录 276 个叶子例外。其余叶子沿用分类判断，**尚未完成对 1,805 个叶子的逐项精审**。所有源叶子都得到可追溯的范围与理由；分类和例外判断在 `scope-policy.json`，完整清单在 [scope-review.csv](../../data/taxonomy/scope-review.csv)。

**这是目录用途与服务形态审阅，并非逐项找到真实 SaaS 产品或部署认证。** 纳入一个类型，表示适合按规定边界寻找软件；待确认表示类型混合了在线应用、本地工具、设备或实际消费服务，需要产品证据再决定。排除表示本轮产品范围不收录，并非断言该领域永远不可能服务化。

- 主目录：供客户持续管理自身资料、协作及业务工作流的在线软件。开源项目允许自托管为应用服务，不要求已有商业化或多租户。
- 排除：消费社交和内容场所、交易撮合或实际服务、纯客户端和 CLI、SDK/引擎/基础设施、设备与现场实时控制。
- 没有再按业务大域、`platform`、`cloud` 等名称直接纳入；未来新增源叶子先进入待确认，即使位于已有业务分类。

## 通讯与社交如何处理

大域改为“团队通讯与社区运营”。主目录保留 18 个类型、待确认 4 个、排除 22 个。

| 处理 | 示例 | 判断理由 |
|---|---|---|
| 保留 | 团队消息、客户消息、共享收件箱、网页邮箱、会议、论坛与私有社区 | 面向组织或社区提供可管理的成员、消息、内容与协作工作流 |
| 待确认 | 聊天室、群消息、通用邮件客户端、通用视频通话 | 类型可能指消费聊天或本地客户端，需按实际项目判断 |
| 排除 | 消费社交网络、交友撮合、直播社交、软电话和对讲客户端 | 主要是参与者使用的网络场所或客户端，不直接作为本轮 SaaS 类型 |

团队通讯和社区软件确实存在 SaaS 与自托管形态。例如 [Zulip 官方自托管说明](https://docs.zulip.com/self-hosting/)说明自托管与其云服务使用同一套软件；[Discourse 官方介绍](https://www.discourse.org/about)提供官方托管和自行部署两种方式。这些资料用于确认边界，不代表本轮已将应用录入正式库。

- 默认 API 与页面均只返回主目录；`scope=conditional`、`scope=all` 为显式候选查看。

- 分类中文显示名称覆盖不修改源快照，原始 slug 与父级关系保持稳定。
- 导入重建同步导出 1,805 行判断清单；确定性重建通过。
- 后端 9 项回归、浏览器 8 条流程及 TypeScript/Vite 构建通过。覆盖默认范围、消费社交排除、待确认导航、未来导入保护、原有列表与移动端流程。未新增正式应用记录。
