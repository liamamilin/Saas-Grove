## 执行顺序与完成口径

1. 完成第5轮97个输入的实际检索、官方来源读取和逐项判断。不能仅因生成了97行记录就称完成；尚未读取的已发现候选属于待续工作。
2. 将证据充分、独立复核通过的条目导入，再用新run_id发布指定conditional类型；其余保留研究、候选和具体缺口，不删除或改为excluded。
3. 按`parent_id`、`slug`顺序补主目录空类型。一个产品可关联多个类型，但每条关系都需有针对该类型定义性核心的依据。已有合格案例的类型可跳过本轮存在性搜索。
4. 每批结束保存查询、实际结果、快照及摘要、类型判断、导入回执和实际覆盖统计，随后继续下一批。所有原有应用、关联、源快照和历史发布证据保留。

首轮每叶最多三组有区别的查询，优先完整开源应用；找到合格案例即可停止存在性搜索。商业只保存名称、官网、简介、类型关联和来源，不扩展价格、架构或对比研究。个人、家庭或行业客户均可有持续软件工作区；不要求企业客户、多租户或单独销售。模块具备完整核心工作流也可匹配，裸组件和仅在路线图中的能力不算完成应用。

对已经找到的官方候选，应至少尝试读取来源并作核心匹配审查；抓取受阻记录URL及失败事实，必要时试另一个公开官方来源。没有核完与核验后证据不足需区分。不会把一次无结果、网络错误、无开源或供应商兼有实体履约直接当作整类不存在或归档理由。
