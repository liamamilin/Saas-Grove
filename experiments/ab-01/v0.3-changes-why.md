# 模板 v0.3 的改动和原因

v0.2 已用 git tag `blueprint-v0.2.0-draft` 保存（提交 `9253edb`）；B3-ab01 的 67/67 按它计算，不变。

起因：B3-ab01（v0.2 测试，B + 测试第 3 次）的审查和我的核实里，剩下的问题都是"契约没写"或"假模型测不到"的：bcrypt cost 10、非测试模式默认假模型、真实请求没有 `max_tokens` 且预留按固定 900 token 估算。见 `template-learnings.md` 24–26。

## 新增 / 改动的测试（67 → 70）

| 测试 | 为什么 |
|---|---|
| `s1/security.test.ts` 密码哈希（改动，不新增） | bcrypt 要求 cost ≥ 12（`decisions.md` T5 一直这么写，构建者看不到）；注册和重置密码两条路径都查；库里出现 cost < 12 的 bcrypt 就失败，所以"一部分 12、一部分 10"也过不了 |
| `s2/real-mode.test.ts` 启动 | 配置完整时能启动、非测试模式下 `/api/__test__/*` 是 404；去掉 `MODEL_PROVIDER` / `MODEL_BASE_URL` / `MODEL_API_KEY` / 任一单价，必须拒绝启动。先有"完整配置能启动"这条守卫，否则一个在非测试模式下根本起不来的产品会白白通过全部拒绝检查 |
| `s2/real-mode.test.ts` 按 usage 记账 | 假服务每次回复的 token 数都不同；检查请求头、`model`、`max_tokens`，用量记录的金额等于每份回复按单价算出的钱；回了 200 就要收费，不管产品解析得了解析不了 |
| `s3/real-budget.test.ts` 预留 | 预算只够一次小调用，假服务每次都用满 `max_tokens`；发给模型的每个请求都必须付得起它的输出上限（`max_tokens × 输出单价 ≤ 余额`），且总花费不超过预算。没有 `max_tokens`（B3）、预留按固定估算（B3）、预留不够的产品都过不了 |

## runner 和测试库

- `run.mjs` 新增控制接口 `POST /instances`、`DELETE /instances/<id>`：再起一个产品实例，各有自己的端口、全新的库、日志，环境由测试指定。不继承 runner 的 `TEST_MODE` / `MODEL_*` / `EMBEDDING_*` / `FAKE_*` / `MAIL_*`，`null` 表示去掉这个变量；与主实例同样在 `--app-sandbox` 里运行；结束时一定停掉并删库。`App.start()` 拆成 `probe()`（不抛错，返回健康/退出/超时）和 `start()`。
- 新增 `lib/instance.ts`（启动实例）、`lib/mock-model.ts`（进程内的假 OpenAI 兼容服务，一次性和流式都支持，回复总带 `usage`）。

## 契约（spec）的改动

- §5.1 增加三条必须做到的规则（缺配置拒绝启动；每次调用带 `max_tokens` 且按最坏情况预留；按返回的 `usage` 记账，回 200 就收费）。
- 新增 §5.2：验收怎样检查真实模式。
- §7：启动脚本不得替产品补默认值（B、B2b、B3 的启动脚本都写了 `MODEL_PROVIDER` 默认 fake）。
- §9：bcrypt cost ≥ 12，两条路径。
- 这些都在只给可测性契约的那一组能看到的 §5 之后。

## 刻意没做的

- 追问路径、重试、流式中途出错、并发任务一起占用预算时的真实模式记账：假服务需要更多协议细节，且追问要求任务成功（依赖产品如何解析假服务的回复，不公平）。留给审查员检查表，已在检查表里写明"还没测"的部分。
- 其他启动入口（`npm start`、容器入口）：验收只测 `scripts/acceptance-start.sh`，其余仍靠人工审查。
- 网页链接导入：仍然推迟，见 `spec/decisions.md`。
