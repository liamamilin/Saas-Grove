# B5：换构建者模型（opencode-go），v0.3 的 B + 测试——预测，跑之前写下

起因：用户要求把 opencode 的 provider 切到 `opencode-go`，试 `longcat-2.5-preview-free`、`beam-free`、`deepseek-v4.1-flash` 三个模型。目的是看"契约 + 可执行验收"的效果是否只在 DeepSeek 一个模型上成立。

## 设定

- 输入和 B4 完全一样：`user-brief.md` + v0.3 可测性契约（§5.1、§5.2、§9…）+ 70 条可运行验收。模板、验收、契约不变（tag `blueprint-v0.3.0-draft` 之后没有改过 `blueprints/`）。
- 只改构建者模型（`baseline.mjs new --builder-model`，harness 提交 `harness: baseline --builder-model`）。**审查员不变**：`open-design/deepseek-v4-pro`，这样审查结果可比。
- 三个运行：`B5-longcat`（`opencode-go/longcat-2.5-preview-free`）、`B5-beam`（`opencode-go/beam-free`）、`B5-dsgo`（`opencode-go/deepseek-v4.1-flash`，和 B4 同一个模型，换了 provider，作为对照）。
- **三个并行跑**（端口随机、库名唯一，不会冲突）。代价：用时会受 CPU 和 provider 并发影响，**不能和 B4 的用时直接比**；通过数和缺陷不受影响。
- 冒烟测试（各一次最小的沙箱内 builder 回合：写文件、跑 shell、回复 DONE）三个模型都正常，token 用量可读。冒烟目录已删除。
- 注意 `opencode-go/deepseek-v4.1-flash` 不是免费的（冒烟那一回合记了约 0.0009 美元），完整一次的花费我会在结果里报出。
- 我对 `beam-free` 一无所知，只知道名字；对 LongCat 2.5 Preview 也只有先验。以下都是先验，不是依据。

## 事后我会怎么核实

- 看每个运行的 `records/STATUS.md`、`journal.jsonl`（通过数、用时、token、`agent.turn` 的 `errors`）。
- 若有失败：把最终的 `app/` 复制到沙箱外，在安静的机器上用同一份 `run.mjs` 单独复测一遍，排除并行造成的偶发失败。
- 对着代码读：哈希参数、配置校验、所有调用模型的地方（任务、追问、重试）的 `max_tokens` 和预留。
- 审查员的结论逐条核实，并单独找它漏报的。

## 这个实验能回答什么、回答不了什么

能回答：同一份契约 + 验收，换构建者模型，通过数和缺陷类型会不会变。
回答不了：模板（spec + 阶段）是否比"只给测试"更好（A 组仍然只有 DeepSeek 一次）；第二个项目是否省时（North Star）；验收之外的泛化（没有留出的、构建者看不到的测试）。
