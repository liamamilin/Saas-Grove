# 这次运行暴露的模板缺口（留到 v0.2 处理）

实验进行中**不改**模板和验收，否则 A 组后面的阶段和 B 组的评分会失去可比性。这些问题都在实验结束后统一处理，处理完同样要经过独立 agent 审查。

## 验收没覆盖到的

1. **在 synthesize 阶段取消**（来自 S2 审查第 1 条）：现有的取消测试是在 plan 刚完成后取消的，没有覆盖"最后一次调用进行中被取消"这种情况。可以补一条：把假模型的延迟调大，等 synthesize 阶段开始运行后取消，然后断言最终状态仍是 `canceled`、`reportId` 为空，并且之后不再新增用量记录。
2. **进度要随步骤推进**（来自 S2 审查第 9 条）：现在只断言了进度"不倒退"。可以补一条：analyze 阶段内至少能观察到 2 个不同的进度值。
3. **引用标记的格式**（来自 S2 审查第 12 条）：spec 只说了 `[n]`，没有说多编号写法（`[1,2]`、`[1-3]`）怎么处理。要么在 spec 里规定"必须写成单个编号"，要么规定多编号要展开成多条引用。

## spec 写得不够明确的

4. 启动脚本是否要在启动时构建（已在 harness 层解决：runner 在验收前统一构建）。实验结束后，把这条约定也正式写进 v0.2 的启动约定。
5. "所有查询都要带 workspace_id"这条黑盒测试测不到，只能靠审查发现。可以考虑在 `reference/` 里提供一个带工作区作用域的查询辅助函数作为参考实现。

## 真实模式的安全默认值（来自 S3 审查）

6. spec 只规定了 `MODEL_PROVIDER=real|fake`，没规定默认值，也没规定"真实模式缺配置就拒绝启动"这道检查必须覆盖**所有启动方式**。这次的产品选择了默认用假模型，配置检查也只放在验收启动脚本里，于是正式部署会在不知不觉中退回假模型。v0.2 应该写明：非测试模式下缺少模型配置必须报错（失败时关闭），并在验收里加一条测试：不设 `TEST_MODE` 又不配模型时，产品要拒绝启动（或拒绝发起研究任务）。
7. 预算不变式在真实模式下要靠"预留上限 = 调用时传给模型的输出上限"来保证。spec §4.3 只说了"预留预估费用"，应该明确：预留必须基于输出 token 的硬上限，而不是一个估计值。
