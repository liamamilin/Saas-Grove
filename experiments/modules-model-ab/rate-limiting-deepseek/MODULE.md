# rate-limiting — 认知模板（限流与滥用控制）

> **一页必读**
> - 它是**准入闸门**：在请求进入昂贵或敏感逻辑之前，用确定的配额回答"现在放不放行"，并把剩余额度告诉客户端。不是 WAF、不是封禁、不是账单配额。
> - 模型只有四个变量：**策略（policy）× 键（key）× 窗口（W）× 代价（cost）**。成熟度全部体现在这四者的正确性与可运维性上。
> - 三条不可协商：①同一 key 在任意 ≤W 秒内放行的 cost 总和 ≤ Limit，且原子；②拒绝不消耗额度、不延长窗口；③键只来自服务端解析的身份与 IP，IP 取 `X-Forwarded-For` **最右**非受信跳。
> - 最常死的地方：取最左 XFF（换头即绕过）；把 429 也计数（正常用户被永久锁死）；进程内计数（实际额度 = 实例数 × Limit）；先做业务再限流（昂贵工作已发生）；对 `/api/health` 限流（健康检查 429 → 实例被摘 → 全站故障）。
> - 验收只看：200/429、三个 `RateLimit-*` 头、`Retry-After`、错误体、时钟前进后的恢复、`params` 里的数值。规则见 `contract.md`，用例见 `acceptance-plan.md`。

## 这个模块是什么

限流模块是横切层：所有"写、贵、可被爆破"的入口在执行业务前向它要一个判定。它做四件事——识别调用者（IP/账号/标识符）、按策略类计费式计数、返回放行或 429 加恢复提示、对滥用模式做**结构性**抑制（多维度、更严的 auth 桶、按 IP 的安全上限）。

它必须能回答三个问题，且答案在黑盒下可验证：**谁**（键）、**多少**（配额与 cost）、**多久恢复**（`Retry-After`）。答不出任一个，实现就只是装饰。

它与相邻概念的分界：预算是"用多少"（月/额度），限流是"多快"；封禁是"还能不能用"，限流是"现在能不能"。

## 成熟版应该有什么（MVP → 成熟分层）

### L0 最小可用（单策略，能上线）
1. 一个 `anon` 策略：按 IP 计数，数值取契约 §0.2 的缺省值（约 30 次 / 分钟）。
2. 超限返回 429，带 `Retry-After` 与 `RateLimit-Limit/Remaining/Reset`，全部整数秒，禁 HTTP-date。
3. 计数放**集中式**存储，单键原子自增；不得用进程内 Map。
4. 429 带 `Cache-Control: no-store`。
5. 数值来自配置/`params`，不硬编码；改值不改代码。
6. 验收钩子：清空计数、时钟前进（`HOST.md` §3），且仅 `TEST_MODE` 存在。

### L1 身份分维（不再一个桶打天下）
7. 策略类至少：`anon`、`account_read`、`account_write`、`costly`、`auth`、`signup`。
8. 已认证请求双维：**account id** + **ip_safety**（粗粒度 IP 上限），两者都过才放行。
9. `cost` 权重：昂贵操作按配置权重计（缺省 5 个单位），配额按 cost 而非请求数。
10. 键归一：identifier trim + 小写；IP 归一（IPv4-mapped IPv6、零压缩）。
11. 429 指出是哪一层拒绝（`policy` 字段）。
12. 匿名请求不消耗任何账号额度（`auth`/`signup` 另加 identifier 桶）。

### L2 正确性（黑盒能证伪的部分）
13. 滑动窗口语义：任意 ≤W 秒区间放行 cost ≤ Limit；拒绝不写入。
14. 判定与计数在**同一次原子操作**里完成（读余量、判够不够、扣减不可分割）。
15. 判定顺序：解析 IP → 选策略 → 限流 → 认证/授权 → 业务；`/api/health` 与清空接口豁免。
16. 客户端 IP 取 XFF 最右非受信跳，受信跳数可配；**永不取最左**。
17. 计数 TTL ≥ W+60s；键以带密钥摘要存储，不落明文邮箱/IP。
18. 枚举安全：429 在"不存在/未验证/已验证/禁用"四态下不可区分（`Retry-After` 误差 ≤1s）。
19. 会话轮换不重置额度（键是 account id，不是 token）。

### L3 运维与滥用控制
20. 策略可独立开关与调值（含按套餐），改值灰度不重启；关闭一个不影响其他。
21. 观测：按 policy 的放行/拒绝率、Top 摘要键、存储错误率、降级标志；日志不含明文标识。
22. 存储故障分级：`auth`/`account_write` fail-closed，`account_read`/`anon` 可 fail-open 并标注 `degraded`；此处的 503 表示依赖故障，不是限流拒绝（契约列为建议，不测）。
23. 显式、最小化的旁路名单（健康检查、内部任务），带审计；不得靠"内部 IP 段"隐式放行。
24. 容量预算：单实例 QPS、计数存储 p99、键基数上限；有压测基线。
25. 出站重试风暴也要有上限：复用同一套计数原语，由出站模块实施（见接口）。

### L4 客户端与生态契约
26. 客户端遵守 `Retry-After` 并加抖动；429 后不对非幂等写自动重试。
27. 错误码与文档统一（唯一 `rate_limited`），前端据 `Reset` 显示倒计时。
28. 每次改数值/策略都回归本模块验收；变更记录可追。

## 每项的正确行为

**键。** 已认证时键 = `(policy, account_id)`；匿名时 = `(policy, 归一化 IP)`；`auth`/`signup` 额外加 `(policy, 归一化 identifier)`，两者都计数。`account_id` 只能来自校验过的会话，忽略请求头里的 `X-Account-Id`、`X-User-Id`、body 字段。IP 解析：取 XFF 从右往左**第一个非受信地址**（右端是受信代理则继续向左）；非法值归入固定桶，不放行。

**配额。** `Limit` 是每 W 秒的 cost 配额。一次放行扣 `cost`，`Remaining` 永不小于 0；`cost` 大于剩余时拒绝，即使剩余非 0。`Reset` = 再过多少秒该键至少能再放行一个 cost 单位，因此 `Retry-After` 与它同值、且 ≤ W。

**拒绝。** 一律 429 + 唯一错误码，响应体含 `policy`、`limit`、`remaining`、`retryAfterSeconds`、`resetSeconds`、`requestId`，不含任何标识符、IP、其他账号数据或堆栈。拒绝是**只读操作**：不扣减、不推迟恢复时刻；连续被拒 20 次后，等待首个 `Retry-After` 仍必须恢复。

**窗口。** 语义是"任意 ≤W 区间内的放行量"，实现可选滑动日志、GCRA 或带权滑动计数；固定窗口在边界可放行 2×Limit，不合规。并发下计数必须原子：常见正解是把"判断 + 扣减 + 写 TTL"放进一次服务端原子操作。

**顺序。** 限流先于认证：匿名 IP 桶耗尽后，本应 401 的请求也返回 429（否则攻击者可无成本地打认证端点）。健康检查、清空计数接口豁免。

**存储。** 键为带密钥摘要（HMAC 之类），记录 TTL ≥ W+60s 且 ≤ W+300s；摘要不可逆、不参与业务查询。密钥轮换时，因计数在窗口后自然过期，无需回填（**不要**为已散列的长效令牌"重算摘要"）。

**运维。** 所有数值可声明、可观测、可按套餐覆盖；`ip_safety` 上限必须 ≥3×`account_write`（契约要求），否则正常办公网/NAT 用户互相拖累。

## 容易做错的地方（会出什么事故）

1. **取 XFF 最左**：攻击者每请求换一个伪 IP，限流等于不存在，且日志里的"客户端 IP"全是伪造值。取最右非受信跳。
2. **拒绝也计数**：脚本重试风暴把窗口不断推后，被误伤的正常用户永远 429（不会自愈）；同时真实攻击量被掩盖。
3. **进程内计数**：3 个实例 = 3×Limit；滚动发布时额度忽高忽低；重启清零，攻击者只要等一次部署。
4. **先读后写两步**：20 个并发请求都读到 `Remaining=1` 全部放行，瞬时超额 20 倍——爆破类端点直接被打穿。
5. **用 session token 做键**：重新登录即清零；攻击者循环登录，auth 桶形同虚设。
6. **用原始邮箱/IP 做键**：计数库变 PII 库，导出/日志即泄露；且 `A@x.com` 与 `a@x.com` 各占一桶，额度翻倍。
7. **固定窗口**：边界前后各打满，瞬时 2×Limit；对 `auth` 等于把爆破窗口翻倍。
8. **`Retry-After` 写毫秒或 HTTP-date**：客户端立刻重试形成风暴，或算成 1970 年。
9. **限流在业务之后**：昂贵查询、模型调用、邮件已发生，429 只是事后通知。
10. **对 `/api/health` 限流**：负载均衡探活拿到 429，判实例死亡并摘除，全站 5xx——最经典的自伤。
11. **429 文案区分账号状态**：`user not found` vs `rate limited` 成为枚举 oracle，auth 的枚举防护被限流层绕过。
12. **全站共享一个键**：办公网/NAT 一人拖垮整栋楼；或多租户漏了 workspace 维度，一个租户 DoS 其他租户。
13. **TTL 短于窗口或永不过期**：前者提前清零（额度翻倍），后者键无限增长打爆内存。
14. **429 无 `no-store`**：CDN/浏览器缓存 429，用户清缓存前一直失败。
15. **从请求头选桶**：伪造 `X-Account-Id` 即可换桶，双维隔离失效。
16. **只做 IPv4 字符串比较**：`::ffff:1.2.3.4` 与 `1.2.3.4` 分属两桶，额度双倍。
17. **存储故障时对 auth 放行**：存储抖动几分钟，爆破无限制。
18. **把 429 当 403/503**：客户端重试逻辑、监控告警、SLO 全部错位（503 会触发熔断与摘除）。

## 与其他模块的接口

- **auth**：提供会话 → account id、账号状态（未验证/禁用）；本模块只在它前面加闸，401/403 的判定与正文仍由 auth 返回。
- **workspaces-and-permissions**：成员/角色可作额外键维度（团队额度）；403 仍由它返回。
- **usage-metering-and-budgets**：预算是用量上限，与速率正交；被 429 的请求不得计入用量；预算耗尽的错误不由本模块产生。
- **ai-model-gateway**：提供每次调用的 cost 权重（token/费用）；本模块只消费权重。
- **payments-billing**：套餐档位 → 额度参数的来源；升级生效时机由它定义。
- **web-security**：受信代理链与客户端 IP 的权威来源；机器人信号可作为额外键输入（可选）。
- **audit-and-data-export**：429 事件（摘要键、policy、时间）进审计，不含明文标识。
- **observability**：按 policy 的放行/拒绝指标、存储错误与降级告警。
- **feature-flags**：策略开关与灰度；关闭一个策略不得影响其他策略。
- **notifications** / **email-transactional**：低频、去重地通知账号所有者或运营"被限流"。
- **async-jobs**：内部任务走显式旁路凭据，不靠 IP 白名单。

## 不做什么

- 不做封禁、惩罚升级、黑名单、验证码挑战（属 auth / 风控 / 人工流程）；本模块无状态、可确定恢复。
- 不做 WAF、L3/L4 DDoS 清洗、机器人指纹（**web-security**）。
- 不做用量预算、计费、套餐权益（**usage-metering-and-budgets** / **payments-billing**）。
- 不做每 token 的模型成本核算（**ai-model-gateway**）。
- 不做租户数据隔离本身（**workspaces-and-permissions**）。
- 不做请求内容审查与提示注入防护（**prompt-injection-and-guardrails**）。
- 不做前端倒计时组件与文案本地化（前端 / **internationalization**）。
- 不承诺跨区域强一致计数；单区域正确即可，跨区策略见 `decisions.md`。
