# rate-limiting 决策点（人类拍板，其余照契约）

每条给出**推荐默认**。默认是选型建议，凡与契约冲突以契约为准；改了默认必须同步 `module-map.json` 的 `params`，验收从 params 读值，不读本文。

| # | 决策 | 推荐默认 | 选另一个的后果 |
|---|---|---|---|
| D1 | 计数存哪里 | 集中式、单键原子操作（KV 或 SQL 单行） | 进程内计数：多实例实际额度 = 实例数 × Limit；重启清零；滚动发布期间额度抖动，攻击者等一次部署即可 |
| D2 | 窗口算法 | 滑动日志 / GCRA（任意 ≤W 区间 ≤Limit） | 固定窗口：边界前后各打满，瞬时 2×Limit；`auth` 类等于把爆破窗口翻倍 |
| D3 | 已认证请求的维度 | account id + `ip_safety` 粗粒度上限（≥3× `account_write.limit`） | 只按 account：一个 IP 批量开号即可分摊刷爆；只按 IP：办公网/NAT 一人连坐全楼 |
| D4 | 限流与认证的先后 | 限流先于认证（匿名 IP 桶耗尽后 401 也变 429） | 先认证：无效凭据的爆破零成本、不计数；auth 端点的 401 风暴无从抑制 |
| D5 | 计数存储不可用时 | `auth`/`account_write` fail-closed（503），`account_read`/`anon` fail-open 并标 `degraded` | 全 fail-open：存储抖动几分钟 = 爆破无限额；全 fail-closed：只读接口也全站 503，故障放大 |
| D6 | 429 是否区分账号状态 | 四种状态（不存在/未验证/已验证/禁用）不可区分（`Retry-After` 误差 ≤1s） | 精准提示（"账号不存在"）：限流层变成枚举 oracle，绕过 auth 的枚举防护 |
| D7 | 代理与客户端 IP | 声明 `trustedProxyHops` 与受信 CIDR，取最右**非受信**跳 | 信任全部 XFF 或取最左：攻击者换头即绕过，审计里的 IP 全为伪造 |
| D8 | 额度从哪来 | `params` + 套餐覆盖（payments-billing 给档位），运行时可调 | 代码常量：每次调额都发版，遇到攻击时止损要等发布窗口 |
| D9 | 是否自动惩罚/封禁 | 不升级，只有窗口内 429 | 指数封禁/拉黑：与"拒绝不延长窗口、Retry-After 可恢复"的不变量冲突，误伤无法自愈；封禁属 auth/人工流程 |
| D10 | 多区域部署 | 单区域强一致计数；跨区只做粗粒度总量约束 | 各区域独立计数：有效额度 = 区域数 × Limit，跨区攻击成本按区域数摊薄 |
| D11 | 旁路名单 | 只放健康检查 + 签名内部凭据，变更入审计 | 按"内网 IP 段"放行：一次 SSRF 或内网横向即可无限调用；名单还会随基础设施漂移 |
| D12 | 归一化/摘要密钥轮换 | 计数随窗口自然过期（≤W+300s），轮换即生效 | 轮换时回填"重算摘要"：旧计数全部失配，窗口内额度瞬间翻倍或清零；对长效已散列令牌尤其禁止 |

配套：D3 的 3× 与 D1 的原子性直接决定并发用例（RL-17）能否通过；`TEST_MODE` 下直接取 XFF 最右值，生产跳数必须由部署方声明，不能猜。
