# nt-01 成熟度清单（草案，待独立审查后打 tag 冻结）

来源：`blueprints/ai-support-bot/spec/product.md`（§6 容易做错的地方、§7）、`architecture.md` §4，加冻结简报本身的要求（引用出处、不瞎编、转人工留联系方式、月度预算超了就停、哪些问题没答上来、文档格式乱）。共 39 条，二值，分母固定 39。

## 通用规则（评判者必须遵守）
- 评判者只依据：被评产品自己的 README（学路径、界面入口、怎么注册）、运行中的产品、产品使用的 Postgres（可读行）、假模型服务（`MODEL_BASE_URL` 指向它，回答确定；评判者按自己的评判手册让它"返回指定文本 / 报告指定 usage / 变慢 / 报错 429、500 / 记录收到的请求"）。清单里不写路径、testid、错误码。条目里说"拒绝"指产品给出明确的 4xx 或等价的界面提示；说"查不到"指 404 或等价的"不存在"。
- 判定：PASS 必须附证据（原始请求与响应、数据库行、假模型服务收到的请求记录、截图的文字描述）。无法操作、产品没有这个功能、证据不全 = UNKNOWN = 不通过。FAIL 与 UNKNOWN 都计 0 分，但报告里要分开写，UNKNOWN 要写出卡在哪。
- 标 **[模型]** 的条目需要假模型做特殊行为（指定输出、指定 usage、报错、变慢）。若评判手册里的假模型控制手段做不到，记 UNKNOWN 并说明，不得改用别的办法宣称通过。
- 每条先用产品自带界面或 API 建立前置数据（注册两个用户、两个工作区等）；涉及两个工作区的条目用两个独立的工作区，其中一个用户同时是两个工作区成员的情形见 M10。
- 同一条目允许多个探测，**任一探测失败整条 FAIL**。
- 评判者不得为了让某条通过而修改产品代码或数据库内容（只读数据库，只通过产品入口造数据）。

## 一、账号与会话

### M01 注册与登录，邮箱不区分大小写
- 区域：认证
- 来源：category
- 行为：邮箱 + 密码可注册、登录；`A@x.com` 注册后用 `a@X.COM` 能登录，且不能再注册同一邮箱的另一种大小写写法。
- 探测：① 用 `Alice@Example.com` 注册；② 用 `alice@example.com` 登录；③ 再用 `ALICE@EXAMPLE.COM` 注册；④ 用错误密码登录。
- PASS 证据：②成功并拿到登录态（响应含会话或之后能访问需登录的页面）；③被拒绝（邮箱已占用或等价）且数据库用户表中该邮箱只有一行；④被拒绝。
- FAIL/UNKNOWN：③成功创建第二个账号 = FAIL；注册流程无法走通 = UNKNOWN。

### M02 密码与各类令牌在库里不是明文
- 区域：认证 / 数据
- 来源：category
- 行为：密码用慢哈希（argon2id 或 bcrypt 等）存；会话令牌、邀请令牌、找回密码令牌、访客令牌库里只存哈希，不存明文。
- 探测：① 注册并登录，记下密码、响应里和 Cookie 里的会话令牌；② 发邀请，记下邮件里（产品 README 说明的取信方式，如开发用的邮件出口）的邀请令牌；③ 触发找回密码，记下重置令牌；④ 访客创建对话，记下返回的访客令牌；⑤ 在整个数据库所有表所有文本列中搜索这四个明文值（可 dump 后 grep），并查看密码列的格式。
- PASS 证据：四个令牌明文在数据库中零命中；密码列是带算法前缀/盐的哈希（如 `$argon2id$`、`$2b$`），不是明文、不是未加盐的 md5/sha 单次哈希。
- FAIL/UNKNOWN：任一明文命中或密码为快速哈希 = FAIL。邮件/令牌取不到而无法验证的那一项记 UNKNOWN（整条 UNKNOWN）。

### M03 会话 Cookie 安全属性
- 区域：会话
- 来源：category
- 行为：登录后的会话 Cookie 带 HttpOnly 和 SameSite（Lax 或 Strict）；页面脚本读不到它。
- 探测：登录请求的 `Set-Cookie` 头；在浏览器页面里执行 `document.cookie` 看是否可见。
- PASS 证据：`Set-Cookie` 含 `HttpOnly` 与 `SameSite=Lax|Strict`；`document.cookie` 不含会话值。
- FAIL/UNKNOWN：缺任一属性或会话值可被脚本读到 = FAIL。

### M04 登录失败多次被限流
- 区域：认证
- 来源：category
- 行为：同一账号（或同一来源）连续密码错误后被暂时拒绝，且之后即使密码正确，短时间内也不放行；不会因此泄露账号是否存在。
- 探测：对已注册邮箱连续 15 次错误密码登录，记录每次状态；紧接着用正确密码登录；再对不存在的邮箱做同样 15 次。
- PASS 证据：存在某次起响应变为限流类拒绝（如 429 或明确的"请稍后再试"）；之后正确密码在限流窗口内也被拒绝；不存在邮箱的响应形态与存在邮箱的一致。
- FAIL/UNKNOWN：15 次始终只是"密码错误" = FAIL。

### M05 登录与找回密码不泄露邮箱是否已注册
- 区域：认证
- 来源：category
- 行为：已注册与未注册的邮箱，在登录失败、找回密码两处，得到的响应内容（状态码、正文、关键字段）无法区分。
- 探测：对一个已注册、一个未注册邮箱各发：错误密码登录；找回密码。逐字比较响应（忽略时间戳、请求 ID）。
- PASS 证据：两组响应状态码一致、正文一致。
- FAIL/UNKNOWN：任一处能看出差别（如"用户不存在"、404 对 200）= FAIL。

### M06 登出让会话在服务端失效
- 区域：会话
- 来源：category
- 行为：登出后，旧 Cookie 再也无法访问需登录的内容。
- 探测：登录保存 Cookie → 访问需登录的信息接口成功 → 登出 → 用保存的旧 Cookie 再访问。
- PASS 证据：登出前 200，登出后用旧 Cookie 得到未登录类拒绝。
- FAIL/UNKNOWN：旧 Cookie 仍可用（仅客户端清 Cookie）= FAIL。

### M07 重置密码后其他会话失效，重置链接只能用一次
- 区域：会话
- 来源：category
- 行为：用邮件链接重置密码后，此前登录的所有会话作废；同一个重置链接第二次使用被拒绝。
- 探测：同一账号开两个会话 S1、S2 → 触发找回密码，取邮件链接 → 用链接设新密码 → 用 S1、S2 访问需登录的内容 → 再用同一链接再次设密码 → 用新密码登录。
- PASS 证据：S1、S2 都被拒绝；第二次使用链接被拒绝；新密码可登录、旧密码不可。
- FAIL/UNKNOWN：任一旧会话仍可用或链接可重复使用 = FAIL；取不到邮件 = UNKNOWN。

## 二、租户隔离与角色

### M08 跨工作区读取：返回"不存在"，且与真正不存在的资源无法区分
- 区域：租户隔离
- 来源：category
- 行为：工作区 B 的用户读 A 的任何资源（资料、对话、转人工、成员、设置、用量、分析、审计、导出），得到的响应与读一个根本不存在的 ID 完全一致（同状态码、同正文），不能是"无权限"。
- 探测：用户 U_A 在工作区 A 建好一份资料、一个对话（通过 A 的公开小窗）、一个转人工；U_B 属于工作区 B 且不属于 A。U_B 登录后，用 A 的资源 ID 请求每一类资源的读取（在 B 自己的路径下带 A 的资源 ID，也在 A 的路径下直接读）；再对同类型的随机不存在 ID 做同样请求；比对响应。
- PASS 证据：每一类都是"不存在"类响应，且与随机 ID 的响应在状态码和正文上一致；响应中无 A 的任何数据。
- FAIL/UNKNOWN：出现 403/"无权限"这类表明资源存在的响应、或任一数据泄露 = FAIL。至少覆盖 6 类资源，覆盖不足 = UNKNOWN。

### M09 跨工作区写入与删除无效
- 区域：租户隔离
- 来源：category
- 行为：B 的用户不能修改或删除 A 的资源，也不能把 A 的资源归到 B 下。
- 探测：U_B 对 A 的资料、对话、转人工、成员、预算、小窗设置分别尝试删除/修改/标记已解决；随后以 A 的管理员身份核对这些资源未变化。
- PASS 证据：全部尝试得到"不存在"类拒绝；A 侧核对数据未变。
- FAIL/UNKNOWN：任一次改动生效 = FAIL。

### M10 一个用户同属两个工作区时，小窗回答只用当前工作区的资料
- 区域：租户隔离 / 检索
- 来源：category
- 行为：同一用户同时是工作区 A、B 成员；A 的资料只出现在 A 小窗的回答与出处里，B 的小窗不会用到 A 的资料，反之亦然。
- 探测：A 上传含独特标记词 `ALPHA-7731 的退款期限是 11 天` 的资料，B 上传含 `BETA-2290 的退款期限是 29 天` 的资料；分别配置各自小窗允许同一测试来源；对 A 的小窗问"ALPHA-7731 的退款期限"和"BETA-2290 的退款期限"，对 B 的小窗做对称提问；**[模型]** 让假模型按收到的资料块原样复述并引用（或用能回显提示词中资料的模式），并记录假模型收到的请求。
- PASS 证据：假模型收到的请求中，A 小窗的提示词只含 A 的资料；B 同理；回答的出处只指向本工作区的资料；问对方的标记词得到兜底。
- FAIL/UNKNOWN：任一提示词或出处含对方资料 = FAIL。假模型回显手段不可用时，只能依据出处，证据不足 = UNKNOWN。

### M11 邀请：必须同邮箱登录才能接受，链接只能用一次
- 区域：角色 / 邀请
- 来源：category
- 行为：管理员邀请某邮箱；用别的邮箱账号打开链接不能接受；对的邮箱接受后链接作废。
- 探测：admin 邀请 `bob@x.com` → 取邮件链接 → 用另一账号 carol 登录并尝试接受 → 用 bob 账号接受 → 再次使用同一链接（bob 或 carol）。
- PASS 证据：carol 被拒绝且未成为成员；bob 成功并成为成员；第二次使用被拒绝；数据库成员表只有一条 bob。
- FAIL/UNKNOWN：carol 加入成功或链接可重复使用 = FAIL；取不到邮件 = UNKNOWN。

### M12 普通成员（member）做不了管理员的事，只能删自己上传的资料
- 区域：角色
- 来源：category
- 行为：member 可以看资料/对话/分析/用量、上传资料、处理转人工、删除自己上传的资料；不能邀请成员、移除成员、改小窗设置、换 widget key、设预算、删他人上传的资料、删对话、看审计日志、导出数据。
- 探测：工作区有 owner O、admin A、member M；M 与 A 各上传一份资料。以 M 的登录态逐一尝试上述每个管理操作和删除 A 的资料，再尝试删除自己的资料和标记转人工已解决。
- PASS 证据：每个管理操作被拒绝（拒绝类响应，且数据未变）；删自己的资料成功；处理转人工成功。至少覆盖 8 个管理操作。
- FAIL/UNKNOWN：任一管理操作对 member 生效、或 member 连自己的资料都删不了 = FAIL。

### M13 角色变更与删除工作区只有 owner 能做，且至少保留一个 owner
- 区域：角色
- 来源：template-only
- 行为：admin 不能改角色、不能删工作区；owner 可以；最后一个 owner 不能被降级或移除。
- 探测：admin 尝试给自己升为 owner、改他人角色、删除工作区；owner 尝试把自己（唯一 owner）降为 admin 或移除自己。
- PASS 证据：admin 的尝试均被拒绝；唯一 owner 的降级/移除被拒绝；工作区与成员表未变。
- FAIL/UNKNOWN：任一成功 = FAIL。

## 三、公开小窗的安全

### M14 来源（Origin）允许名单：不在名单、没有来源头都被拒绝；只收 JSON
- 区域：公开接口
- 来源：category
- 行为：公开聊天接口只接受来自允许名单中网站的请求；没有来源头的请求（脚本、curl）也被拒绝；允许时回显具体来源而不是 `*`；预检请求同样按名单应答；表单类（非 JSON）提交被拒绝。
- 探测：名单只含 `https://good.example`。用 widget key 分别发起"新建对话"：① 来源头 `https://good.example`；② `https://evil.example`；③ 不带来源头；④ 来源头 `https://good.example.evil.example` 与 `http://good.example`（协议不同）；⑤ 对 ①② 发 OPTIONS 预检；⑥ 允许来源下用表单编码提交；⑦ 把名单置空再试 ①。
- PASS 证据：① 成功且响应头 `Access-Control-Allow-Origin` 恰为 `https://good.example`（含 `Vary: Origin` 更好但非必须）；②③④ 被拒绝且响应无 `Access-Control-Allow-Origin: *`，也不为恶意来源放行；⑤ 对允许来源放行、对恶意来源不放行；⑥ 被拒绝；⑦ 被拒绝。
- FAIL/UNKNOWN：②③④⑦ 任一成功，或响应头为 `*` = FAIL。

### M15 widget key 泄露后的处置：只凭 key 无法获取任何数据；换 key 后旧 key 立刻失效；关闭小窗后不可用
- 区域：公开接口
- 来源：template-only
- 行为：key 是公开的，仅凭 key 不能读取对话、资料、设置之外的任何东西；管理员换 key 后旧 key 作废；小窗开关关闭后拒绝新对话。
- 探测：① 只拿 key（带允许来源）尝试列出对话、读取资料、读取工作区信息；② admin 换 key；用旧 key 新建对话；用新 key 新建对话；③ admin 关闭小窗，再新建对话；④ 对不存在的 key 新建对话，与已关闭/已作废 key 的响应对比。
- PASS 证据：① 全部拒绝/不存在，且未返回工作区内部数据；② 旧 key 拒绝、新 key 成功；③ 拒绝；④ 无效 key 与作废 key 响应一致（不泄露某 key 曾经存在）。
- FAIL/UNKNOWN：旧 key 仍可用或仅凭 key 可读数据 = FAIL；④ 不一致只记备注，不单独判 FAIL。

### M16 访客提问有频率限制
- 区域：公开接口
- 来源：category
- 行为：同一对话每分钟能问的问题有上限（合理值，≤ 30/分钟），超出被拒绝，并且是明确的"过于频繁"提示而不是服务器错误。
- 探测：新建对话，在 10 秒内连续发 40 个问题（**[模型]** 假模型快速应答）。
- PASS 证据：某次起返回限流类拒绝（如 429），此前的成功数 ≤ 30；拒绝的响应是受控的 4xx，不是 5xx；等待窗口后恢复可问（可选）。
- FAIL/UNKNOWN：40 个全部被处理 = FAIL。

### M17 新建对话有频率限制，且来源 IP 不能靠伪造头绕过
- 区域：公开接口
- 来源：template-only
- 行为：同一 key + 同一客户端 IP 在一小时内新建对话次数有限；默认配置下 `X-Forwarded-For` 之类的头不被信任。
- 探测：从同一地址连续新建 80 个对话；然后每次带不同的伪造 `X-Forwarded-For` 再新建。
- PASS 证据：80 次内出现限流类拒绝；伪造头后仍被限流（头不被信任）。
- FAIL/UNKNOWN：80 次全成功或伪造头即可绕过 = FAIL。

### M18 访客令牌隔离：只能访问自己的那个对话
- 区域：访客隔离
- 来源：category
- 行为：对话相关操作（读历史、提问、评价、转人工）必须带该对话的访客令牌；令牌只对它所属的对话有效；猜对话 ID 没用。
- 探测：访客甲、乙各建一个对话得到令牌 Ta、Tb 与对话 ID。① 不带令牌读/提问/评价/转人工甲的对话；② 用 Tb 访问甲的对话；③ 用甲的令牌访问另一个工作区的对话（跨工作区）；④ 用甲的令牌正常访问。
- PASS 证据：①②③ 全部得到"不存在"类拒绝（不是"无权限"），且响应不含甲的内容；④ 成功；数据库中甲的对话未因 ①–③ 增加消息。
- FAIL/UNKNOWN：任一越权成功 = FAIL。

### M19 访客输入在管理后台显示时被转义
- 区域：公开接口 / 后台
- 来源：category
- 行为：访客的问题、转人工的姓名/邮箱/备注含脚本代码时，管理员在后台看到的是文字，不会执行。
- 探测：访客提问 `<img src=x onerror="window.__xss=1">`，转人工备注填同样内容；管理员在浏览器里打开对话记录、问题列表、转人工列表；检查 `window.__xss` 与页面 DOM。
- PASS 证据：`window.__xss` 未定义；DOM 中该文本以转义后的文字出现，没有活跃的 `onerror` 元素。
- FAIL/UNKNOWN：脚本执行或以原始 HTML 渲染 = FAIL；后台没有展示这些内容的页面 = UNKNOWN。

### M20 嵌入脚本能从客户网站直接跨域使用，且名单在真实浏览器里生效
- 区域：嵌入
- 来源：idea
- 行为：按产品给的嵌入代码贴到另一个来源的网页上，小窗出现并能问答；不在名单的网页上提问被拒绝（小窗给出提示，不崩溃）；小窗不使用以产品自己域名承载的内嵌框架来绕开名单。
- 探测：用评判者自备的两个不同端口的静态页面（一个来源已加入名单，一个没有），都贴嵌入代码；在浏览器中打开，提问；检查网络请求的来源头与页面 DOM 里小窗是否是内嵌框架；刷新页面看对话是否能接着看。
- PASS 证据：名单内页面能看到回答；名单外页面提问被拒；对话请求的来源头是宿主页面来源而不是产品来源；刷新后同一会话历史还在。
- FAIL/UNKNOWN：名单外页面也能问答（例如因为使用内嵌框架导致来源恒为产品自己）= FAIL；产品没有嵌入代码 = FAIL。

## 四、回答质量

### M21 引用是真的：每个 `[n]` 都能追到资料原文
- 区域：引用
- 来源：idea
- 行为：回答里的每个引用标记对应一条出处，出处含资料标题和摘录，摘录在该资料的提取文本里逐字存在。
- 探测：上传一份含若干独特句子的资料（≥ 3 段）；**[模型]** 假模型按提示词中资料块的编号写出引用（用能做到引用的模式）；提问相关问题；取回答与引用；把每条摘录与资料原文做子串比对；核对回答正文里出现的每个 `[n]` 都有对应出处。
- PASS 证据：回答至少 1 条出处；每个正文标记在出处中有对应；每条摘录是原文子串（逐字）；出处的资料标题与上传的一致。
- FAIL/UNKNOWN：摘录对不上原文、或正文标记无出处 = FAIL；没有任何出处结构 = FAIL。

### M22 没有出处的回答不会给访客：编号对不上的标记被去掉，完全无出处则换成兜底
- 区域：引用 / 不编造
- 来源：category
- 行为：模型输出不带有效引用或引用了不存在的编号时，访客看到的是兜底文案，或不含悬空标记的内容；不会看到"[7]"指向不存在的出处。
- 探测：**[模型]** 让假模型分别返回：(a) 一段不带任何标记的流畅回答；(b) 只含 `[9]`（资料只有 4 块以内）的回答；(c) 同时含有效 `[1]` 和无效 `[9]` 的回答。每次记录访客拿到的最终内容与出处。
- PASS 证据：(a)(b) 访客内容是兜底文案（与设置里的兜底文案一致）且无出处；(c) 保留 `[1]` 与对应出处，不留 `[9]`。
- FAIL/UNKNOWN：(a)(b) 的编造内容到达访客，或 (c) 留下悬空标记 = FAIL。

### M23 资料里没有答案时不编造：给兜底文案，且模型"无法回答"的约定输出不泄露
- 区域：不编造
- 来源：idea
- 行为：问题资料库回答不了时，访客看到的内容恰好等于管理员设置的兜底文案，无出处，不暴露错误信息、内部原因或模型的拒答标记。
- 探测：把兜底文案改为独特字符串 `FALLBACK-QX`；上传一份与问题无关的资料；提问；**[模型]** 让假模型返回它的"无法回答"形式（评判手册说明的方式）；同时捕获流式增量的全部片段。
- PASS 证据：流式增量拼接结果与最终内容都恰好等于 `FALLBACK-QX`；中途任何片段不含拒答标记或模型原始拒答文字；无出处。
- FAIL/UNKNOWN：任一增量片段出现拒答标记、或内容不是设置的兜底文案 = FAIL。

### M24 知识库为空时不调用模型
- 区域：不编造 / 成本
- 来源：category
- 行为：工作区没有任何已处理好的资料时，提问直接得到兜底文案，并且不向模型服务发请求、不产生费用。
- 探测：新建工作区、不上传资料；访客提问 3 次；统计假模型服务收到的请求数；查用量记录与本月已花费。再上传一份损坏文件（失败状态，见 M28）后重复。
- PASS 证据：假模型请求数 = 0；用量与花费 = 0；访客得到兜底文案；这些问题仍被保存并在"没答上来"里可见。
- FAIL/UNKNOWN：模型收到请求 = FAIL。

### M25 模型出错时访客看到兜底而不是报错；临时错误会自动重试，最多 3 次
- 区域：可靠性
- 来源：category
- 行为：模型返回 429/5xx/超时：产品重试（有退避），仍失败则给访客兜底文案；访客永远看不到错误细节；重试后成功则正常回答；失败调用不产生费用。
- 探测：**[模型]** ① 假模型对一个请求永久报 500 → 提问，统计假模型收到的请求次数与间隔；② 假模型先报 2 次 429 再正常 → 提问；③ 假模型持续超时（响应拖得很久）→ 提问，观察访客等待是否有上限。
- PASS 证据：① 访客内容为兜底文案，收到的请求 ≤ 3 次且间隔递增（第二次前 ≥ 约 200 ms）；该问题在"没答上来"中原因标为模型出错类；用量/花费为 0；② 最终回答成功；③ 在合理时间内（≤ 2 分钟）给出兜底。
- FAIL/UNKNOWN：访客收到错误堆栈或 5xx；无限重试；失败也被计费 = FAIL。

### M26 提示词里只放检索到的少量相关资料，不是整篇文档
- 区域：成本 / 检索
- 来源：category
- 行为：无论知识库多大，每次交给模型的资料量有上限；找不到相关内容的资料不被整体塞入。
- 探测：上传 30 份各约 3000 字的不同主题资料（合计 ≥ 90000 字符）；提问其中一份的内容；**[模型]** 让假模型记录收到的完整请求；统计请求中的资料总字符数，并检查是否含有大量不相关资料全文。
- PASS 证据：单次请求的资料部分总长 ≤ 约 8000 字符（模板为 4 块、约 6000 字符；评判者允许合理的上浮到 10000）；包含与问题相关的那一份的相关片段。
- FAIL/UNKNOWN：资料部分长度接近全部资料总和或随资料量增长 = FAIL。

### M27 中文资料能被中文问题检索到并正确引用
- 区域：检索
- 来源：category
- 行为：中文资料、中文问题在没有空格分词的情况下也能找到相关片段并给出带出处的回答。
- 探测：上传一份 ≥ 5000 字的中文手册（含 20 个以上主题段落，其中一段写明"企业版支持开具增值税专用发票，申请需提供纳税人识别号并在工作日 3 个工作日内处理"，别的段落主题互异）；用不同措辞提问"开发票要提供什么"、"专票多久能开好"、"你们周末发货吗"（资料中没有）；**[模型]** 假模型要求能回显收到的资料并按编号引用，记录它收到的资料块。
- PASS 证据：前两个问题，假模型收到的资料块包含"增值税专用发票"那一段，且回答带指向该段的出处；第三个问题得到兜底（或模型据无关块说"无法回答"后给兜底）。
- FAIL/UNKNOWN：前两个问题的检索结果不含目标段落 = FAIL。同样的检查以一份英文资料各做一遍作为对照，英文不通过则整条按 UNKNOWN 并说明环境问题。

### M28 坏文件：给出失败原因，不静默成功，不影响其他资料
- 区域：资料处理
- 来源：category
- 行为：解析不出文字的文件（损坏的 PDF、只有图片的 PDF、伪装成 .pdf 的随机字节、空文件）显示失败及原因；超过 10 MB 的文件被拒绝；不支持的类型被拒绝；好文件正常处理；失败文件不会成为知识来源。可接受 .txt / .md / .pdf / .docx / .html。
- 探测：依次上传：随机字节改名 `a.pdf`；空文件 `b.txt`；11 MB 的 `c.txt`；`d.exe`；一份合格 `.docx`、`.html`、`.md`、`.pdf` 各一；然后向有 d 之外失败文件的工作区提问其内容（**[模型]** 若需要，用回显资料的模式）。轮询状态至稳定。
- PASS 证据：失败项在后台列表中有明确失败状态与人能读懂的原因；超大与不支持类型被拒绝并有说明；四种合格文件都变为可用，且各自能被问答检索到；失败项的任何文字（如果有）不被引用；处理中状态最终都会变化（不会永远处理中）。
- FAIL/UNKNOWN：失败文件显示成功、或永远卡在处理中、或产品崩溃/变为 5xx = FAIL。

### M29 删除资料后不再用于回答
- 区域：数据 / 检索
- 来源：category
- 行为：删除某份资料后，它的内容立即不再出现在检索结果、提示词和新回答的出处中；已有对话的历史记录可以保留，但新的提问不再引用它。
- 探测：上传含独特事实 `ZULU-4410 保修期 18 个月` 的资料，提问得到带出处的回答；删除该资料；再次提问同一问题；**[模型]** 记录假模型收到的请求。
- PASS 证据：删除后假模型收到的请求不含 `ZULU-4410`（知识库若因此为空则没有请求）；访客得到兜底；数据库中该资料及其文本块不可再被检索（行已删除，或标记删除且检索排除）。
- FAIL/UNKNOWN：删除后仍引用 = FAIL。

## 五、预算与用量

### M30 预算硬停止：用完后访客得到兜底，不调用模型，也不是报错
- 区域：预算
- 来源：idea
- 行为：月度预算用完后，新问题不再调用模型，访客看到兜底文案和转人工入口，而不是错误；被拒绝的问题仍保存，并在没答上来的列表里标出是因预算原因；新工作区有一个默认的非空预算；预算可设为不限。
- 探测：① 新建工作区读取预算设置（默认值）；② 设预算为一个很小的数（如 0.01 美元）；**[模型]** 假模型对每次调用报告一个足以在 2–3 次内用完预算的 usage（评判手册给出换算）；连续提问直到预算用完；统计之后的问题是否产生假模型请求；记录访客看到的内容；③ 检查没答上来列表与原因；④ 把预算设为不限后再提问。
- PASS 证据：① 默认预算为正的有限值；② 用完后的问题：假模型请求数不再增加，访客内容为兜底（与 M23 的兜底文案一致），响应是正常成功类，不是 4xx/5xx；本月已花费 ≤ 预算；③ 这些问题在列表里标有预算类原因；④ 不限后恢复调用。
- FAIL/UNKNOWN：预算用完仍调用模型、已花费超过预算、访客收到错误 = FAIL。

### M31 并发时也不超支
- 区域：预算
- 来源：category
- 行为：预算只够 k 次调用时，同时发来 N≫k 个问题，实际成功调用数不超过预算允许的数，已花费不超过预算。
- 探测：**[模型]** 设预算恰好够 3 次调用的 usage 费用（评判手册给出换算，如每次调用报告固定 usage、预算 = 3.5 次费用）；假模型每次响应拖 2 秒；用 20 个不同对话（避开 M16 的单对话限流）同时各问一个问题；全部结束后统计假模型实际收到的请求数、已花费、各问题结果。
- PASS 证据：假模型收到的请求数 ≤ 预算允许的调用数（允许因"预留"保守而更少）；已花费 ≤ 预算；其余问题得到兜底并标预算原因。重复 3 轮均满足。
- FAIL/UNKNOWN：任一轮已花费 > 预算 = FAIL（"并发时多超一点"也算 FAIL）。

### M32 预算提醒：80% 时一次，用完时一次，每月各至多一封
- 区域：预算
- 来源：template-only
- 行为：当月花费第一次达到预算的 80% 时，给所有 owner 和 admin 发一封提醒；第一次因预算拒绝问题时再发一封"已用完"；同月不重复；改预算也不让同月重发。
- 探测：**[模型]** 同 M30 的受控 usage；在花费刚过 80% 前后各提问；此后继续提问至用完并再提问数次；改大预算后再次逼近 80%；查邮件出口（README 说明的取信方式）。
- PASS 证据：80% 提醒恰 1 封，收件人含 owner 与 admin；用完提醒恰 1 封；之后的拒绝与改预算后均不再新增。
- FAIL/UNKNOWN：缺任一类、重复、或收件人不含管理员 = FAIL；取不到邮件 = UNKNOWN。

### M33 用量按模型自己报告的 usage 记账，且流式也一样
- 区域：用量
- 来源：idea
- 行为：每次模型调用写一条用量记录（模型、token、费用、成败、所属对话/消息）；token 取自模型响应里报告的 usage，不是估算，流式回答也不记成 0；失败调用费用为 0；汇总 = 明细之和。
- 探测：**[模型]** 假模型对流式与非流式（如果产品两种都用）分别报告奇异值 `prompt=1234, completion=567`（评判手册确保该值不可能由字符数估算得出）；提问；查用量明细与后台汇总；再让一次调用失败（M25 方式），查其记录。
- PASS 证据：明细的 token 恰为 1234/567；费用 = 按产品自己公布的单价计算的值（评判者用 README/界面里的价格复算）；汇总 = 各条之和；失败调用无费用；记录关联到对话与消息。
- FAIL/UNKNOWN：token 为 0、等于估算值而非报告值、或汇总与明细不符 = FAIL；产品没有用量明细 = FAIL。

## 六、转人工与运营

### M34 转人工：留联系方式可选，团队收到通知，后台可见完整对话并可标记已解决
- 区域：转人工
- 来源：idea
- 行为：访客任何时候（尤其在拿到兜底后）可转人工，可填姓名/邮箱/备注，也可全不填；创建后工作区成员收到邮件通知；后台列表可见该转人工及完整对话；可标记已解决；联系方式只对本工作区成员可见。
- 探测：① 访客提问得到兜底 → 转人工并留邮箱与备注；② 另一访客不留联系方式直接转人工；③ 查邮件出口；④ 成员登录后台查看转人工列表与对话；⑤ 标记已解决；⑥ 另一工作区用户尝试查看；⑦ 对同一对话重复转人工。
- PASS 证据：①② 都成功；③ 每个成员收到通知（含对话指向，不含对话以外的他人数据）；④ 显示联系方式与完整消息；⑤ 状态变为已解决；⑥ M08 式拒绝；⑦ 行为有定义（拒绝或幂等，不产生崩溃/5xx）。
- FAIL/UNKNOWN：联系方式为必填、不通知团队、或联系方式对其他工作区可见 = FAIL。

### M35 运营分析：本月汇总，问题列表，能单独看没答上来的及原因
- 区域：分析
- 来源：category
- 行为：后台显示本月对话数、问题数、答上/没答上数、转人工数、花费；问题列表可只看没答上来的，并显示原因（没有答案 / 模型出错 / 预算用完）；对话记录里有访客的评价（赞/踩）。
- 探测：造数据：3 个已答（含引用）、2 个因无答案、1 个因模型出错（M25 方式）、1 个因预算（M30 方式）、1 个转人工、2 个评价（赞、踩）；打开后台汇总与问题列表，核对数字；使用"只看没答上来"过滤。
- PASS 证据：汇总数字与造数据一致（答 3、未答 4、转人工 1、问题数 7 等）；过滤结果恰为 4 条且各自原因正确；评价可见；本月边界按月，上月的数据不计入（可用造一条上月数据库记录前先问产品是否允许；不允许则不测此子项）。
- FAIL/UNKNOWN：数字与明细不符、没有原因区分 = FAIL。

### M36 审计日志：谁在什么时候做了敏感操作
- 区域：审计
- 来源：template-only
- 行为：邀请成员、移除成员、改角色、改小窗设置、换 key、改预算、删资料、删对话、导出数据、删工作区等操作都有记录（操作者、时间、对象）；只有 admin 以上可看；不记录密码或令牌。
- 探测：以 admin 依次执行上述 ≥ 7 种操作；查看审计日志；用 member 尝试查看；检查日志条目中是否出现令牌或密码；跨工作区查看（M08 方式）。
- PASS 证据：每个操作恰有一条记录，含操作者、类型、时间；member 被拒绝；条目文本不含任何密钥或令牌；他人工作区的日志读不到。
- FAIL/UNKNOWN：缺少 ≥ 2 种操作的记录，或条目含令牌/密码 = FAIL。

### M37 数据导出只包含本工作区的数据，且不含密钥
- 区域：导出
- 来源：category
- 行为：管理员导出得到本工作区的资料、对话、转人工、用量等；不含其他工作区的数据；不含密码哈希、会话令牌、邀请令牌、访客令牌及其哈希、widget 之外的密钥。
- 探测：A、B 两个工作区各有独特标记数据（资料、访客问题、转人工邮箱）；A 的 admin 导出；对导出文件 grep B 的标记；对导出文件 grep 各类令牌值（M02 中记下的）与 `$argon2`/`$2b$` 等哈希前缀、令牌哈希；member 尝试导出。
- PASS 证据：导出含 A 的全部类别数据；B 的标记零命中；令牌与哈希零命中；member 被拒绝。
- FAIL/UNKNOWN：任一泄露 = FAIL；产品没有导出功能 = FAIL。

### M38 删除的效果：删对话、删工作区之后数据真的不可访问
- 区域：数据
- 来源：category
- 行为：删除对话后，对话、其消息、其中的访客联系方式在后台和访客侧都访问不到，访客令牌也失效；删除工作区后，其资料、对话、小窗入口（旧 key）、成员对它的访问全部失效，且不影响其他工作区。
