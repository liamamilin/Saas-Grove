# 成熟产品定义：AI 研究/文档助手

> 这份文档回答"一个成熟的 AI 研究/文档助手应该是什么样"。能做出 demo 的人很多，难的是把下面每一条都做对。**验收测试是这份文档的可执行版本**；两者冲突时以验收测试为准，并把冲突报告给人。

## 1. 一句话

团队把资料（文本、Markdown、PDF）放进一个工作区，向系统提出研究问题。系统在后台分步骤研读这些资料，生成一份**每个结论都能追溯到原文**的报告。之后可以针对报告继续追问。所有 AI 花费都记账，并且不超预算。

## 2. 用户与角色

一个**用户**可以属于多个**工作区**（workspace）。工作区是数据隔离的边界：工作区之间什么都看不到，连对方资源"是否存在"都不能泄露。

| 角色 | 能做什么 |
|---|---|
| `member` | 查看工作区内全部资料、任务、报告；上传资料；发起和取消**自己的**研究任务；追问；删除**自己上传的**资料 |
| `admin` | 在 member 基础上：邀请成员、移除非 owner 成员、取消任何任务、删除任何资料、设置预算、查看审计日志、导出数据 |
| `owner` | 在 admin 基础上：修改成员角色、删除工作区。每个工作区至少保留一个 owner |

## 3. 核心对象

- **Document（资料）**：上传后要经过解析、切块、向量化，状态从 `processing` 变为 `ready`，失败则为 `failed`。删除后不再参与任何检索。
- **Research Job（研究任务）**：一个问题加若干资料，按三个阶段执行：`plan`（把问题拆成子问题）→ `analyze`（逐个子问题检索资料并分析）→ `synthesize`（汇总成报告）。状态有：`queued`、`running`、`succeeded`、`failed`、`canceled`、`budget_exceeded`。
- **Report（报告）**：Markdown 正文，带编号引用 `[1]`、`[2]`。每条引用都指向一份资料，并附上**原文中逐字存在**的摘录。
- **Message（追问）**：针对报告提问，回答以流式返回，同样带引用，只能引用该报告用到的资料。
- **Usage Record（用量记录）**：每次模型调用记一条，包含阶段、模型、token、费用和成败。
- **Budget（预算）**：每个工作区按自然月设置美元上限；可以设为不限。
- **Audit Event（审计事件）**：记录谁在什么时候做了哪些敏感操作。

## 4. 核心流程

1. **注册与登录**：邮箱 + 密码注册，邮箱不区分大小写。支持登录、登出（服务端让会话失效）、找回密码（邮件链接）。重置密码后，其他会话全部失效。
2. **建工作区与邀请**：创建者成为 owner。邀请通过邮件发出，被邀请人必须用**同一个邮箱**登录后才能接受。邀请链接只能用一次。
3. **上传资料**：支持粘贴文本，或上传 `.txt` / `.md` / `.pdf`，单个文件不超过 10 MB。解析在后台完成。
4. **发起研究**：选资料、写问题、提交，之后可以看到阶段和进度。可以取消。失败后可以重试，**已完成的阶段不重做、不重复计费**。
5. **阅读报告**：引用可以点开看原文摘录，报告可以下载为 Markdown。
6. **追问**：流式回答，带引用，计入预算。
7. **管理**：设置预算、查看用量、查看审计日志、导出工作区数据、删除资料、删除工作区。

## 5. 功能清单（按阶段，从 MVP 到成熟）

| 阶段 | 必须有 |
|---|---|
| **S1 骨架** | 注册/登录/登出/找回密码；会话 Cookie 安全属性；登录失败限流；工作区；邀请；角色与权限；跨工作区隔离；基础界面（注册 → 创建工作区 → 进入工作区） |
| **S2 AI 作业** | 资料上传与解析（文本/Markdown/PDF）；后台研究任务（三阶段、进度、取消、自动重试临时错误、手动重试失败任务、并发上限、服务重启后继续）；每次模型调用写一条用量记录；带引用的报告；界面上可发起研究、看进度、看报告 |
| **S3 成本与产物** | 用量的费用和汇总；预算设置与执行（超预算拒绝新任务、运行中的任务在超预算前停下）；引用摘录必须是原文；报告下载；报告和用量的访问控制 |
| **S4 成熟化** | 流式追问；审计日志；数据导出；删除资料（之后不再被检索）；删除工作区；界面上的追问与用量页面 |

## 6. 容易做错的地方（验收会专门测）

- **跨租户泄露**：A 工作区的资料出现在 B 的检索结果、报告或回答里；或者通过 ID 能读到别人的资源（必须返回 404，而不是 403）。
- **取消不彻底**：点了取消，后台还在继续调用模型、继续扣钱。
- **重试重复执行**：重试时把已完成的阶段又跑一遍，重复计费，甚至生成两份报告。
- **预算形同虚设**：只在发起任务时检查一次，任务执行中把钱花超。
- **引用造假**：引用的"原文摘录"在原文里根本找不到，或者引用了任务之外的资料。
- **重启丢任务**：服务重启后，任务永远停在 `running`。
- **会话残留**：登出或重置密码后，旧 Cookie 还能用。
- **账号枚举**：登录、找回密码的报错能看出邮箱是否已注册。
- **敏感数据外泄**：接口或导出文件里出现密码哈希、会话令牌、邀请令牌。

## 7. 非功能要求

- **安全**：密码用 argon2id 或 bcrypt 哈希；会话令牌随机生成，服务端保存哈希；Cookie 设 `HttpOnly` 和 `SameSite`；登录失败限流；接口不回显敏感字段。
- **可靠**：任务状态持久化在数据库里；临时错误自动重试（最多 3 次，带退避）；服务重启后，未完成的任务能继续推进到终态。
- **可观测**：有健康检查接口；日志结构化，带请求 ID 和任务 ID。
- **数据**：所有业务数据都在一个 Postgres 里；删除即不可再被访问。导出内容只包含本工作区的数据。
- **测试模式**：`TEST_MODE=1` 时，使用假模型和假邮件（见 `architecture.md`）。非测试模式下，测试接口必须不存在。

## 8. 这一版不做的（明确的非目标）

联网搜索（只研究用户提供的资料）；SSO / OAuth 登录；对外收费；公开分享链接；多语言界面；移动端 App；平台级超级管理员后台。这些放在后续版本，或者到人工决策点再决定。
