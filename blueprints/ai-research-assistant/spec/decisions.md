# 决策点

## A. 必须停下来问人的

下面这些问题已经由人在 2026-10-17 答复（见最后一列）。以后再遇到同类问题时，agent **先按默认值继续做**（凡是会影响验收的，默认值都能保证验收照常进行），同时把问题写进产品仓库的 `QUESTIONS.md`，在阶段结束时交给人处理。以下几类**不能替人决定**：花钱、开账号、对外发送、改动本机系统、法律承诺。

| ID | 问题 | 默认值（人回答之前照此执行） | 人的答复（2026-10-17） |
|---|---|---|---|
| H1 | 真实环境用哪个模型提供方？API key 是什么？ | 只实现 `fake` 和一个 OpenAI 兼容的 `real` 提供方，通过环境变量配置；不提交任何 key | 真实模型用 `deepseek-v4.1-flash`，接口地址和 key 由人填在仓库根目录的 `.env` 里（变量见 `architecture.md` §5.1）。agent 不得读取、打印或提交 key |
| H2 | 真实邮件用哪家服务发送？ | 只实现测试模式下的 outbox，以及一个"打印到日志"的开发模式发信器 | 同意默认值 |
| H3 | 部署到哪里？域名是什么？ | 不部署，只保证本地能跑 | 同意默认值 |
| H4 | 是否在本机安装 pgvector（`brew install pgvector`，会改动本机系统）？ | 不安装；向量先存在 `real[]` 列里，在应用层计算相似度，并在 `DECISIONS.md` 里写明规模上限 | 同意默认值；以后有需要时再安装 pgvector |
| H5 | 产品名称和品牌 | 工作名 "Research Assistant" | 同意默认值 |
| H6 | 是否开放公开注册？ | 开放（验收依赖公开注册） | 同意默认值 |
| H7 | 数据保留：删除是软删除还是物理删除？保留多久？ | 软删除（设置 `deleted_at`），对外表现为不可访问；物理清理以后再定 | 同意默认值 |
| H8 | 本机 pnpm 坏了（corepack 缓存丢失），是否修复？ | 不修，改用 npm | 同意默认值 |

## B. 可以按默认值走的技术决定

偏离默认值是允许的，但要在 `DECISIONS.md` 里写一行：改成了什么、为什么。

| ID | 决定 | 默认值 |
|---|---|---|
| T1 | 认证实现 | 把 Better Auth 放在契约接口之后；如果冲突，就自己实现会话 |
| T2 | 后台作业 | 用 pg-boss，worker 和 Web 跑在同一个进程里 |
| T3 | 切块方式 | 每块约 1000 个字符，相邻块重叠 150 个字符，尽量在段落边界切分 |
| T4 | 检索 | 每个子问题取前 4 个块 |
| T5 | 密码哈希算法 | argon2id；如果原生依赖装不上，就用 bcrypt（cost ≥ 12） |
| T6 | 会话有效期 | 30 天，按访问滑动续期 |
| T7 | 登录限流 | 同一邮箱 15 分钟内失败 10 次后，返回 429 |
| T8 | 邀请有效期 | 7 天 |
| T9 | 单个工作区的并发任务数 | 2 |
| T10 | 新工作区的默认预算 | 不限（`null`）。是否给新工作区设一个保护性的默认上限，属于商业化之前要再决定的事 |

## C. 已知但这一版不处理的问题

- **提示注入**：资料里的指令可能会影响模型输出。这一版只做到"系统提示和资料内容分开传给模型"，没有专门的验收。
- **大规模检索**：不使用 pgvector 时，相似度在应用层计算，只适合单个工作区几千个块的规模。
- **看不到的测试**：这一版构建 agent 能看到全部验收测试；以后会加一组它看不到的测试，用来发现"只为通过测试而写"的实现。
