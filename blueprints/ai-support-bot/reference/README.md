# reference/

用来放难点的**参考实现**：经过验证的小段代码，供构建 agent 对照，避免它在最容易出错的地方自己摸索。

这一版是空的。研究助手模板的 `reference/` 本来也是空的；它列的候选（任务取消、子步骤幂等重试）在这个产品里不存在，所以没有任何东西可以搬过来。等第一次实做暴露出 agent 真正会做错的地方，再把对应的参考实现放进来。候选：

- 预算的原子预留与结算（`spec/architecture.md` §4.3）：一条 `UPDATE … WHERE spent + reserved + :cost <= budget` 之类的写法，并发也不超支
- 公开接口的 Origin / CORS 门（§4.4）：预检、回显 Origin、`Vary: Origin`、缺 Origin 拒绝
- 流式回答里的引用过滤与哨兵拦截（§4.2）：边流边去掉对不上的 `[n]`，不把"无法回答"的约定输出流给访客
- 按工作区限定范围的检索查询（§4.1）

每个参考实现都要附带自己的测试，并在这里登记来源。
