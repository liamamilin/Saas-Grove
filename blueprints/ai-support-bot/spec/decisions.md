# 决策点

## A. 必须停下来问人的

H1–H8 沿用 `ai-research-assistant` 模板里人在 2026-10-17 的答复（同一个人、同一台机器、同一类决定）。H9–H12 是这个品类新增的，**还没有人答复**：在人答复之前，agent 按默认值继续做（凡是会影响验收的，默认值都能保证验收照常进行），同时把问题写进产品仓库的 `QUESTIONS.md`，在阶段结束时交给人处理。以下几类**不能替人决定**：花钱、开账号、对外发送、改动本机系统、法律承诺。

| ID | 问题 | 默认值（人回答之前照此执行） | 人的答复 |
|---|---|---|---|
| H1 | 真实环境用哪个模型提供方？API key 是什么？ | 只实现 `fake` 和一个 OpenAI 兼容的 `real` 提供方，通过环境变量配置；不提交任何 key | （2026-10-17）真实模型用 `deepseek-v4.1-flash`，接口地址和 key 由人填在仓库根目录的 `.env` 里（变量见 `architecture.md` §5.1）。agent 不得读取、打印或提交 key |
| H2 | 真实邮件用哪家服务发送？ | 只实现测试模式下的 outbox，以及一个"打印到日志"的开发模式发信器（转人工通知、预算提醒也一样） | （2026-10-17）同意默认值 |
| H3 | 部署到哪里？域名是什么？ | 不部署，只保证本地能跑。注意：小窗要挂到客户网站上，真正试用前必须有一个公网 HTTPS 地址 | （2026-10-17）同意默认值 |
| H4 | 是否在本机安装 pgvector（`brew install pgvector`，会改动本机系统）？ | 不安装；向量先存在 `real[]` 列里，在应用层计算相似度，并在 `DECISIONS.md` 里写明规模上限 | （2026-10-17）同意默认值 |
| H5 | 产品名称和品牌 | 工作名 "Support Bot" | 待答复（H5 原答复针对的是另一个产品名） |
| H6 | 是否开放公开注册？ | 开放（验收依赖公开注册） | （2026-10-17）同意默认值 |
| H7 | 数据保留：删除是软删除还是物理删除？保留多久？ | 软删除（设置 `deleted_at`），对外表现为不可访问；物理清理以后再定 | （2026-10-17）同意默认值。**这个品类新增的问题见 H11** |
| H8 | 本机 pnpm 坏了（corepack 缓存丢失），是否修复？ | 不修，改用 npm | （2026-10-17）同意默认值 |
| H9 | 新工作区的默认月度预算是多少？ | **10 美元**。小窗是公开的，任何人都能替客户花钱，所以默认就要有上限（研究助手模板的默认是"不限"，这里有意不同）。验收测这个默认值 | 待答复 |
| H10 | 访客没有 `Origin` 头的请求（服务器脚本、curl）是否放行？ | **不放行**（403 `origin_not_allowed`）。浏览器里的小窗一定带 `Origin`；放行无 Origin 的请求，等于给刷预算的脚本开门。需要服务端接入的客户以后另做带密钥的 API | 待答复 |
| H11 | 访客的联系方式（个人数据）保留多久？导出里要不要带？ | 跟对话走：对话删除，联系方式一起不可访问；导出里带（导出只有 admin/owner 能做）。具体保留期限和隐私政策文字，属于法律承诺，等人决定 | 待答复 |
| H12 | 用户需求里提到 Notion、帮助中心，是否做"从网址导入"？ | 不做（SSRF 风险，见 `product.md` §8、`review-checklist.md`）。客户先导出成文件再上传 | 待答复 |

## B. 可以按默认值走的技术决定

偏离默认值是允许的，但要在 `DECISIONS.md` 里写一行：改成了什么、为什么。

| ID | 决定 | 默认值 |
|---|---|---|
| T1 | 认证实现 | 把 Better Auth 放在契约接口之后；如果冲突，就自己实现会话 |
| T2 | 后台处理 | 用 pg-boss，worker 和 Web 跑在同一个进程里；只用于资料处理，回答在请求里同步流式完成 |
| T3 | 切块方式 | 每块约 1000 个字符，相邻块重叠 150 个字符，尽量在段落边界切分 |
| T4 | 检索 | 每个问题取相似度最高的 4 块；不设相似度下限 |
| T5 | 密码哈希算法 | argon2id；如果原生依赖装不上，就用 bcrypt（cost ≥ 12） |
| T6 | 会话有效期 | 30 天，按访问滑动续期 |
| T7 | 登录限流 | 同一邮箱 15 分钟内失败 10 次后，返回 429 |
| T8 | 邀请有效期 | 7 天 |
| T9 | 访客限流 | 每个会话每分钟 10 个问题；每个 widget key + 客户端 IP 每小时新建 30 个会话 |
| T10 | 访客令牌 | 32 字节随机数，base64url；库里存 SHA-256 哈希；令牌不过期（对话删除即失效） |
| T11 | 预算提醒阈值 | 80% 和 100%（第一次因预算拒绝问题时） |
| T12 | 回答的输出上限（真实模式） | `max_tokens` = 800；预算不够时可以降低，但不低于 200，再不够就不调用 |

## C. 已知但这一版不处理的问题

- **提示注入**：资料或访客问题里的指令可能影响模型输出（例如"忽略以上要求"）。这一版只做到"系统提示、资料、访客问题分开传给模型"，并且回答必须带有效引用才算答上；没有专门的验收。
- **大规模检索**：不使用 pgvector 时，相似度在应用层计算，只适合单个工作区几千个块的规模。
- **刷预算的人用真实浏览器**：Origin 名单挡不住在允许的网站上用真浏览器反复提问的人；限流和预算硬停止是兜底。更强的手段（验证码、按访客指纹限流）以后再定。
- **回答质量**：模板只保证回答"有出处、不越界、不超支"，不保证回答好不好（提示词打磨、模型选择属于产品团队之后的工作，见仓库 `README.md` 的质量边界）。
- **看不到的测试**：构建 agent 能看到全部验收测试；评测时另有一组它看不到的测试。
