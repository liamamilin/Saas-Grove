# 审查检查表：黑盒测试看不到的东西

> 给两类人用：**审查员**（只读代码，对照这份检查表找问题），以及**构建者**（做完后自己过一遍）。这里每一条，验收测试要么测不到，要么只能测到一半。标"（来自 ab-01）"的是在研究助手模板的实验里真实出现过的问题，同类缺陷在这个品类大概率会再出现。
>
> 先读 `spec/decisions.md`：人已经决定的事（比如非测试模式不发真实邮件、删除是软删除）**不算缺陷**，不要报。

## 租户隔离

- 每一个查询都带 `workspace_id`，**包括只在回答流程内部用的**（读块、写引用、按对话查消息、结算用量……），不只是路由层。只在路由层检查权限、查询本身只按主键查，算问题。（来自 ab-01）
- 公开接口里，`workspace_id` 只能从 URL 里的 widget key 查出来；会话必须同时匹配工作区和访客令牌哈希。从请求体、查询参数或 Cookie 里取工作区，算问题。
- 检索只查当前小窗所属的工作区；同一个用户管理多个工作区时，后台预览也只用当前工作区的资料。

## 公开接口

- Origin 校验在**每个**公开路由上都做（包括 `config`、反馈、转人工），不只在提问接口上；预检和真实请求用同一套规则。没有 `Origin` 头的请求被拒绝（H10）。`Access-Control-Allow-Origin` 不能是 `*`，也不能把任意请求的 Origin 原样回显而不查名单。
- 限流计数存在数据库里（或其他多进程共享的地方），计数和判断是原子的（并发请求不能同时通过"小于上限"的检查）。（同类问题来自 ab-01 的登录限流）
- 客户端 IP 只在 `TRUST_PROXY=1` 时才读 `X-Forwarded-For`。
- 访客输入（问题、姓名、邮箱、备注）在后台页面、邮件里显示时都要转义；`widget.js` 往宿主页面里插回答时不能用 `innerHTML` 拼接模型输出（模型输出也是不可信输入）。
- 小窗不是 iframe；如果构建者改成了 iframe，必须同时用 `Content-Security-Policy: frame-ancestors` 按允许名单限制嵌入方，并在 `DECISIONS.md` 里说明。

## 不编造

- "答上了"的判定在服务端：回答里没有有效引用就按没答上处理，不能只信模型的自我判断。
- 模型约定的"无法回答"信号不会流给访客；`[n]` 指向不存在的块时，标记被去掉，而不是留在正文里。
- 系统提示、资料、访客问题分开传给模型（`messages` 的不同角色或明确分隔），访客问题不能拼进系统提示里。

## 测试模式

- `TEST_MODE=1` 只能打开假模型、outbox 和故障注入，不能放宽任何业务规则：限流、Origin、权限、预算、校验、大小上限，在测试模式下都要和正式模式一致。（来自 ab-01）
- 非测试模式下，不得写 outbox、不得挂载 `/api/__test__/*`。
- 名字含 `outbox` 的表只能是 §6 描述的测试邮箱。验收只按表名豁免，所以把别的东西（比如访客令牌）放进这类表来躲开明文检查，算问题。

## 钱的路径

- 预留检查和写入在一条原子语句或一个加锁事务里完成；"先查余额、再写预留"两步走，在并发提问时会一起冲过上限。
- 每一次预留，在**所有**路径上都有对应的释放或结算：包括预留之后、进入 `try/finally` 之前就抛错的路径、访客断开连接的路径。（来自 ab-01）
- 已经付费的调用，无论之后遇到断开、记账失败还是重启，都要留下一行用量或一个保留的预留。启动时把所有预留一律删掉，等于忘记了正在进行的付费调用。（来自 ab-01）
- 真实模式：预留的上限必须等于发给模型的 `max_tokens` 硬上限；流式调用带 `stream_options.include_usage`；没配单价就拒绝启动，而不是按 0 计费。（验收已用假服务测了回答路径。**还没测**：自动重试时每次尝试的预留、流式中途出错的记账。）
- 预算提醒每月每种最多一封，并发结算时不会发两封。

## 中止

- 访客断开连接时，`AbortSignal` 要传到**真正发出请求的地方**（真实提供方的 `fetch`），不能只让假模型的等待可以中止。（验收永远是假模型，这一条只能靠人工审查。）

## 恢复

- 服务重启后，`processing` 状态的资料会被重新处理到终态；恢复不能把当前进程里正在正常处理的资料重新放回队列。（来自 ab-01）

## 请求体与资源

- 请求体（JSON 和 multipart 上传）在读进内存**之前**就有大小上限，不能先整个读完再检查；公开接口的请求体上限要更小（例如 16 KB）。（来自 ab-01：修复轮只修了 JSON，没修 multipart）
- 文件解析（PDF、Word、HTML）放在后台、有超时；一个畸形文件不能卡死或拖垮进程。`.docx` 是 zip，要防解压炸弹（限制解压后的大小）。
- 任何会请求外部地址的功能（网址导入、webhook 等）：每一跳重定向都要重新校验地址；先解析再连接到校验过的地址；拒绝私有、回环、链路本地和云元数据地址（含 IPv6 和各种数字写法）；限制大小、时间和重定向次数。**需求里提到、但模板范围里没有的这类功能（Notion、帮助中心导入），不要悄悄加上，见 `TEMPLATE.md`。**（来自 ab-01：5 次不带 spec 的运行都做了网页导入并带出 SSRF）

## 配置

- 非测试模式下，`MODEL_PROVIDER` 没设置就拒绝启动，不要默认用假模型；真实模式缺 key 或单价就拒绝启动。检查要覆盖**所有**启动方式（`npm start`、直接 `node`、容器入口），不能只在验收脚本里。（来自 ab-01）
- `DATABASE_URL` 不是 Postgres 时报错退出，不要悄悄换成别的存储。
- 日志、错误信息里没有密钥、令牌、密码、访客令牌。

## 交付物

- `DECISIONS.md`：偏离模板默认做法的地方都写了（改成了什么、为什么）。
- `QUESTIONS.md`：等人回答的问题（H9–H12 等）；**用户需求里有、但模板里没有的内容**（例如 Notion、帮助中心导入）也要列在里面。
- `PROVENANCE.md`：复制过的第三方代码；没有就写"无"。
