# 成熟产品定义：AI 客服知识库助手

> 这份文档回答"一个成熟的 AI 客服知识库助手应该是什么样"。能做出 demo 的人很多，难的是把下面每一条都做对。**验收测试是这份文档的可执行版本**；两者冲突时以验收测试为准，并把冲突报告给人。

## 1. 一句话

小公司把产品文档和常见问题放进一个工作区，在自己网站上挂一个聊天小窗。访客匿名提问，系统**只根据这些资料**回答，并标明每句话出自哪份资料；答不上来就老实说不知道，并引导访客转人工、留下联系方式。公司后台能看到本月用了多少钱、访客都问了什么、哪些问题没答上来，并设一个月度预算——**花到预算就停，绝不超支**。

## 2. 用户与角色

两类使用者：

- **团队成员**：登录后台的人。一个用户可以属于多个**工作区**（workspace，一个工作区就是一家客户公司）。工作区是数据隔离的边界：工作区之间什么都看不到，连对方资源"是否存在"都不能泄露。
- **访客**：客户网站上的匿名访问者，不注册、不登录。他只能通过小窗的公开接口，用创建对话时拿到的**访客令牌**访问**自己的那一个对话**。

| 角色 | 能做什么 |
|---|---|
| 访客 | 打开小窗、提问、看回答和出处、给回答点赞或点踩、转人工（可留姓名、邮箱、备注）、刷新页面后接着看自己的对话 |
| `member`（客服） | 查看工作区内全部资料、对话、转人工、分析和用量；上传资料；删除**自己上传的**资料；处理转人工（标记已解决）；在后台预览里试问 |
| `admin` | 在 member 基础上：邀请成员、移除非 owner 成员、修改小窗设置（允许的网站、文案、开关）、更换 widget key、设置预算、删除任何资料、删除对话、查看审计日志、导出数据 |
| `owner` | 在 admin 基础上：修改成员角色、删除工作区。每个工作区至少保留一个 owner |

## 3. 核心对象

- **Document（资料）**：粘贴的文本，或上传的 `.txt` / `.md` / `.pdf` / `.docx` / `.html`。上传后后台解析、切块、向量化，状态从 `processing` 变为 `ready`；解析不出文字（损坏的文件、只有图片的 PDF）就是 `failed`，并给出原因 `unreadable`，让客户知道该换一份。工作区里所有 `ready` 的资料合起来就是它的**知识库**。删除后立即不再参与回答。
- **Widget（小窗设置）**：每个工作区一个。包含公开的 **widget key**、允许嵌入的网站（`allowedOrigins`）、开关、机器人名字、欢迎语、**兜底文案**（答不上来时访客看到的话）和嵌入代码。
- **Conversation（对话）**：访客打开小窗后的一次对话，状态 `open` 或 `handed_off`。带一个只返回一次的访客令牌（库里只存哈希）。
- **Message（消息）**：访客的问题（`user`）和系统的回答（`assistant`）。回答有结果：`answered`（带引用，每个 `[n]` 都能追到资料原文）或 `unanswered`（内容就是兜底文案，没有引用）；后台还能看到没答上来的原因：`no_answer`、`model_error`、`budget_exceeded`。访客可以给回答打 `up` / `down`。
- **Handoff（转人工）**：访客要求找真人时创建，带可选的联系方式，状态 `open` → `resolved`。创建时给工作区所有成员发邮件。
- **Usage Record（用量记录）**：每次模型调用记一条，包含模型、token、费用、成败、所属对话和消息。
- **Budget（预算）**：每个工作区按自然月（UTC）设置美元上限，新工作区默认 10 美元；可以设为不限。到 80% 时提醒，用完时提醒并停止调用模型。
- **Audit Event（审计事件）**：记录谁在什么时候做了哪些敏感操作。

## 4. 核心流程

1. **注册与登录**：邮箱 + 密码注册，邮箱不区分大小写。支持登录、登出（服务端让会话失效）、找回密码（邮件链接）。重置密码后，其他会话全部失效。
2. **建工作区与邀请**：创建者成为 owner。邀请通过邮件发出，被邀请人必须用**同一个邮箱**登录后才能接受。邀请链接只能用一次。
3. **建知识库**：粘贴文本或上传文件，单个文件不超过 10 MB；解析在后台完成，页面上能看到每份资料的状态和失败原因。
4. **试问**：在后台预览里像访客一样提问，看回答和出处是否靠谱。
5. **挂到网站上**：把自己网站的地址加进允许名单，复制一行嵌入代码贴到网站上。
6. **访客提问**：流式看到回答，回答下方列出出处（资料标题和原文摘录）。答不上来时看到兜底文案和"转人工"按钮。
7. **转人工**：访客留下（或不留）联系方式，团队收到邮件，在后台看到完整对话，处理后标记已解决。
8. **看运营**：本月对话数、问题数、答上/没答上的数量、转人工数、花了多少钱；问题列表（可以只看没答上来的）；每个对话的完整记录和访客评价。
9. **管理**：设置预算、更换泄露的 widget key、查看审计日志、导出数据、删除资料、删除对话（访客要求删除时）、删除工作区。

## 5. 功能清单（按阶段，从 MVP 到成熟）

| 阶段 | 必须有 |
|---|---|
| **S1 骨架** | 注册/登录/登出/找回密码；会话 Cookie 安全属性；登录失败限流；工作区；邀请；角色与权限；跨工作区隔离；基础界面（注册 → 创建工作区 → 进入工作区） |
| **S2 知识库与回答** | 资料上传与解析（文本/Markdown/PDF/Word/HTML，失败给原因）；小窗设置（key、允许的网站、文案）；公开接口（key、Origin 允许名单、CORS、访客令牌、限流、只收 JSON）；带引用的流式回答；答不上来时的兜底（不编造、知识库为空不调用模型）；临时错误自动重试；每次模型调用写一条用量记录；真实模式（缺配置拒绝启动、`max_tokens`、按 `usage` 记账、资料真的进了提示词）；界面上能建知识库并试问 |
| **S3 成本与转人工** | 用量的费用和汇总；预算设置与**硬停止**（原子预留，并发也不超支）；80% 和用完两种提醒；访客评价；转人工（联系方式可选、通知团队、后台处理） |
| **S4 成熟化** | 运营分析（本月汇总、问题列表、没答上来的问题和原因）；对话记录；审计日志；数据导出；删除资料（之后不再被用来回答）；删除对话；删除工作区；更换 widget key；嵌入代码与 `/widget.js`；界面上的小窗、转人工和分析页 |

## 6. 容易做错的地方（验收会专门测）

- **瞎编**：知识库里没有的东西也编一个答案；或者回答带了 `[1]`，但 1 号出处根本不存在、摘录在原文里找不到。没有出处的回答一律不给，换成兜底文案。
- **知识库是空的也去问模型**：既花钱，又一定是编的。
- **跨租户泄露**：A 公司的资料出现在 B 公司小窗的回答里（尤其是同一个用户同时管两个工作区时）；或者通过 ID 能读到别人的资源（必须返回 404，而不是 403）。
- **公开接口裸奔**：只校验 key，不校验 Origin，别人把你的 key 贴到自己网站上，用你的预算；CORS 回 `*`；没有 `Origin` 头的请求（脚本、curl）直接放行；没有限流。
- **用 iframe 做小窗却仍然检查 Origin**：iframe 发出的请求 Origin 永远是产品自己，名单形同虚设。
- **访客能看别人的对话**：会话接口只认会话 ID，不认访客令牌；或者令牌明文存库。
- **预算形同虚设**：只在后台显示花了多少，不拦；先检查后扣费，并发时一起冲过上限；预算用完后报错给访客，而不是给兜底文案和转人工入口。
- **流式记账为 0**：真实模式流式调用不带 `stream_options.include_usage`，拿不到 `usage`，按 0 记账，预算永远用不完。
- **哨兵漏给访客**：模型说"无法回答"的约定输出被原样流给了访客。
- **整篇资料塞进提示词**：资料一多，每个问题都花大钱，而且超出模型上下文。
- **会话残留**：登出或重置密码后，旧 Cookie 还能用。
- **账号枚举**：登录、找回密码的报错能看出邮箱是否已注册。
- **敏感数据外泄**：接口或导出文件里出现密码哈希、会话令牌、邀请令牌、访客令牌。

## 7. 非功能要求

- **安全**：密码用 argon2id 或 bcrypt 哈希；会话令牌和访客令牌随机生成，服务端只存哈希；Cookie 设 `HttpOnly` 和 `SameSite`；登录失败限流；公开接口限流、Origin 名单、只收 JSON；访客输入在后台显示时转义；接口不回显敏感字段。
- **可靠**：资料处理状态持久化在数据库里，服务重启后处理中的资料能处理完；模型临时错误自动重试（最多 3 次，带退避）；模型最终失败时访客看到兜底文案而不是报错。
- **可观测**：有健康检查接口；日志结构化，带请求 ID、工作区 ID、对话 ID；日志里不出现访客令牌和联系方式之外的敏感值。
- **数据**：所有业务数据都在一个 Postgres 里；删除即不可再被访问。导出内容只包含本工作区的数据。访客联系方式属于个人数据，只对本工作区成员可见，随对话删除。
- **测试模式**：`TEST_MODE=1` 时，使用假模型和假邮件（见 `architecture.md`）。非测试模式下，测试接口必须不存在。

## 8. 这一版不做的（明确的非目标）

- **从网址、Notion、帮助中心在线导入资料**：需要抓取外部地址，带来 SSRF 风险（见 `review-checklist.md`），属于单独一个阶段。客户可以先把这些内容导出成 PDF / Word / HTML / Markdown 再上传。用户需求里提到了这类来源，构建者必须把它写进 `QUESTIONS.md`，不要自己实现。
- 真人客服在小窗里实时接管对话（这一版转人工 = 记录 + 邮件通知，团队通过访客留的联系方式回复）；
- 资料的版本管理和"替换内容保留 ID"（先删除再上传）；
- 扫描件 OCR；多语言界面；对外收费；SSO / OAuth 登录；平台级超级管理员后台；移动端 App。
