# 品类认知：AI 客服知识库助手

> 目的：让 agent 知道这类产品已经有什么、用户会拿什么来比较、哪些可以直接用、哪些只能参考。
> **这一份是简版，没有联网核实**：商业产品和开源项目都来自背景知识，许可证以各项目仓库里的 LICENSE 原文为准，复制任何代码前必须自己去读原文并登记（§4）。和 `ai-research-assistant` 共用的依赖库沿用那份模板在 2026-10-17 的核实结果。

## 1. 用户会拿来比较的商业产品（背景知识，未核实）

Intercom Fin、Zendesk AI、Crisp、Tidio、Chatbase、CustomGPT、DocsBot 等。用户从这些产品里形成的预期是：

- **回答要有出处**，不确定就说不知道。这是小公司敢把机器人放到自己网站上的前提（用户原话："不然客户不敢信"，"最担心它瞎编"）。
- **一行代码嵌入**，不改自己网站的技术栈。
- **答不上来能转人工**，并留下联系方式。
- **后台能看到问了什么、哪些没答上**，用来补资料。
- **费用可控**：按量计费的产品最怕月底账单失控，"花到上限就停"是硬需求。
- 资料格式杂：PDF、Word、网页、Notion。

我们这一版的差异化不在"更聪明"，而在**不编造、不越界、不超支、可追溯**这些成熟 SaaS 的基本功。

## 2. 开源项目（背景知识，未核实）

| 项目 | 许可证（大致） | 对我们的用处 |
|---|---|---|
| Chatwoot | MIT（企业版目录另有许可） | 参考客服收件箱、转人工、访客会话、小窗嵌入方式。Ruby 实现，不复用代码；**不要碰企业版目录** |
| Typebot | 功能源码许可（FSL/AGPL 类，限制商用） | 只看小窗嵌入的交互形态，**不复用代码** |
| Mintplex-Labs/anything-llm | MIT（2026-10-17 核实） | 参考工作区 + 文档问答 + 可嵌入聊天小窗的产品形态 |
| langgenius/dify | 修改版 Apache-2.0，多租户服务需要商业许可（2026-10-17 核实） | 只看产品形态，**不复用代码** |
| infiniflow/ragflow | Apache-2.0（2026-10-17 核实） | 参考文档解析和切块策略。体量很大（Python），不引入 |
| open-webui/open-webui | 自定义许可，附加品牌条款（2026-10-17 核实） | 只看产品形态，**不复用代码** |

结论：**没有哪个项目能直接拿来当我们的产品**。只参考产品形态和流程设计，用默认技术栈自己实现。

## 4. 复用规则

- 只以**依赖包**的形式引用上面这些库，不复制它们的源码。标"未核实"的，安装前先读一遍包里的 LICENSE。
- 如果确实需要复制开源代码片段，在产品仓库的 `PROVENANCE.md` 里登记：来源 URL、许可证、commit、复制了哪些文件。**AGPL / SSPL / BSL / FSL / 自定义限制性许可证的代码一律不复制。**
